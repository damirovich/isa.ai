# ISC.AI — правила проекта

## О проекте
Платформа внутреннего контроля с ИИ. Первый профиль — «ИнспекторAI» для Главной инспекции. Работает **on-premise в изолированном контуре (без интернета)** на локальных моделях. Цель архитектуры: переиспользование того же **ядра** для других отделов без его переписывания.

Документация: [docs/README.md](docs/README.md) — индекс. Архитектура: [docs/02_Архитектура.md](docs/02_Архитектура.md). Требования и приёмка: [docs/ТЗ_ISC.AI.md](docs/ТЗ_ISC.AI.md). (Идентификаторы требований — ТС/ТБ/ТО/ТД/GATE и т.д. — определены в ТЗ; ссылаться на них в коде безопасности/грунтовки.)

## Технологический стек
- **.NET 10, C#**
- **Фронт:** Blazor Server + MudBlazor
- **CQRS-lite:** Mediator (martinothamar) — `Mediator.SourceGenerator` **только в хосте** `Web`, `Mediator.Abstractions` в остальных
- **Маппинг:** Riok.Mapperly (source-генератор)
- **Валидация:** FluentValidation (Apache 2.0 — **НЕ** путать с FluentAssertions)
- **Данные:** EF Core + PostgreSQL (Npgsql) + pgvector
- **ИИ:** Microsoft.Extensions.AI (`IChatClient`) → локальный OpenAI-совместимый сервер инференса (`llama-server` / ik_llama.cpp), модель Gemma; **эмбеддинги — отдельной моделью**. Сервер/модель — по конфигу (см. [ADR-0011](docs/06_ADR/ADR-0011-vybor-modeley-i-embedder.md), [справочник API](docs/reference/llm-api-gemma.md))
- **Логи:** Serilog
- **Промпты:** Scriban (файлы-шаблоны). **Экспорт:** DocumentFormat.OpenXml. **OCR:** Tesseract
- **Тесты:** xUnit + NSubstitute + Shouldly (или AwesomeAssertions) + Testcontainers.PostgreSql; Blazor — bUnit

### Лицензии — только MIT/Apache
Перед добавлением зависимости проверять лицензию. **НЕ добавлять** (платные/коммерческие): MediatR, AutoMapper, MassTransit, FluentAssertions.

## Структура решения
```
src/core/     ISC.AI.Abstractions | AI | Ingestion | Documents | Persistence | Web(хост)
src/profiles/inspector/  Inspector | .Domain | .Application | .Data | .UI(RCL)
tests/        UnitTests | IntegrationTests | Evals
```

## Правило зависимостей (НЕ нарушать)
- Всё зависит от `Abstractions`.
- Ядро **НИКОГДА** не ссылается на профиль. Единственное исключение — хост `Web` подключает выбранный профиль.
- `Inspector.Data` — единственное место профиля, ссылающееся на конкретный проект ядра (`Persistence`).
- `Abstractions` держать тонким: только контракты, **без** EF/Npgsql/OpenAI.

## Жёсткие правила (инварианты — переопределяют любые задачи)
1. **Грунтовка.** Ссылки на НПА формируются ТОЛЬКО из фрагментов, извлечённых RAG-ом. Генерация ссылок «по памяти» модели запрещена. После генерации валидатор обязан проверить, что каждая ссылка есть в извлечённых фрагментах; иначе — пометить как непроверенную. Системный промпт грунтовки лежит в ядре (`ISC.AI.AI`), профиль не может его ослабить.
2. **Режим/air-gap.** Никаких обращений к внешним интернет-API. Все сервисы — внутри контура.
3. **Фильтр доступа.** Разграничение применяется на этапе retrieval: пользователю не выдаются фрагменты выше его допуска. Материалы разного грифа не смешивать в общем индексе без разграничения.
4. **Аудит.** Все обращения и генерации пишутся в неизменяемый журнал.
5. **Данные.** Два DbContext (`CoreDbContext` — схема `core`; `InspectorDbContext` — схема `inspector`) над одной БД PostgreSQL; у каждого своя история миграций.

## Конвенции
- **CQRS-lite:** команды/запросы через Mediator; сквозные pipeline-поведения для аудита, авторизации и проверки грунтовки.
- Обработчики (use-cases), валидаторы и промпты — в `*.Application` профиля. **Промпты — файлы-шаблоны, НЕ хардкод в C#.**
- UI-страницы модулей — в `*.UI` (RCL); хост `Web` держит только оболочку и реестр модулей.
- **Blazor Server:** `DbContext` через `IDbContextFactory` на операцию, не как долгоживущий scoped. Длинные вызовы модели — стримить через `IAsyncEnumerable` с `CancellationToken`.
- Версии пакетов — через **Central Package Management** (`Directory.Packages.props`).
- В тестах **НЕ** использовать EF Core InMemory как БД — только Testcontainers с настоящим Postgres+pgvector.
- Имена тестов — **английские (ASCII)** идентификаторы; человекочитаемая формулировка — по-русски через `[Fact(DisplayName = "…")]`. (CA1707 для тестовых проектов отключён.)
- Комментарии к коду обязательны: XML-doc на русском для публичного API; код безопасности/грунтовки — с пояснением инварианта и ссылкой на пункт ТЗ (см. [docs/10_Стандарт_кодирования.md](docs/10_Стандарт_кодирования.md), ТД-001..008).

## Как работать над задачами
1. Сначала **скелет решения** (проекты, ссылки, пакеты, CPM), затем — **по одному модулю**.
2. Перед добавлением зависимости проверять лицензию (только MIT/Apache).
3. Любой генерирующий сценарий обязан проходить **грунтовку** и писать **аудит** — не обходить.
