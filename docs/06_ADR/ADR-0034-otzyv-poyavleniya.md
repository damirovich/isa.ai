## Контекст

Появление («лицо на материале — этот фигурант») создаётся после двух независимых подтверждений (ТБ-073) и дальше
только копилось: исправить ошибку было нельзя. Ошибочное появление при этом создаёт ложные пересечения между делами,
подсказку эксперту «уже подтверждено у …» и может стать источником эталона.

## Решение

1. **Отзыв, а не удаление.** Статус «отозвано» (`AppearanceStatus.Revoked`), время, отозвавший, причина (обязательна,
   10–1000 знаков). Строка остаётся — история видна в карточке фигуранта с пометкой (ТБ-030). Решения стадий
   верификации в модуле «Медиа» не переписываются (ТБ-072).
2. **Правило двух лиц для отзыва.** Эксперт и верификатор этого появления его не отзывают — ошибку признаёт другой
   сотрудник. Проверяется в хранилище, кнопка в карточке неактивна с объяснением.
3. **Право** — строка матрицы доступа «Отзыв ошибочного появления» (`verification.revoke`), по умолчанию Руководитель
   (утверждает результаты, ТФ-ВЕР-02) и Администратор.
4. **Видимость.** Отзыв возможен только для появления, видимого субъекту по той же решётке, что список появлений;
   невидимое — «не найдено» (ТБ-021).
5. **Последствия отзыва.** Отозванное не участвует в пересечениях по лицу, в подсказке эксперту, в счётчике появлений
   и не мешает новому независимому подтверждению того же лица (новое появление по новому кандидату). Эталон,
   взятый с лица отозванного появления, помечается в карточке «проверьте и при необходимости замените».
6. **Аудит.** Команда пишет `investigation:appearance:{id}:revoke`; причина — только в строке появления под решёткой.

## Последствия

- **Плюсы.** Ошибку можно исправить, не теряя истории; ложные пересечения исчезают сразу.
- **Минусы.** Эталон с отозванного лица автоматически не заменяется — решение за сотрудником (подсказка в карточке).
