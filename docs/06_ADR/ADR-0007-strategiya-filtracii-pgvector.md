# ADR-0007. Стратегия фильтрации доступа в pgvector (pre/post-filter)

| | |
|---|---|
| **Документ** | ДОК-06 / ADR-0007 |
| **Система** | ISC.AI («ИнспекторAI») |
| **Версия** | 0.1 (черновик) |
| **Статус** | **Предложено** (решение на Э1) |
| **Связь с ТЗ** | ТБ-022 (основное); ТБ-020, ТБ-021, ТБ-023, GATE-1, ТО-мат-01 |

## Контекст

Несущий режимный контроль системы — фильтрация по допуску **на этапе извлечения** на стороне БД, до возврата результатов модели (ТБ-020). Векторный поиск выполняется в pgvector. При семантическом поиске возникает выбор момента применения фильтра грифа/подразделения относительно ANN-поиска по векторам:
- **pre-filter** — сначала ограничить множество строк по допуску, затем искать ближайшие векторы в этом подмножестве;
- **post-filter** — сначала найти ближайшие векторы по всему индексу, затем отбросить недопустимые.

Выбор нетривиален и влияет одновременно на безопасность и на полноту. Post-filter с приближённым индексом (например, HNSW/IVF) может скрыто терять полноту в пределах допуска: top-k заполняется недопустимыми кандидатами, которые затем отбрасываются, и допустимые результаты «вытесняются» за границу k. Кроме того, любая стратегия может непреднамеренно раскрыть **наличие** документов выше допуска — через метаданные, счётчики/агрегаты, ранжирование, подсказки/автодополнение и, что особенно коварно, через **различие во времени ответа и в тексте ошибки** (timing/oracle).

ТЗ требует, чтобы выбранная стратегия не приводила к скрытой потере полноты в пределах допуска и не допускала утечки наличия документов выше допуска, и чтобы стратегия была **обоснована в ADR** (ТБ-022). Фильтр обязан быть fail-closed (ТБ-021), а материалы разного грифа — не смешиваться в индексе без разграничения (ТБ-023).

## Решение (предлагаемое, требует подтверждения на Э1)

Предлагается реализовать фильтрацию по принципу **pre-filter на стороне БД как базовую стратегию**, при которой множество кандидатов ANN-поиска ограничивается допуском субъекта до ранжирования, что устраняет класс утечек «через вытеснение» и через ранжирование. Окончательная стратегия (pre-filter, либо раздельные индексы/коллекции по грифу, либо их сочетание) **выбирается и фиксируется на рабочем этапе Э1** по результатам теста полноты/утечки на фактической конфигурации и объёме корпуса.

Обязательные свойства любой выбранной стратегии:
- **fail-closed** (ТБ-021): при отсутствии/неопределённости атрибутов допуска или грифа — доступ запрещается.
- Атрибут грифа/подразделения несёт само хранилище эмбеддингов и подчиняется решётке доступа **при любом обращении**, а не только через штатный retriever (ТБ-020); проверяется тестом прямого доступа к таблице эмбеддингов.
- Изоляция грифов в индексе — раздельные индексы/коллекции **либо** гарантированная фильтрация, с обоснованием в модели угроз (ТБ-023).
- **Неразличимость** ответа от случая «документ отсутствует» по контенту, метаданным, счётчикам, ранжированию, **тексту и времени** ответа об ошибке (методика GATE-1): единый код/текст ошибки и выровненная задержка для случаев «нет доступа» и «нет документа».

Контракт `IRetriever` объявляет обязательность фильтра доступа как инвариант безопасности (ТО-прог-04).

Открытые вопросы для Э1: фактический объём корпуса и распределение по грифам (вход для оценки потери recall при pre-filter); тип векторного индекса и его параметры; приемлемый порог recall в пределах допуска (КИ-03); подтверждение методики измерения timing-канала.

## Последствия

Положительные:
- Pre-filter устраняет скрытую потерю полноты «через вытеснение» и утечку через ранжирование.
- Явная фиксация неразличимости ответов закрывает oracle/timing-канал (ключевой для GATE-1).
- Инвариант доступа в контракте `IRetriever` не даёт обойти фильтр в обход штатного пути (ТБ-020).

Отрицательные / обязательства:
- Pre-filter по селективному атрибуту может снижать эффективность ANN-индекса (производительность/качество приближения) — требуется бенчмарк на реальном объёме (вход ТН-002).
- Выравнивание времени ответа и унификация текста ошибки усложняют реализацию и тестирование (GATE-1 проверяет именно это).
- Решение блокирующее для приёмки: невыполнение GATE-1 — основание для отказа независимо от прочих результатов; поэтому окончательный выбор и его проверка обязательны на Э1/Э3.

## Связь с ТЗ

- **ТБ-022** — выбор стратегии (pre/post-filter), запрет скрытой потери recall и утечки наличия (в т.ч. timing/oracle); обоснование в ADR.
- **ТБ-020** — фильтрация на этапе извлечения на стороне БД; атрибут грифа в хранилище эмбеддингов при любом обращении.
- **ТБ-021** — fail-closed при неопределённости атрибутов.
- **ТБ-023** — изоляция грифов в индексе; тест изоляции.
- **GATE-1** — блокирующий тест фильтра доступа и неразличимости ответа (контент, метаданные, счётчики, ранжирование, текст и время ошибки).
- **ТО-мат-01** — фильтр доступа как часть RAG-конвейера.

> Запись имеет статус «Предложено»: окончательная стратегия и её параметры фиксируются на рабочем этапе Э1 по результатам теста полноты/утечки на фактической конфигурации; после чего статус переводится в «Принято».
