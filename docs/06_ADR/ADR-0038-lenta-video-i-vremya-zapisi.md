## Контекст

ТФ-МЕД-11 требует рядом с системным таймкодом покадрового просмотра показывать «встроенное» время записи из
метаданных файла: время начала записи плюс смещение. Покадровый просмотр (ADR-0028) показывал только смещение от
начала файла. Дата съёмки читалась при загрузке лишь из JPEG и MP4/MOV/3GP (и только если заголовок `moov` в начале
файла), а потом её подтверждал оператор (ТФ-МЕД-17).

Кроме того, заказчик попросил под видео ленту, как в видеоредакторе: шкалу времени и полосу миниатюр кадров с
бегунком. Для следствия к ней полезно добавить отметки: где в записи есть найденные лица и подтверждённые фигуранты.

## Решение

1. **Встроенное время записи — по пробе ffprobe.** При индексации видео (та же проба, что даёт частоту кадров,
   ADR-0028) читаются теги: `com.apple.quicktime.creationdate` (телефоны Apple — местное время со смещением), затем
   `creation_time` контейнера (MP4/MOV/3GP — UTC; Matroska/WebM — DateUTC; AVI — IDIT без пояса, считается временем
   пояса сервера), затем `creation_time` видеопотока. Неправдоподобное (раньше 1990 года — пустые эпохи 1904/1970 —
   или позже завтрашнего дня) и дата без времени отбрасываются. Правило — `RecordTimeMetadata` (`Media.Domain`).
   Значение хранится в `media.asset.recorded_at` и обновляется при каждой переиндексации **поверх** прежнего (как
   частота и размер кадра); при сбое пробы не трогается.
2. **Время записи — сведения из файла, а не дата съёмки.** `recorded_at` не подменяет `captured_at`: дату съёмки
   по-прежнему подтверждает человек (ТФ-МЕД-17). На карточке носителя рядом с датой съёмки показывается «В файле: …»;
   если даты съёмки нет — ссылка «применить как дату съёмки» (та же аудируемая команда `SetAssetCapturedAtCommand`);
   если они расходятся больше чем на минуту — пометка «не совпадает с датой съёмки». Подсказка везде одна: часы камеры
   могли быть сбиты, метаданные — изменены; это не доказательство (ТЭ-006).
3. **Часы записи на ленте.** Над лентой — текущий момент «мм:сс.ммм / длительность» и «запись: дд.мм.гггг
   чч:мм:сс.ммм» = встроенное время + положение. Если встроенного времени нет, но есть дата съёмки, время показывается
   приблизительно — «≈ …», без миллисекунд (оператор указывает дату съёмки с точностью до минуты). Время показывается
   в поясе сервера, как и остальные даты на страницах; браузер его не пересчитывает.
4. **Лента кадров — из той же раскадровки.** Отдельного прохода по файлу нет: при индексации часть кадров раскадровки
   уменьшается до плиток высотой 72 px (ширина — по пропорциям кадра) и склеивается в **одну** картинку JPEG
   (`media-filmstrips/{носитель}/{имя}.jpg`). Отбор — прореживанием (`FilmstripCollector`): длительность может быть
   неизвестна, поэтому берётся каждый кадр с шагом, а при переполнении (больше 120) остаётся каждый второй и шаг
   удваивается — кадры ленты всегда идут с равным шагом от начала записи. В носителе хранятся имя картинки, число
   кадров и шаг (`filmstrip_stored_file_name`, `filmstrip_tile_count`, `filmstrip_step_ms`). Сбой ленты индексацию не
   валит: поиск лиц важнее, а прежняя лента (снятая с того же оригинала) остаётся; новая лента пишется той же
   транзакцией, прежний файл снимается после фиксации, а при сбое до фиксации новый файл снимается как сирота.
5. **Лента — производная носителя под его решёткой.** Картинка раздаётся тем же эндпоинтом файлов, что вырезки лиц:
   floor ядра по грифу и подразделению носителя, затем область дел субъекта (ТБ-020/021/071), единый 404; выдача
   аудируется (ТБ-030, с тем же ограничением частоты). При уничтожении носителя (ТБ-064/075) файл ленты удаляется
   вместе с ним и упоминается в акте. При закрытии дела (ADR-0024) лента не снимается: кадры носителя сохраняются.
6. **Отметки на ленте.** Под лентой кадров — по дорожке на каждого **подтверждённого** фигуранта (своим цветом,
   отрезками треков его лиц по ADR-0037, имя — внутри отметки; без трека — точкой на кадре появления). Треки всех
   найденных лиц на ленту **не** выводятся: в первой версии они были отдельной дорожкой, но на видео с людьми их много,
   и они загромождали ленту — заказчик попросил убрать (06.10.2026); треки остаются карточками под видео (ADR-0037).
   Фигуранты берутся новым методом порта профиля `ICaseScope.ListAssetAppearancesAsync`: только не отозванные
   появления, только фигуранты, доступные сотруднику по решётке и роли (недоступный не раскрывается ни именем, ни
   фактом отметки). Предложения системы и кандидаты на верификации на ленте **не** показываются — проекция для
   верификатора остаётся слепой (ADR-0035/0036).
7. **Только навигация.** Щелчок или перетаскивание по ленте — переход к моменту; щелчок по отметке — к её началу.
   Инструментов правки записи (вырезать, удалить, копировать) нет: материал дела не меняется (ТЭ-007). В режиме
   браузерного `<video>` лента следит за проигрывателем сама, без обращений к серверу; в режиме кадров с сервера
   (MKV/AVI/MOV/3GP) перетаскивание только двигает бегунок, а кадр запрашивается один раз — при отпускании.
8. **Видео, проиндексированные раньше,** ленты и встроенного времени не имеют: вместо ленты — подсказка
   «появится после «Переиндексировать»», шкала и отметки работают.

## Последствия

- **Плюсы.** Видно, где в длинной записи нужный человек, и туда можно перейти одним щелчком; время записи по камере
  видно у каждого кадра, без пересчёта в уме; дата съёмки для MKV/AVI и для MP4 с `moov` в конце теперь подсказывается
  из файла.
- **Минусы.** Лента грубая: не больше 120 кадров на всю запись, у часовой записи — кадр примерно раз в минуту; масштаба
  (+/−) пока нет. Картинка ленты — до ~1 МБ на видео. Встроенное время у перекодированных файлов — время перекодирования,
  а не съёмки (поэтому подпись «по метаданным файла» и ручное подтверждение даты съёмки).
- **Не сделано.** Масштаб ленты для длинных записей; отметки фрагментов расшифровки на ленте; снимок кадра по-прежнему
  берёт время съёмки из `captured_at` (подтверждённой даты), а не из встроенного времени.
