## Контекст

У Заказчика накоплено около 10 ТБ материалов, и видео в них бывает по нескольку гигабайт (ДОК-14 §7). Система
принимала носитель не больше 200 МБ: экран читал файл в память целиком, а команда загрузки получала его массивом
байт. Предел защищал память сервера Blazor Server, но такой архив в систему не попадал. Хранилище при этом уже
принимало поток: копировало его во временный файл, считало SHA-256 вторым проходом и только потом писало в
хранилище.

Это первый шаг переноса архива. Пакетный импорт с носителя (ТФ-МЕД-06) и параллельная обработка — следующие шаги.

## Решение

1. **Команда загрузки получает поток, а не массив.** Вместо `byte[]` — `MediaUploadContent`: поток и заявленная
   длина. Поток одноразовый: обработчик его забирает и закрывает. Маленькие файлы (эталон фигуранта) по-прежнему
   передаются массивом — для них есть неявное приведение.
2. **Сигнатура — по заголовку, без второго чтения.** Обработчик читает первые 4 КБ и проверяет по ним семейство
   файла (ТС-010), как и раньше. Затем `UploadContentStream` отдаёт хранилищу сначала этот заголовок, потом остаток
   потока — побайтно тот же файл.
3. **Предел — по виду носителя.** Фото — 200 МБ, как было: индексатор раскодирует изображение в памяти целиком.
   Видео и аудио — до `Media:Upload:MaxFileBytes`, по умолчанию 16 ГБ (сутки записи с камеры), допустимо от
   200 МБ до 64 ГБ. Предел задаёт эксплуатант по свободному месту на защищённом томе (ТБ-062): файл занимает место
   во временном каталоге при приёме и при обработке, и ещё раз — в хранилище.
4. **Заявленной длине не доверяют.** Заявленная длина больше предела — отказ до чтения. Фактический объём
   считается при чтении: превысил предел — приём прерывается, временный файл удаляется, в деле ничего не появляется.
5. **Хеш — по ходу записи.** Хранилище считает SHA-256 одновременно с записью во временный файл буфером 1 МБ.
   Файл в гигабайты не перечитывается ради хеша; в памяти — только буфер.
6. **Экран.** Файл уходит в команду потоком из браузера. Полоса хода показывает «1,2 ГБ из 3,4 ГБ», загрузку можно
   остановить кнопкой; уход со страницы её прерывает. Подсказка называет пределы: фото — 200 МБ, видео и аудио —
   из настройки.

## Последствия

- **Плюсы.** Видео и аудио в гигабайты принимаются без роста памяти сервера. Дедупликация, проверка сигнатуры,
  гриф от дела и очередь обработки — те же.
- **Минусы и ограничения.**
  - Через браузер файл в гигабайты идёт минуты. Если связь оборвётся, файл придётся загрузить заново: докачки нет.
  - Временный каталог должен вмещать принимаемые файлы целиком. Индексатор и расшифровка по-прежнему копируют
    оригинал во временный файл на время обработки (в отличие от вырезки кадра, ADR-0028).
  - Для архива в терабайты браузер не годится — для него нужен пакетный импорт с носителя на сервере (ТФ-МЕД-06).
- **Не сделано.** ~~Пакетный импорт с описью и раскладкой по делам~~ — сделано, ADR-0041; чтение оригинала на месте индексатором и
  расшифровкой (без копии); параллельная обработка нескольких носителей; докачка оборванной загрузки.
