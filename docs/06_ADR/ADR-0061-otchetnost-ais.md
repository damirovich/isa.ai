## Контекст

Утверждённое ТЗ Заказчика ([АИС 6.0–6.6]) требует отчётных форм, которых в системе нет: журнал суточной оперативной
активности (6.3), отчёт по графу связей (6.4), сводный отчёт результативности биометрической идентификации (6.5) и
статистику карточек объектов по подразделениям-инициаторам (ОР-6.0.1). Общие требования: отчёты строятся автоматически
по первичным записям базы, без ручного сведения (ОР-6.0.2), выгружаются в DOCX и защищённые экранные формы, факт
выгрузки фиксируется в журнале (ОР-6.0.3). Решение Заказчика 22.10.2026 — делать по частям; первая часть — форма 6.5.

Форма 6.5 — «аудит работы нейросетевого модуля распознавания лиц»: количество обработанных фото и видео, число
распознанных лиц, совпадений выше заданного порога, подтверждённых оператором связей, процент отбраковки нерелевантных
кадров. Все величины уже лежат в схеме `media`: носители (вид, подразделение, время индексации), лица (признак
пригодности по качеству ТО-мат-07), сессии поиска (подразделение, дата, ручная или автосверка) и кандидаты выдачи
(статус верификации).

## Решение (часть 1 — результативность распознавания)

### Показатели и правило отнесения

Период — даты «с» и «по» включительно (по местному времени сервера). Строка — подразделение записи.

| Показатель | Что считается |
|---|---|
| Обработано фото / видео | Носители вида «фото» / «видео», проиндексированные (статус «проиндексирован») в периоде — по времени индексации |
| Найдено лиц | Лица этих носителей |
| Отбраковано по качеству | Из них непригодные для сравнения (ТО-мат-07: мало, размыто, обрезано); доля — от найденных |
| Поисков | Сессии поиска по лицу, начатые в периоде, — оператором и автосверкой (ТФ-ПЕР-09), автосверки отдельно |
| Совпадений выше порога | Кандидаты выдачи этих сессий: в выдачу попадают только лица, прошедшие порог схожести сессии (ТФ-ПЛ-06/08) |
| Подтверждено / отклонено / не определено / на верификации | Те же кандидаты по их статусу верификации на момент построения отчёта |

Поиски и их исходы относятся к подразделению **сессии** (кто искал), носители и лица — к подразделению **носителя**.
Исходы считаются по сессиям периода, а не по дате решения: так отчёт сводится с первичными записями (ОР-6.0.2) —
сколько поисков начато за месяц и чем они кончились.

### Разграничение и гриф (ТБ-020/021/032/033)

- Подсчёт — **на стороне БД под той же решёткой**, что каталог «Медиа» (`MediaAccessFilters`: гриф ≤ допуска,
  подразделение ∈ разрешённых, политика профиля): каждая строка носителя, лица, сессии и кандидата входит в счёт,
  только если видна субъекту; кандидат — ещё и если видна его сессия. Отчёт двух сотрудников с разным допуском
  различается — это и есть решётка, а не ошибка.
- Отбор по подразделению — только из разрешённых субъекту; без отбора — все разрешённые.
- Гриф отчёта и файла — **максимум грифа записей, вошедших в счёт** (сводка по ДСП сама является ДСП, как отчёты
  документооборота). Пустой отчёт — гриф 0.

### Профиль «Следствие»

- **Право** — новая строка матрицы «Статистические отчёты» (`reports.statistics`, раздел «Отчётность»): по умолчанию
  Руководитель, Администратор, Офицер ИБ. Оно же откроет журнал суточной активности и статистику карточек (части 2–4).
- **Раздел меню «Отчётность»**, страница «Результативность распознавания» (`/reports/recognition`): период (по
  умолчанию — текущий месяц), подразделение, таблица по подразделениям с итогом, гриф отчёта, выгрузка Excel / Word /
  PDF. Подразделение — полным наименованием с отделом (ОН/ОУ/ОТМ, ADR-0039).
- **Выгрузка** — тем же представлением и отрисовщиками, что отчёты документооборота (`ReportView`, `IReportRenderer`):
  маркировка грифа в файле, «Сформировал: ФИО, дата и время», отбор строкой. Отрисовщики не знают ни базы, ни допуска —
  отбор отработал раньше. Своего форматирования Excel/Word профиль не заводит.
- **Журнал (ТБ-030/032):** построение на экране — `View` (`investigation:reports:recognition:view`); выгрузка —
  `Export` (запись `EXPORT_REPORT` ОР-6.0.3) с грифом отчёта и применённым отбором в чувствительной части, **до** выдачи
  файла: не записалось — файла нет.
- Без ИИ: все показатели — счёт записей (детерминированно).

### Дальнейшие части (план, отдельными версиями этого ADR)

2. Журнал суточной оперативной активности (6.3, ТФ-ОТЧ-05): материалы, введённые за период, — дата и время, группа
   ОН/ОУ/ОТМ, сотрудник, № задания, объект (псевдоним), вид материала, статус.
3. Статистика созданных карточек объектов по подразделениям-инициаторам (ОР-6.0.1, ТФ-ОТЧ-04).
4. Отчёт по графу связей (6.4, ТФ-ОТЧ-06) — из карточки фигуранта, тем же обходом, что граф (ADR-0045), с ТБ-084.

## Последствия

- Миграций нет: отчёт читает существующие таблицы `media`.
- Новый порт пакета «Медиа» `IMediaStatistics` закрывает сам пакет (слой данных) — обязанностей профиля не прибавляет.
- Показатели ТФ-ВЕР-05 (доли исходов верификации) — те же счётчики; отдельный экран при необходимости строится на них.
