# ADR-0011. Выбор моделей, движка инференса и эмбеддера

| | |
|---|---|
| **Статус** | Принято частично (чат-движок/модель — по факту развёртывания; эмбеддер — Предложено, требует отдельного инстанса) |
| **Связь с ТЗ** | ТО-прог-01, ТО-прог-02, ТО-прог-03, ТО-лнг-02, ТН-001, ТН-002, ТБ-044 |
| **Источник** | [Справочник LLM API](../reference/llm-api-gemma.md) (документация заказчика) |

## Контекст

Получена документация по реальному локальному серверу ИИ заказчика. Ключевые факты:

- Движок инференса — **`ik_llama.cpp` (`llama-server`)**, OpenAI-совместимый API на порту 9000 (а не vLLM, как предполагалось ранее в черновиках).
- Развёрнутая модель — **Gemma 4 26B-A4B** (QAT, UD-Q4_K_XL), text-only.
- **Контекст — 65 536 токенов (64K)** (а не 250K).
- `/v1/embeddings` есть, но **Gemma-instruct не годится для качественных эмбеддингов** — рекомендована отдельная embedding-модель (EmbeddingGemma) на втором инстансе/порту.
- Модель **hybrid-thinking**: возможны блоки `<think>...</think>` в ответе.
- **Обработка последовательная** — одна модель, параллельные запросы встают в очередь.
- Авторизации нет (`api_key` — заглушка); рекомендованный сэмплинг Gemma 4: `temperature=1.0, top_p=0.95, top_k=64`.

Спайк [`spikes/LlmChat`](../../spikes/LlmChat) подтвердил: наш стек `Microsoft.Extensions.AI` (`IChatClient`) поверх OpenAI-совместимого клиента успешно работает с этим сервером (ответ на кыргызском получен).

## Решение

1. **Движок и доступ.** Инференс — локальный OpenAI-совместимый сервер (`ik_llama.cpp`/`llama-server`). Доступ из ядра — только через `IChatClient`/`IEmbeddingGenerator` (`Microsoft.Extensions.AI`); архитектура **engine-нейтральна**, конкретный сервер задаётся конфигурацией (keyed-роли, ТО-прог-02/03). Смена сервера/модели не требует правок ядра.
2. **Роли генерации.** `draft` и `analysis` — на текущей модели сервера (Gemma 4 26B-A4B). Параметры сэмплинга по умолчанию `temperature=1.0, top_p=0.95, top_k=64` (уже на сервере); переопределяются конфигом.
3. **Эмбеддинги — отдельной моделью.** Роль `embeddings` обслуживается **отдельным embedding-сервером** (EmbeddingGemma или аналог, второй порт/инстанс). Чат-модель для эмбеддингов **не используется**. Конкретная модель эмбеддингов выбирается бенчмарком с **раздельной метрикой ru/ky** (ТО-лнг-02, КИ-03) — это остаётся открытым пунктом.
4. **Reasoning.** Для чистых юридических ответов оркестратор (Э3-10) **вырезает `<think>...</think>`** либо сервер запускается с `--reasoning off`; reasoning включается выборочно по типу задачи.
5. **Бюджет контекста.** Планировать под **64K** (промпт + ответ). Усиливает необходимость RAG (корпус НПА не помещается целиком).
6. **Канал.** Доступ к серверу инференса — только от хоста, по внутреннему/loopback-интерфейсу (ТБ-044).

## Последствия

- ➕ Подход подтверждён живым спайком; интеграция `IChatClient`→сервер работает, в т.ч. генерация на кыргызском.
- ➖ Нужен **второй инстанс** под эмбеддинги — отдельная инфраструктурная задача (вход для Э3-02/Э3-04).
- ➖ **Последовательная обработка** → пропускная способность ограничена; для многопользовательского режима — очередь/тайм-ауты/несколько инстансов (НФТ ТН-001/002).
- ➖ Reasoning требует пост-обработки вывода (вырезание `<think>`), иначе мусор в документах.
- Открыто: точная модель эмбеддингов и её качество для ky (бенчмарк, КИ-03); решение по `--reasoning` на сервере.

## Заметка

Имя «Gemma 4» — реальное обозначение развёрнутой модели (`Gemma 4 26B-A4B`); прежняя пометка в черновиках о «несуществующих версиях» снимается. Точные id моделей берутся из `/v1/models` при развёртывании.
