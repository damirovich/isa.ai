## Контекст

Шаблон лица — L2-нормированный вектор фиксированной размерности (SFace: 128). Эталонная база — до 1 млн
шаблонов (ТН-005); поиск должен укладываться в p95 ≤ 5 с (ТН-006) и **не пропускать** существующее
совпадение (ЦС-02). Инцидент 26.08.2026 на `core.embedding` показал: HNSW с параметрами по умолчанию
теряет «острова» графа — малые группы непохожих векторов; документ есть, точный скан находит, индексный —
нет, даже при `ef_search=1000`. Лечит только пара `ef_construction=512` при сборке + `ef_search=200` на
транзакцию поиска. Для лиц ситуация ровно такая: редкое лицо среди тысяч чужих — это остров.

## Решение

1. **Метрика — косинусная** (`vector_cosine_ops`, оператор `<=>`), единообразно с ядром; на нормированных векторах эквивалентна скалярному произведению. Оператор запроса обязан совпадать с opclass индекса, иначе seq-scan.
2. **HNSW `m=16, ef_construction=512`** при сборке и `SELECT set_config('hnsw.ef_search', 200, true)` в явной транзакции на каждый поиск — те же значения, что закреплены для ядра после инцидента. Проба полноты после массовой загрузки/миграции/смены модели — по методике платформы (точный топ-K с `enable_indexscan=off` против индексного; критерий — пересечение ≥ K−1 и совпадение топ-1).
3. **Pre-filter решётки в той же строке, что и вектор**: `classification`, `division_id`, `is_current`, `quality_acceptable` денормализованы на `media.face_template` (NOT NULL); `WHERE` floor'а ядра ∧ политика профиля ∧ актуальность ∧ пригодность стоит **до** оператора расстояния — шаблоны вне допуска не участвуют даже в ранжировании; B-tree `(classification, division_id)` рядом с HNSW. Без `AccessContext` — исключение, не поиск без фильтра.
4. **Область поиска — после решётки, не вместо неё**: `FaceSearchQuery.AssetIds` (носители дел субъекта, ТБ-071/ТФ-ПЛ-05) сужает уже отфильтрованный набор; пустая область — пустая выдача.
5. **Размерность — константа сущности** (`FaceTemplate.Dimensions = 128`, тип столбца `vector(128)`), как `EmbeddingEntity.Dimensions` в ядре: смена модели = миграция + полная переиндексация; баллы привязаны к `model_version` (ТО-мат-09).
6. **Режим выдачи — investigation** (ISO/IEC 19795): кандидат-лист фиксированной длины (5..50, по умолчанию 20; ТН-008), порог — индикатор, который пользователь не может ослабить сверх потолка конфигурации (ТФ-ПЛ-06).

Отклонено: post-filter (сначала ANN, затем фильтр) — при узком допуске выдача пустеет и утекает факт наличия; фильтр по делам через `IAccessPolicy` (синхронный, одноконтекстный, `IN` на тысячи id в предикате) — вместо него явная область `AssetIds`.

## Последствия

- (+) GATE-4 доказывает решётку на настоящем pgvector (три теста: допуск/подразделение/актуальность/пригодность, fail-closed без контекста, порог после решётки).
- (+) Урок инцидента не повторяется: параметры зафиксированы в конфигурации сущности и в поисковом сервисе.
- (−) `ef_construction=512` удорожает сборку индекса (`maintenance_work_mem` по размеру графа) — учитывать при массовой загрузке.
- (!) Требование к серверу: исправный pgvector и `maintenance_work_mem` под размер графа. На 10.10.0.115 индекс ядра с этой парой параметров работает (инцидент 26.08.2026 закрыт миграцией `HnswIslandRecall`), миграция `InitialMedia` накатывается штатно.
