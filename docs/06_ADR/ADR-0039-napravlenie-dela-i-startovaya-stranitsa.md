## Контекст

ТЗ Заказчика (§1.3) требует стартовую страницу с наименованием «Оперативно-поисковое управление» и входом по
направлениям ОН, ОУ, ОТМ. По §2.1 ОН и ОУ работают в одной базе с взаимным анализом и поиском, ОТМ — изолированно;
по §2.2 сотрудник «ограничен рамками своей группы». В заявке установка сокращается и «УН», и «ОУ»; в системе принято
«ОУ» (решение Заказчика от 06.10.2026).

В системе уже есть справочник подразделений (иерархия), допуск сотрудника по подразделениям (`core.clearance`) и
подразделение у каждого дела; решётка (ТБ-020) показывает сотруднику только дела подразделений его допуска. Не хватало
одного: система не знала, какое подразделение — ОН, а какое — ОУ.

## Решение

1. **Отдел — свойство подразделения.** В справочнике подразделений профиля появилась отметка отдела
   (`investigation.division.direction`: 1 — ОН, 2 — ОУ, NULL — своей отметки нет; ограничение
   `ck_division_direction`). Подразделение без своей отметки получает её от ближайшего отмеченного вышестоящего:
   администратор отмечает отдел один раз, группы внутри наследуют. Правило — в одном месте (`DivisionDirections`).
   ОТМ в перечне нет — это отдельный экземпляр (ТС-014).
2. **Дело относится к отделу через своё подразделение.** Отдельного поля у дела нет: отдел дела вычисляется по
   подразделению в списке и карточке. Сменить отметку подразделения — значит перенести в другой отдел все его дела и
   дела вложенных без своей отметки; поэтому новая отметка записывается в журнал (ТБ-030). Дела, заведённые раньше,
   получают отдел сами, как только их подразделение отмечено.
3. **Новое дело получает отдел автоматически.** Если в допуске сотрудника одно подразделение, форма подставляет его
   сама (так было и раньше); подсказка под полем показывает, к какому отделу отнесётся дело. При нескольких
   подразделениях сотрудник выбирает (ТБ-024: без угадывания).
4. **Видимость решает допуск, отметка — только отбор.** Какие дела видит сотрудник, по-прежнему решает допуск по
   подразделениям, гриф и роль (ТБ-020). Действующий вариант — «каждый работает в своём отделе»: администратор выдаёт
   сотруднику в допуск подразделения его отдела. Чтобы сотрудник видел оба отдела, ему добавляют в допуск подразделения
   второго — код и данные при этом не меняются; можно и выборочно (например, только руководителям). Отбор по отделу
   в списке сужает его внутри допуска и ничего не открывает.
5. **Взаимный поиск ОН+ОУ — отдельная задача.** Поиск по лицу и пересечения по обоим отделам с выдачей из чужого
   отдела только «есть совпадение: дело №…, отдел, ответственный» (без открытия карточки; Приложение В, вопрос 2)
   делаются отдельно (ТБ-071, ТФ-ПЛ-05, ТФ-ДЕЛ-03). До этого «свой отдел» означает только свой отдел.
6. **Стартовая страница — из профиля.** В манифест профиля добавлено нейтральное свойство `IProfile.HomeComponent`
   (тип компонента без маршрута, по умолчанию `null`); хост на «/» рисует его через `DynamicComponent`, без него —
   прежнюю визитку. Хост не знает ни об ОПУ, ни об отделах (ТС-003, ТС-011); у «ИнспектораAI» главная прежняя.
   Профиль «Следствие» показывает «Оперативно-поисковое управление» и плитки ОН и ОУ: плитка активна, только если в
   допуске есть подразделение этого отдела, и открывает список дел с отбором (`/cases?direction=on|ou`). ОТМ — надпись
   «вход с рабочих мест контура ОТМ» без ссылки и без адреса. Вход — одной учётной записью.

## Последствия

- **Плюсы.** Одно понятие вместо двух: отдел, подразделение и допуск согласованы сами, ручной разметки дел нет.
  Вариант видимости переключается настройкой допусков, без переделки. Ядро получило одно нейтральное свойство.
- **Минусы.** Пока администратор не отметит отделы в справочнике, плитки неактивны (страница подсказывает это), а у
  дел в списке прочерк в столбце «Отдел». Смена отметки подразделения массово переносит его дела в другой отдел —
  это действие администратора справочника, и оно записывается в журнал.
- **Не сделано.** Взаимный поиск ОН+ОУ (п. 5), архив по отделам (ТФ-ДЕЛ-06), отбор материалов, сводок и поиска по
  отделу, показ отдела рядом с подразделением при выдаче допуска.
