## Контекст

У Заказчика накоплено около 10 ТБ материалов (ДОК-14 §7). После ADR-0040 система принимает файлы любого
разумного размера, но только по одному и только через браузер, а оператор выбирает дело для каждого файла. Для
архива в десятки тысяч файлов это неприменимо.

Есть ещё два препятствия, кроме ручного ввода:

- **Одна очередь обработки на всех.** Поиск лиц и расшифровка речи идут через общую фоновую очередь, по одной
  задаче. Если поставить в неё весь архив разом, новые материалы следователей будут ждать неделями (ДОК-14 §7.3
  требует обратного: новые материалы не ждут архива).
- **Очередь живёт в памяти.** После перезапуска сервера всё, что стояло в очереди, переводится в «ошибку, прервано
  перезапуском» и требует ручного повтора. Для архива, который обрабатывается неделями, перезапуск неизбежен.

Структура архива Заказчика пока не известна (вопросы отправлены группе). Поэтому импорт не должен зависеть от
раскладки папок.

## Решение

1. **Архив читается с диска сервера, опись загружается через браузер.**
   - Каталоги, откуда можно брать архив, задаёт эксплуатант: `Media:Import:Roots` (список путей). Оператор
     выбирает каталог и вложенную папку. Пути вне списка недоступны — сервер не читает произвольные файлы по
     просьбе пользователя.
   - Каталог импорта не может лежать внутри хранилища материалов или временного каталога: иначе через импорт
     можно было бы «перенести» в своё дело чужой материал из хранилища.
   - Пути в описи — относительные к выбранной папке. Абсолютный путь, выход выше папки (`..`), символическая
     ссылка или точка соединения (junction) на любом участке пути, скрытые и системные файлы — отказ по строке.
   - Архив только читается: в его каталоги система ничего не пишет (цепочка хранения, ТБ-077).
2. **Опись — таблица CSV**, которую готовят в Excel.
   - Разделитель определяется по строке заголовка: `;`, `,` или табуляция. Кодировка — UTF-8 (с BOM или без) или
     Windows-1251, как сохраняет Excel в русской Windows.
   - Столбцы (заголовок без учёта регистра): **файл**, **дело** — обязательные; **подразделение** (код — нужен,
     только если номер дела повторяется в разных подразделениях); **дата съёмки**; **источник**; **место**;
     **sha256** (контрольная сумма, если её посчитали на стороне Заказчика).
   - **Черновик описи** система строит сама по выбранной папке: все файлы допустимых форматов с пустыми
     реквизитами. По выбору оператора столбец «дело» заполняется именем папки первого уровня — на случай, если
     архив разложен по папкам дел. Черновик скачивается, правится в Excel и загружается обратно.
   - Пределы: опись не больше 50 МБ и 200 000 строк — проверка держит строки в памяти сервера; архив больше
     разбивается на несколько описей и заданий (по годам, по отделам).
3. **Проверка до запуска** — без записи чего-либо.
   - Разбор описи; файл существует, это обычный файл, размер в пределе своего вида (ADR-0040), формат допустим
     по расширению; дело найдено среди дел, **доступных оператору** по допуску и роли (ТБ-020/071); номер не
     повторяется в разных подразделениях без кода; дата разобрана; строка с тем же файлом не повторяется.
   - Итог — по делам: номер, название, подразделение, отдел (ОН/ОУ/ОТМ), гриф, закрыто ли, сколько файлов и
     какой объём. Отдельно — ошибки по строкам и счётчик «только дата, без времени».
   - Сигнатура содержимого и дата из метаданных проверяются **при приёме** файла, а не на проверке: прочитать
     начало каждого файла архива — это часы работы диска до того, как оператор увидит итог.
4. **Гриф и подразделение подтверждаются пачкой (ТБ-024).**
   - Каждый файл получает гриф и подразделение **своего дела** (ТБ-070) — как при обычной загрузке. Оператор
     не вводит гриф, а подтверждает показанные значения галочкой «Гриф и подразделение каждого дела проверены».
   - Подтверждённые гриф и подразделение запоминаются в строке задания. Если до приёма файла у дела поменяли гриф
     или подразделение, файл **не принимается** («гриф или подразделение дела изменились после подтверждения»):
     подтверждение относилось к прежним значениям.
   - Материалы ОТМ ложатся только в дела подразделений ОТМ — так их не увидят ОН и ОУ (ТС-014). Отдел
     показывается в итоге проверки именно для этого.
5. **Задание хранится в БД и переживает перезапуск.**
   - Таблицы `media.import_job` (задание) и `media.import_item` (строка = файл: путь, дело, подтверждённые гриф и
     подразделение, состояние, причина отказа, хеш, носитель).
   - Задание идёт в фоне: оператор может закрыть страницу. Его можно остановить и продолжить с того же места.
     Строка, которую принимали в момент остановки или аварии, начинается заново: повтор безопасен благодаря
     дедупликации по хешу (ТФ-МЕД-04) и идемпотентной привязке к делу.
   - Задания выполняются по одному, в порядке запуска: архив читается с одного диска, параллельное чтение его
     только замедлит.
6. **Каждый файл принимается от имени оператора, с проверками на каждом файле.**
   - Перед каждым файлом заново читаются (ТБ-016): учётная запись активна и допуск действует (новый порт ядра
     `IUserAccessReader` — тот же читатель, что у входа), право «Импорт архива» есть, дело доступно оператору.
     Утрата права или допуска **останавливает задание** с причиной — без неё все остальные файлы получили бы
     одинаковый отказ.
   - Приём — тем же путём, что у обычной загрузки (общий сервис приёма): сигнатура по содержимому (ТС-010),
     предел по виду, SHA-256 по ходу записи, дедупликация, привязка к делу.
   - **Контрольная сумма из описи** сверяется до записи в хранилище: расхождение — отказ, файл в хранилище не
     попадает (повреждён при переносе или опись ошибочна).
   - **Дата съёмки** (ТФ-МЕД-17): из описи; нет в описи — из метаданных файла (EXIF фото, заголовок MP4/MOV — как
     подсказка при обычной загрузке); у фото и видео без даты — отказ с причиной «нет даты съёмки — укажите в
     описи». Дата без времени — 00:00 по местному времени. Подтверждение оператором значений из метаданных — та же
     галочка запуска (п. 4).
7. **Обработка архива — малыми порциями, без вытеснения новых материалов.**
   - Принятый файл архива не ставится в очередь обработки сразу. Задание подаёт в общую очередь не больше
     `Media:Import:ProcessingSlots` носителей одновременно (по умолчанию 1, допустимо 1–8) и следующий — когда
     предыдущий обработан. Новый материал следователя ждёт не дольше обработки одного носителя архива.
   - Носитель, чья обработка прервана перезапуском, задание ставит заново само. Носители архива, ещё не поданные
     в обработку, при старте сервера не переводятся в «ошибка, прервано перезапуском»: они не прерваны, а ждут
     своей очереди.
   - Копирование файлов и обработка идут одновременно: копирование упирается в диск, обработка — в процессор.
8. **Журнал и отчёт (ТБ-030, ТБ-077).**
   - В неизменяемый журнал пишутся запуск задания (с SHA-256 описи, числом строк и дел), остановка, продолжение,
     завершение и **каждый файл** — принят, дубликат или отказ: кто, когда, файл, хеш, дело, носитель. Это
     цепочка хранения: хеш до переноса (из описи) и после (посчитан при приёме).
   - Отчёт задания выгружается в CSV. Строки с отказами выгружаются в формате описи — их можно исправить и
     загрузить новым заданием; уже принятые файлы повторно не появятся (дедупликация).
9. **Право — отдельная строка матрицы доступа** «Импорт архива материалов» (`media.import`, ADR-0032), по
   умолчанию у Администратора. Раздел меню «Импорт архива» — в группе «Медиа». Решётка допуска и сужение по делам
   действуют как всегда: право открывает экран, а не чужие дела.

## Порты и границы

- Пакет «Медиа» по-прежнему не знает про «отдел», «номер дела» и роли. Профиль даёт:
  - `ICaseScope.FindCasesByNumberAsync` — дела по номерам среди доступных субъекту, с наименованием и кодом
    подразделения и подписью отдела;
  - `IMediaAdministration.CanImportArchiveAsync` — право текущего субъекта (экран, команды) и
    `UserCanImportArchiveAsync` — право пользователя по идентификатору (фоновое задание).
- Ядро даёт `IUserAccessReader` — допуск конкретного пользователя свежим чтением, `null` при неактивной учётке
  или отсутствии допуска. Это не обход решётки: результат — тот же `AccessContext`, что получил бы сам
  пользователь при входе, и он применяется теми же фильтрами.

## Реализация

- Пакет «Медиа»: модель и порт заданий (`MediaImport`, `IMediaImportStore`), хранилище с вставкой строк через `COPY`
  (`MediaImportStore`, миграция `MediaImportJobs`), разбор описи (`ImportManifest`), безопасные пути
  (`MediaImportPaths`), проверка (`MediaImportPlanner`), исполнитель и подача в обработку (`MediaImportRunner`,
  `MediaImportFeeder`, фоновая служба `MediaImportWorker`), общий приём файла для загрузки и импорта (`MediaIntake`,
  `MediaProcessing`), экраны `/media/import` и `/media/import/{id}`.
- Носитель получил ссылку на строку импорта (`asset.import_item_id`): по ней исполнитель узнаёт свой носитель после
  аварии посреди приёма, а восстановление при старте не переводит в «ошибка» носители, ещё ждущие подачи.
- Профиль «Следствие»: поиск дел по номерам (`CaseScope.FindCasesByNumberAsync`), право `media.import` в матрице и
  пункт меню «Импорт архива».

## Последствия

- **Плюсы.**
  - Архив переносится без ручной раскладки по делам; структура папок Заказчика влияет только на то, как
    заполнить опись.
  - Режим не ослаблен: гриф и подразделение — от дела, допуск и право проверяются на каждом файле, сигнатура и
    предел — как у обычной загрузки, каждый файл — в журнале.
  - Перезапуск сервера не теряет ни копирование, ни обработку архива.
  - Следователи не ждут архив.
- **Минусы и ограничения.**
  - Обработка архива последовательная: срок — недели (ДОК-14 §7.2). Параллельная обработка нескольких носителей —
    отдельное решение после замера на образце архива.
  - Файл копируется дважды (во временный каталог и в хранилище), как при обычной загрузке: временный каталог
    должен вмещать самый большой файл архива.
  - Дела должны быть заведены до импорта: строки с неизвестным номером дела — отказ на проверке.

## Не сделано

- Заведение дел по описи (если в архиве сотни дел, которых нет в системе).
- Пакетный ввод документов (сводки, справки `.docx`) в документооборот.
- Параллельная обработка носителей архива; чтение оригинала на месте без временной копии.
- Импорт из архивных файлов (`.zip`, `.7z`) без распаковки — архив распаковывается на диск заранее.
