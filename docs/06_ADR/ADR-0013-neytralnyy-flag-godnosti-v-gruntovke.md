# ADR-0013. Нейтральный флаг годности источника в грунтовке

| | |
|---|---|
| **Документ** | ДОК-06 / ADR-0013 |
| **Система** | ISC.AI («ИнспекторAI») |
| **Версия** | 0.1 (черновик) |
| **Статус** | **Принято** |
| **Связь с ТЗ** | ТБ-040, ТО-инф-04 (основные); ТС-003, ТБ-041, ТО-мат-02, ТЭ-003, GATE-2, GATE-3, КИ-02, Ц-04 |

## Контекст

Цель архитектуры — **одно нейтральное ядро** для любого профиля внутреннего контроля (ТС-003, ADR-0002). Доменная модель НПА (норма, редакция, статус «действующая/утратила силу») специфична для профиля «ИнспекторAI» и выносится из ядра в схему `inspector` (ДОК-04 §3.6–3.8). Это вскрывает конфликт инвариантов:

- **ADR-0008 (§2)** делает проверку **статуса редакции** явной частью шага грунтовки и прямо фиксирует: грунтовка сама по себе **не считается достаточной** защитой от выдачи утратившей силу редакции, поэтому статус проверяется явно.
- **ADR-0005** требует, чтобы инвариант грунтовки жил **в ядре** и **не мог быть ослаблен профилем** (профиль — менее доверенная сменная часть, ADR-0002).
- **GATE-3 / КИ-02** — блокирующий приёмочный критерий: утратившая силу редакция не выдаётся как действующая.

Если просто убрать статус редакции из ядровых контрактов (`RetrievedChunk`, `IGroundingValidator`) вслед за выносом НПА-модели, ядро структурно **не сможет** выполнить проверку ADR-0008, а защита GATE-3 окажется целиком в сменном профиле — это нарушает ADR-0005. Если же оставить НПА-понятия (`NormId`, `RevisionStatus`) в ядровых контрактах — ядро перестаёт быть профиле-нейтральным (нарушение ADR-0002). Нужен способ сохранить ядровый неотключаемый контроль годности, не вводя в ядро доменных понятий.

## Решение

Ядро держит **доменно-нейтральный обязательный флаг годности источника** и сам его проверяет; доменную семантику в флаг наполняет профиль, **не имея права отключить** ядровую проверку:

1. **Нейтральный флаг в данных и контрактах.** На чанке ядра — `core.chunk.is_current` (`boolean NOT NULL`, default `true`); в ядровом контракте извлечения — `RetrievedChunk.IsCurrent` (`bool`). Понятия «норма»/«редакция»/«статус» в ядре **отсутствуют**; НПА-атрибуты при необходимости передаются профилем в нейтральных расширяемых метаданных (`core.document.metadata` jsonb / `RetrievedChunk.Metadata`).
2. **Ядровый фильтр и ядровая проверка.** `IRetriever` по умолчанию возвращает только источники с `IsCurrent = true` (поверх обязательного фильтра доступа, ТБ-020). `IGroundingValidator` отвергает как подтверждённую любую ссылку на источник с `IsCurrent = false` — это **обязательная и неотключаемая** часть шага грунтовки в ядре (развитие ADR-0005/0008, GATE-2/И-GRND-1).
3. **Материализация смысла профилем.** Доменный статус редакции профиль материализует в нейтральный флаг: при переводе редакции НПА в «утратила силу» профиль в **той же транзакции** выставляет `is_current = false` для связанных чанков (по `inspector.chunk_revision_link`, ДОК-04 §6.3). Доменное извлечение и нормализацию ссылок (для НПА — привязка к норме/редакции, ADR-0008/ТО-мат-02) профиль поставляет через расширяемые точки (например `ICitationNormalizer`/`IRetrievalRefiner`), которые **дополняют**, но не ослабляют ядровой инвариант.

Отклонённые альтернативы: (а) оставить `NormId`/`RevisionStatus` в ядровых контрактах — ядро не нейтрально (нарушение ТС-003/ADR-0002); (б) полностью перенести защиту от утратившей силу редакции в профиль — делает блокирующий GATE-3 зависимым от корректности сменного профиля (нарушение ADR-0005); (в) убрать проверку статуса из грунтовки вовсе — нарушение ADR-0008 и невыполнение GATE-3.

## Последствия

Положительные:
- Ядро становится профиле-нейтральным (ТС-003), но инвариант грунтовки и блокирующий GATE-3/КИ-02 остаются **ядровыми** и неотключаемыми (ADR-0005).
- Нейтральный `IsCurrent` пригоден любому профилю (для не-НПА вертикали — «актуальная/устаревшая запись»), не навязывая чужого понятия редакции.
- Защита от выдачи устаревшего источника обеспечивается данными + запросом + грунтовкой, а не только текстовой проверкой (усиление ADR-0008).

Отрицательные / обязательства:
- Профиль обязан поддерживать `is_current` в согласованном состоянии **транзакционно** при смене статуса редакции; рассинхронизация флага — доменный дефект профиля.
- Связки `inspector.chunk_revision_link`/`norm_document_link` ссылаются на ядро «слабо» (по значению, без FK через границу схем, ТО-инф-06); при гарантированном удалении носителя в ядре (ТБ-064) профиль обязан удалять осиротевшие строки связок в той же транзакции.
- Контрактные документы (ДОК-04 §2/§3/§6, ДОК-05 §2.6/2.7/2.10) приведены к нейтральной форме; обратное введение НПА-полей в сборки ядра запрещено и проверяется архитектурным тестом (запрет идентификаторов `Norm*`/`Revision*`/`Legal*` в `ISC.AI.Abstractions`/`ISC.AI.Persistence`).

## Связь с ТЗ

- **ТБ-040** — грунтовка как контракт: неподтверждённые/неактуальные ссылки не выдаются как готовые; проверка флага годности — в ядре.
- **ТО-инф-04** — модель версионности редакций (домен профиля) материализуется в нейтральный флаг годности ядра.
- **ТС-003 / ADR-0002** — нейтральное ядро: НПА-понятия отсутствуют в ядровых контрактах.
- **ADR-0005 / ADR-0008** — инвариант грунтовки в ядре, не ослабляемый профилем; проверка годности источника строже строкового совпадения.
- **GATE-3, КИ-02** — невыдача утратившей силу как действующей остаётся блокирующим ядровым критерием.
- **ТЭ-003** — явная маркировка «УТРАТИЛА СИЛУ» при показе неактуальных источников (на стороне профиля).

> Запись принята как следствие рефактора нейтральности ядра. Конкретные сигнатуры расширяемых точек (`ICitationNormalizer`/`IRetrievalRefiner`) и метод нормализации ссылок калибруются вместе с ADR-0008 на рабочем этапе Э1.
