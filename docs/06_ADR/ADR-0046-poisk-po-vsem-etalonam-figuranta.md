## Контекст

Кнопка «Искать по материалам» в карточке фигуранта ищет по **одному** эталону — лучшему по качеству (ТФ-ПЛ-03, через
лицо носителя). У объекта обычно несколько эталонов: анфас и полупрофиль, разные годы, разное освещение. Поиск по
одному из них пропускает материалы, где человек похож на другой эталон; поиск по каждому отдельно даёт несколько
сессий, где один и тот же кандидат повторяется — и его пришлось бы верифицировать столько раз, сколько эталонов
(правило двух лиц, ТБ-073, — работа двух сотрудников на каждый повтор). ТФ-ПЕР-03 требует поиска «по всем эталонным
изображениям (агрегация кандидатов)».

## Решение

1. **Одна сессия — несколько проб.** Сценарий поиска по лицу (`SearchByFaceQuery`) принимает третий вид пробы —
   **список лиц-эталонов** (`ProbeFaceIds`, от 2 до 10 лиц) наряду с изображением и одним лицом носителя. Каждое лицо
   проверяется так же, как одиночная проба: под решёткой и только из материалов доступных субъекту дел (ТБ-071,
   ДОК-13 §248); недоступное лицо — отказ всего поиска «не найдено или недоступно» (ТБ-020/021). Лицо без шаблона
   (непригодно по качеству, ТО-мат-07, или шаблон удалён регламентом закрытого дела, ТБ-074) **пропускается** с
   причиной на странице и в журнале; если пригодных не осталось — отказ с причинами.

2. **Сводный кандидат-лист** (агрегация, ТФ-ПЕР-03). По каждой пригодной пробе — обычный поиск ближайших соседей в
   той же области и с теми же порогом и шириной выдачи (ТФ-ПЛ-06, ТН-008). **Порог у поиска по эталонам
   обязателен**: без порога оператора и конфигурации берётся рабочий порог системы — тот же, что у предложений
   (ADR-0035; 0,5, то есть схожесть от 50 %, до калибровки ТО-мат-08). Он записывается в сессию и виден на странице.
   Без порога «согласие эталонов» ничего не значило бы: каждый эталон выдаёт ширину выдачи ближайших лиц, и на малой
   базе почти любой кандидат «нашёлся бы всеми эталонами» (замечание по проверке 14.10.2026). Выдачи сводятся по
   лицу-кандидату:
   - для отобранных кандидатов расстояние до **каждого** эталона пересчитывается по шаблону кандидата (в памяти,
     ТБ-074): эталон мог не выдать кандидата не потому, что тот далёк, а потому, что выдачу заняли другие лица — в
     видео десятки кадров одного человека;
   - расстояние кандидата — **наименьшее** из расстояний до эталонов (лучшее совпадение);
   - запоминается **эталон, по которому оно лучшее** (`ProbeFaceId` кандидата; при равенстве — первый по порядку), и
     **у скольких эталонов** расстояние в пределах порога (`ProbeMatchCount`) — согласие нескольких эталонов говорит
     оператору больше, чем один балл;
   - порядок — по расстоянию, при равенстве — по числу совпавших эталонов; ширина выдачи — как у обычного поиска;
   - **сами эталоны** в кандидаты не попадают: это уже известные снимки этого человека.
   Балл по-прежнему вероятностный и показывается с предупреждением (ТЭ-006); слова «кандидат», не «найден» (ТЭ-005).
   - **Порог на странице — схожестью в процентах** (замечание заказчика 14.10.2026: «порог расстояния» приходилось
     пересчитывать в уме). Поле «Схожесть не ниже, %» (не ниже предела эксплуатанта: 20 % при пределе расстояния
     0,8), в поиск уходит расстояние 1 − схожесть; выдача и страница сессии подписывают порог так же — «схожесть от
     N %». Для всех видов поиска, не только по эталонам; хранение и журнал — по-прежнему расстоянием.

3. **Хранение** (ТО-инф-12). Сессия — та же сущность: `ProbeFaceId` — первый (лучший по качеству) эталон, новое поле
   `ProbeFaceIds` — все пригодные эталоны поиска; хеш пробы (`ProbeSha256`) — SHA-256 от перечня хешей шаблонов
   эталонов через «;» в порядке поиска. У кандидата — новые поля `ProbeFaceId` и `ProbeMatchCount` (у одиночного
   поиска пусты). Векторы проб в базу не пишутся (ТБ-074), как и раньше. Миграция схемы `media` — три nullable-колонки,
   прежние сессии не меняются.

4. **Верификация — один раз на кандидата** (ТБ-073). Кандидат сводного списка — одна строка, верифицируется один раз.
   Пара «проба ↔ кандидат» (ТФ-ВЕР-01) показывает **эталон, по которому совпадение лучшее**, и подпись «совпало
   эталонов: k из N». Подсказка «уже подтверждено у …» (ТФ-ВЕР-03) и запись появления — без изменений.

5. **Карточка фигуранта.** Кнопка «Искать по материалам» ищет по **всем** действующим эталонам с лицом (не
   заменённым и не с отозванного появления), до 10 лучших по качеству; подпись — «эталонов: N · все доступные
   дела». Один пригодный эталон — прежний поиск по одному лицу. Область, основание и права — как раньше (ADR-0044,
   ТБ-071): страница поиска открывается с заполненной формой, при единственном основании поиск запускается сразу.

6. **Аудит** (ТБ-072). Запись поиска — та же, состав расширен: все эталоны (лицо, носитель, хеш шаблона), пропущенные
   эталоны с причиной, полный кандидат-лист с лучшим эталоном и числом совпавших эталонов у каждого кандидата.

## Не сделано

- **Несколько проб-изображений** (загрузка нескольких фото сразу) — только лица уже проиндексированных эталонов.
- **Объединение «по лицу» результатов разных сессий** (например, ручного поиска и предложений системы) — каждая
  сессия по-прежнему отдельна; предложения системы остаются по одной паре «эталон × носитель» (ADR-0035).
- **Учёт согласия эталонов в балле** (например, «среднее по эталонам»): балл — лучшее совпадение, согласие показано
  отдельным числом; другой способ свёртки — после калибровки на пилоте (ТО-мат-08).

## Последствия

- Одна кнопка вместо N ручных поисков; один кандидат — одна верификация.
- Поиск по N эталонам — N запросов к индексу лиц; при N ≤ 10 и ТН-005 это в пределах ТН-006 (до 5 с, p95), но на
  пилоте замеряется отдельно.
- Миграция `media`: `search_session.probe_face_ids integer[]`, `search_candidate.probe_face_id integer`,
  `search_candidate.probe_match_count smallint` — все необязательные.
