## Контекст

По заявке ОПУ отделы ОН и ОУ «доступны для взаимного анализа и поиска» [Расш. 2.1]; ТБ-071 и ТФ-ПЛ-05 требуют
области «все дела ОН и ОУ в пределах допуска». Сейчас область «все доступные дела» строится по полной решётке
профиля — floor ядра (гриф ≤ допуск, подразделение ∈ разрешённых), политика профиля и **сужение по роли**
(`CaseAccessRule.Narrow`): Руководитель, Эксперт по лицам, Верификатор, Офицер ИБ и Администратор ищут по всем делам в
пределах допуска, а **Следователь — только по своим** (ведущий или автор записи). Значит, взаимного поиска нет
именно у Следователя — той роли, которой он нужнее всего.

Расширить область мало: кандидаты из чужих дел попали бы в выдачу, но открыть их следователь не смог бы — просмотр
носителя (карточка, файлы, кадры) проверяет ту же полную решётку с сужением по роли. Что показывать по кандидату из
чужого дела — решение заказчика. Варианты: как у пересечений (ADR-0029 — номер и вид дела, ведущий, без материала),
плюс вырезка лица, либо полный просмотр носителя. **Заказчик 14.10.2026 выбрал полный просмотр носителя**
(фото или видео, кадр, место, дата), карточка чужого дела при этом не открывается.

## Решение

1. **Область «все доступные дела» = все дела в пределах допуска** (ТФ-ПЛ-05): floor ядра и политика профиля, **без
   сужения по роли и владению** — то же правило, что у пересечений (ADR-0029 п. 1). Новый метод порта
   `ICaseScope.ListCasesWithinClearanceAsync`. Субъект без роли профиля — пусто (default-deny, ТБ-012); право
   «Поиск по лицу» проверяется, как и раньше, до поиска. Для ролей без сужения ничего не меняется.
   - **ОТМ** отдельного правила не требует (ТС-014, ADR-0029 п. 8): дела ОТМ лежат в подразделениях ОТМ, и
     сотруднику без допуска к ним floor по подразделениям их не даст ни в область, ни счётчиком.
   - **Закрытые дела** — только по галочке «искать и по закрытым» (ADR-0024), как раньше.
   - **«Выбранные дела»** остаются выбором из своих дел по роли: список выбора показывает номера и названия дел, а
     название задания содержит ФИО объекта — перечень чужих дел целиком следователю не раскрывается.
   - **Аудит** (ТБ-072): область и полный список дел попадают в запись поиска, как и раньше.
2. **Просмотр носителя кандидата** (решение заказчика). Носитель, который субъект не видит по делу, открывается **на
   просмотр**, если он — кандидат поисковой сессии, проведённой в деле, **доступном субъекту по полной решётке**
   (свой поиск, поиск коллеги в своём деле, предложение системы по своему делу — ADR-0035), и сама строка кандидата
   проходит floor (гриф и подразделение носителя в пределах допуска). Правило одно —
   `AssetViewAccess.CanViewAsync` в домене пакета «Медиа» — и применяется во всех путях **чтения**:
   карточка носителя, файлы (оригинал, вырезки лиц, раскадровка), кадры видео, сведения о лице, расшифровка.
   Место и дата кандидата (ТФ-ПЛ-02) читаются в пределах допуска тем же образом (`ICaseScope.ListCandidatePlacesAsync`).
   - **Карточка чужого дела не открывается** (ТФ-ДЕЛ-03 без изменений): у носителя из чужого дела поле «дело» пусто,
     фигуранты чужого дела на ленте видео не показываются. Номер чужого дела и ведущий сотрудник становятся видны
     через пересечения, когда эксперты подтвердят появление (ADR-0029 п. 3а).
   - **Пробой лицо кандидата из чужого дела не берётся**: это уже не просмотр, а новое использование биометрии
     чужого материала (нарушитель «сотрудник, ищущий вне своего дела», ДОК-13 §12). Искать человека дальше — по
     эталонам своего фигуранта после подтверждения появления.
   - **Карточка носителя из чужого дела — только просмотр**: кнопки действий (эталон, привязка, снимок кадра,
     переиндексация, удаление, поиск по лицу) на ней не показываются; **скачивания нет** — ни кнопки «Скачать
     оригинал», ни пункта скачивания встроенного проигрывателя: скачать — уже выдача материала, а не просмотр.
     Технически браузер получает файл, чтобы его показать (как и для своих носителей), — это просмотр, он в журнале.
   - **Изменения закрыты**: привязка лица к фигуранту, эталон, дата съёмки, снимок кадра в дело, переиндексация,
     перерасшифровка, удаление — только по полной решётке, как раньше. Подтверждают кандидата эксперт и верификатор
     (правило двух лиц, ТБ-073) — у них сужения по роли нет.
   - Просто листать чужие материалы нельзя: доступ появляется только у носителей, найденных поиском, и только у
     тех, кому доступна поисковая сессия по делу. Каждое открытие файла и карточки пишется в журнал (ТБ-030), как
     и для своих носителей.
3. **Подписи.** Область на экране поиска — «все дела в пределах допуска», с пояснением, что это дела и других
   сотрудников (взаимный поиск), а материалы найденных кандидатов открываются на просмотр.

## Последствия

- **Плюсы.** Следователь ОН находит человека в материалах ОУ и наоборот — то, ради чего отделы работают в одной базе.
  Floor ядра не ослаблен: дело выше допуска или чужого подразделения (в том числе ОТМ) в область не попадает вовсе.
  Правило просмотра одно для всех путей чтения и привязано к результату поиска, а не к роли.
- **Минусы и риски.** Раскрытие шире, чем у пересечений (ADR-0029): по кандидату следователь видит сам материал
  чужого дела. Это сознательное решение заказчика; Администратор управляет им тем же механизмом — разрешёнными
  подразделениями и грифом учётной записи. Расхождение с ADR-0029 нужно описать в руководстве администратора.
- **Что проверяют тесты.** Модульные: область «все доступные» строится по делам в пределах допуска; правило
  просмотра — своё дело, кандидат сессии доступного дела, кандидат сессии недоступного дела; карточка носителя
  кандидата открывается без дела. Интеграционные (Testcontainers): следователь получает в область чужие дела в
  пределах допуска, но не дела выше грифа, другого подразделения и без роли; кандидат виден по floor; место
  кандидата читается в пределах допуска.

## Не сделано

- Номер и ведущий чужого дела у кандидата до подтверждения — по запросу заказчика.
- Выбор отдельных чужих дел в области «выбранные дела».
- Поиск по лицу кандидата из чужого дела — по отдельному решению заказчика.
