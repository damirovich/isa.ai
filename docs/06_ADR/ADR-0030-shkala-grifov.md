## Контекст

Гриф в системе хранился числом 0–9 без названий: формы предлагали «0 — открытый, 1, 2 … 9», документооборот
маркировал отчёты «ДСП. Гриф: 2», «Инспектор» — «ГРИФ 3». Заказчик требует привычную режимную шкалу:

| Уровень | Смысл |
|---|---|
| Без грифа / несекретно | Открытая информация; «несекретно» не является степенью государственной секретности |
| ДСП | «Для служебного пользования»: несекретная информация с ограничением распространения |
| Секретно | Степень секретности государственных секретов |
| Совершенно секретно | Более высокая степень |
| Особой важности | Наивысшая из этих трёх степеней |

Шкала 0–9 при этом была размазана по коду: пределы 9 в валидаторах допусков и дел, списки выбора в пяти формах,
две копии чипа грифа, три разных текста маркировки.

## Решение

1. **Число остаётся, названия добавляются.** Гриф и допуск по-прежнему `smallint`, решётка сравнивает числа
   (гриф ≤ допуск). Уровни: **0** — «Без грифа», **1** — ДСП, **2** — «Секретно», **3** — «Совершенно секретно»,
   **4** — «Особой важности». Схема БД не меняется.
2. **Один источник.** `ISC.AI.Abstractions.Security.ClassificationLevels` — предел шкалы (`Max = 4`), названия
   (`Label`), маркировка документа (`Marking`: «НЕСЕКРЕТНО», «ДЛЯ СЛУЖЕБНОГО ПОЛЬЗОВАНИЯ», «СЕКРЕТНО», «СОВЕРШЕННО
   СЕКРЕТНО», «ОСОБОЙ ВАЖНОСТИ»), пояснения (`Description`). Из него берут предел все валидаторы (допуск, дело,
   документ, загрузка и импорт корпуса, методика), списки выбора всех форм, оба чипа грифа, отчёты
   документооборота и экспорт «Инспектора». Константы валидаторов (`SetUserClearanceValidator.MaxClassification`,
   `CreateCaseValidator.MaxClassification`) сохранены как ссылки на `ClassificationLevels.Max`.
3. **Прежние значения 5–9.** По новой шкале всё, что выше «Особой важности», и есть «Особая важность».
   - В изменяемых таблицах миграции `ClassificationScaleFiveLevels` (ядро, документооборот, медиа, «Инспектор»,
     «Следствие») приводят значения выше 4 к 4 — во всех колонках `classification`, `max_classification`,
     `result_classification` схемы. Без этого после приведения допусков к шкале строки 5–9 не увидел бы никто.
   - **Журнал аудита не переписывается**: он неизменяем (триггер, цепочка хешей, ТБ-030). Его записи выше 4
     `AuditReader` читает как «Особой важности» — их видит высший допуск.
   - Показ: `Label`/`Marking` значения выше 4 выводят как «Особой важности»; для ввода такие значения недопустимы.
4. **Аудит при неизвестном допуске.** Раньше такая запись получала гриф 32767 — «выше всего», и её не видел
   никто, включая Офицера ИБ с высшим допуском. Теперь она получает высший уровень шкалы (4): запись журнала,
   которую нельзя прочитать, не выполняет ТБ-030. Прежние записи с 32767 читаются по п. 3.

## Ограничение режима (важно)

«Секретно», «Совершенно секретно» и «Особой важности» — степени **государственных секретов**. Шкала позволяет
пометить ими материал, но **обрабатывать такие сведения в системе можно только после её аттестации на
соответствующую степень** (защита информации, ТБ-063). Архитектура (ДОК-02) и модель угроз (ДОК-03) рассчитаны на
сведения **до ДСП включительно**. Пока аттестации нет, эксплуатант выдаёт допуски не выше ДСП; программное
ограничение «максимальный гриф обработки» в конфигурации — возможное развитие по решению Заказчика.

## Последствия

- Формы и карточки показывают названия уровней с пояснением в подсказке; цвет чипа растёт с уровнем.
- Отчёты документооборота и справки «Инспектора» маркируются названием уровня прописными.
- Допуск прежней шкалы 9 становится 4 — доступ не меняется, потому что данных выше 4 после миграции нет.
- Откат миграций данных невозможен: значения 5–9 не сохраняются (по смыслу они совпадают с 4).
