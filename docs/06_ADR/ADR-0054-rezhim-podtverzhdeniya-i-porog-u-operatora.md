## Контекст

Утверждённое ТЗ Заказчика [АИС ФТ-5.7.5, ПМИ 12–13] требует, чтобы совпадение по лицу подтверждал **один** оператор:
окно сличения «эталон ↔ кандидат» с процентом схожести и кнопки «Подтвердить связь в досье» / «Отклонить». У нас
сделано правило двух лиц (ADR-0022): эксперт, слепой верификатор, при расхождении — руководитель (ADR-0036). Заказчик
17.10.2026 решил: по умолчанию — один оператор, режим двух лиц остаётся и включается настройкой Администратора.

[АИС табл. 2.2 экран 9, табл. 7.1 № 8] требует ползунок порога схожести у оператора. Администратор задаёт рабочий
порог и нижнюю границу: по умолчанию 85 % и 70 %, допустимо 40–99 %. Сейчас по умолчанию порога нет вовсе (только
ранжирование), а предел ослабления задан в конфигурации расстоянием, не процентами.

Что значит «%». Индекс лиц считает косинусное расстояние, балл модели — косинусная схожесть шаблонов SFace (−1…1).
Экран до сих пор показывал «балл × 100». У SFace балл одного и того же человека часто ниже 0,85. Разработчики модели
(OpenCV, проверка на LFW) рекомендуют порог «тот же человек» — схожесть **0,363**. Порог 85 % как «балл × 100»
отсекал бы большую часть верных совпадений до калибровки на пилоте (ТО-мат-08). Заказчик 17.10.2026 выбрал шкалу
по порогу модели.

## Решение

### 1. Настройки пакета «Медиа» — в базе, у Администратора

- Таблица `media.setting` («ключ — значение», ключ — первичный), как `docflow.system_setting`. Причина та же: настройки
  меняет эксплуатант на работающей системе, без правки файла и перезапуска.
- Ключи:
  - `verification.mode` — `single-operator` | `two-person`;
  - `search.threshold-percent` — рабочий порог;
  - `search.min-threshold-percent` — нижняя граница.
- Порядок чтения: БД → конфигурация (`Media:Verification:Mode`, `Media:Search:ThresholdPercent`,
  `Media:Search:MinThresholdPercent`) → умолчание (**один оператор, 70 %, без нижней границы — 1 %**, v0.2). Мусор в строке приравнивается к
  «не задано». Если рабочий порог ниже границы (правка мимо экрана), действует граница: при сомнении — строже.
- Кеш — один на процесс, сбрасывается после записи. Новое значение действует со следующего поиска или решения.
- Проверка значений — в хранилище, а не только в форме: каждый порог от 1 до 99 % (v0.2; было 40–99 % по [АИС табл. 7.1
  № 8]), рабочий не ниже границы. Иначе отказ с пояснением.
- Экран `/media/settings` «Настройки поиска и верификации»: режим подтверждения, рабочий порог, нижняя граница, кто и
  когда менял последним.
- Право — новый метод порта `IMediaAdministration.CanManageSettingsAsync`. В «Следствии» это строка матрицы
  `media.settings`, **закреплённая за Администратором**: режим подтверждения и границы порога — правила безопасности
  поиска по лицу, и роль, которая этим поиском пользуется, не должна менять их сама.
- Каждое изменение — запись `Modify` в журнале с прежними и новыми значениями. Отказ без права тоже пишется.

### 2. Режим подтверждения — в правиле модуля, профиль его не ослабляет

- Режим (`ConfirmationMode`: один оператор = 1, два лица = 2) живёт в `TwoPersonRule` модуля «Медиа» (ADR-0022).
  Название класса сохранено: правило покрывает оба режима. Профиль по-прежнему отвечает только «кто вправе на стадии».
- **Режим разбора фиксируется первым решением.** Решение эксперта записывается с режимом, действующим в этот момент.
  Решения верификатора и руководителя копируют режим эксперта. Режим хранится в каждой строке
  `media.verification_decision` (колонка `confirmation_mode`; у существующих строк — «два лица»).
- **Смена режима ничего не пересчитывает.**
  - Подтверждённые, отклонённые и неопределённые кандидаты остаются как были.
  - Разбор, начатый вдвоём (статус «ждёт верификатора»), доводится по правилам двух лиц: верификатор, при
    расхождении — руководитель.
  - Кандидат без решений разбирается по режиму, действующему в момент первого решения.
  - Никакой процесс системы статус не меняет (ТБ-073, GATE-5).
- **Один оператор:**
  - Решение стадии эксперта (право «Верификация — подтверждение совпадения», по умолчанию Эксперт по лицам и
    Администратор) сразу даёт итог: «подтверждён» → «подтверждён», «отклонён» → «отклонён», «неопределённо» →
    «неопределённо», в очередь руководителя.
  - Вторая подпись не требуется. Стадия верификатора по такому кандидату отклоняется с пояснением и аудитом.
  - Руководитель решает «неопределённого» кандидата только третьим лицом (не оператор). «Подтверждён» ему доступен:
    в этом режиме статус даёт одно положительное решение человека с правом. «Отклонён» — всегда.
  - Обоснование, привязка к фигуранту при «подтверждён» (ТФ-ВЕР-03) и аудит — как раньше.
- **Два лица** — без изменений (ADR-0022, ADR-0036).
- Без решения человека статус «подтверждён» недостижим ни в одном режиме (GATE-5).

### 3. Появление с одной подписью

- `investigation.appearance.verifier_user_id` становится необязательным. В режиме одного оператора в появлении одна
  подпись: `ExpertUserId` — тот, кто подтвердил (оператор или руководитель по «неопределённому»), второй подписи нет.
- Проверка на границе профиля («эксперт ≠ верификатор») остаётся для появлений с двумя подписями.
- Отзыв (ADR-0034) — как раньше: отзывает не тот, кто подтверждал.
- Карточка фигуранта и справка показывают одну или две подписи.

### 4. Шкала процентов — по порогу модели, в одном месте

- `SimilarityScale` — кусочно-линейное соответствие «балл → %» по опорным точкам. Точки — в конфигурации
  `Media:Search:SimilarityScale`, по умолчанию `0.363:70`: к ним всегда добавляются концы 0 → 0 % и 1 → 100 %.
  Порог модели (0,363) = 70 %, полное совпадение = 100 %, ниже нуля — 0 %.
- Точки уточняются на пилоте (ТО-мат-08) без правки кода. Немонотонная или битая шкала **останавливает запуск**:
  молча подставленная шкала исказила бы порог, а это правило безопасности.
- Соответствие при шкале по умолчанию:

| % | Балл модели | Косинусное расстояние |
|---|---|---|
| 40 | 0,207 | 0,793 |
| 70 | 0,363 | 0,637 |
| 76 | 0,490 | 0,510 |
| 85 | 0,682 | 0,319 |
| 92 | 0,830 | 0,170 |
| 99 | 0,979 | 0,021 |

- Показ процента кандидата — **с округлением вниз**. Тогда «на экране не ниже порога» ⇔ «прошёл порог»: кандидат 84,7 %
  при пороге 85 % не показывается как «85 %».
- Шкалой пользуются все экраны и выгрузки: чип схожести, порог сессии, отборы очереди и сессии, карточка фигуранта,
  справка. Прежние сессии показывают свой порог по той же шкале: порог 0,5 прежнего автопредложения — «от 76 %».
- Проценты на экранах станут выше прежних «балл × 100». Это та же оценка в другой шкале; подсказка у чипа
  по-прежнему говорит, что это вероятностная оценка, а не установление личности (ТЭ-006).

### 5. Порог у оператора — ползунок, проверка на сервере

- `SearchByFaceQuery` принимает порог в процентах (`MinSimilarityPercent`) вместо расстояния.
- Сервер:
  - не задан → рабочий порог;
  - ниже границы (если Администратор её поднял) → поднимается до границы;
  - перевод в расстояние — по шкале, и не дальше предела эксплуатанта `Media:Search:MaxAllowedCosineDistance`;
  - кандидаты ниже порога в выдачу не попадают.
- Порог в процентах (и запрошенный, если его подняли до границы) пишется в журнал поиска (ТБ-072). Расстояние
  по-прежнему пишется в сессию.
- Без порога поиск больше не бывает. Ключ `Media:Search:MaxCosineDistance` удалён: его заменили настройки
  Администратора. У поиска по эталонам (ADR-0046) запасной порог больше не нужен.
- Страница поиска: ползунок на всей шкале 1–100 % (решение заказчика 17.10.2026), вся шкала доступна; по умолчанию —
  рабочий порог. Только если Администратор поднял нижнюю границу, часть ниже неё затенена и ползунок туда не заходит.
  Ползунок появляется после чтения настроек, поэтому браузер не подставляет прежнее положение из заранее отрисованной
  разметки. Предустановки (ТФ-ПЛ-06):
  - «низкий» — рабочий порог − 15 %, не ниже границы;
  - «средний» — рабочий порог;
  - «высокий» — рабочий порог + 15 %, не выше 99 %.
- Автопредложение (ADR-0035) идёт по своему порогу из конфигурации (0,5 ≈ 76 %), но не мягче нижней границы
  Администратора.
- Отборы очереди верификации и сессии — в процентах той же шкалы.

### 6. Окно сличения

- Карточка решения в режиме одного оператора — окно [АИС табл. 2.3]:
  - пара в равном масштабе и оригиналы (ТЭ-007), как раньше;
  - процент с предупреждением (ТЭ-006);
  - кнопки «Подтвердить связь в досье», «Отклонить», «Неопределённо»;
  - обязательное обоснование и фигурант при подтверждении.
- Тексты страниц про «двух сотрудников» показываются по действующему режиму.

## Изменения v0.2 (17.10.2026, решение заказчика)

После проверки экрана заказчик решил: «30–40 % тоже должны быть активны — какой порог пользователь выберет, по такому
пусть и ищет; по умолчанию — 70 %». Поэтому:
- Пределы настроек Администратора — 1–99 % вместо 40–99 % [АИС табл. 7.1 № 8]. Рабочий порог по умолчанию — 70 %
  (было 85 %). Нижняя граница по умолчанию — 1 %, то есть ограничения нет (было 70 %). Механизм границы сохранён:
  Администратор может её поднять, и тогда сервер не пустит порог ниже неё.
- Предел эксплуатанта `Media:Search:MaxAllowedCosineDistance` по умолчанию — 1,0 (было 0,8 ≈ 39 %). Иначе выбранные
  оператором 30 % молча превращались бы в 39 %.
- Предустановки — вокруг рабочего порога (±15 %): при 70 % — 55 / 70 / 85.
- Расхождение с утверждённым ТЗ [АИС] (пределы 40–99 %, «85 % и 70 %») записано в ТЗ_Следствие как решение заказчика.

## Последствия

- **Миграции** (накатывает заказчик):
  - `media`: таблица `setting`, колонка `verification_decision.confirmation_mode`, у существующих строк — 2;
  - `investigation`: `appearance.verifier_user_id` становится необязательным.
- После обновления действует **один оператор**. Чтобы сохранить прежний порядок, Администратор включает «два лица» на
  экране настроек или ключом `Media:Verification:Mode=two-person` до первого входа.
- **Поиск без порога больше не бывает.** По умолчанию отсечение 70 % (порог модели); оператор может выбрать любой порог
  1–100 % (v0.2).
- Проверки:
  - модульные — правило в обоих режимах и при смене режима, шкала, хранилище и команда настроек;
  - поиск — порог по умолчанию и подъём до границы;
  - интеграционный GATE-5 на Postgres — в обоих режимах;
  - bUnit — ползунок, экран настроек, окно сличения.
- Не сделано: калибровка точек шкалы — на пилоте (ЭС4, Evals КИ-05..07); ведомственный акт о порядке подтверждения —
  за Заказчиком (ПОДГ-09).
