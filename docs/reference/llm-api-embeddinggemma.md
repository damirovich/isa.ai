## 2. Эндпоинт `/v1/embeddings`

`POST /v1/embeddings` — единственный нужный. Тело: `input` (string ИЛИ array — батч), `model` (формально нужен OpenAI-клиентам, значение не важно). Ответ: `data[i].embedding` — массив из 768 float; при батче порядок сохраняется (`index`).

## 3. Префиксы задач — КРИТИЧНО для качества

EmbeddingGemma обучена с **task-специфичными префиксами**; **запрос и документ кодируются ПО-РАЗНОМУ** (асимметричное кодирование). **Без префиксов retrieval заметно хуже** — это самый частый источник «плохого поиска». Префиксы **не опциональны**.

Для RAG — два префикса:

| Что | Префикс |
|---|---|
| **Документ** (при индексации) | `title: none \| text: {текст_чанка}` (если есть заголовок — вместо `none`) |
| **Запрос** (при поиске) | `task: search result \| query: {вопрос}` |

Прочие задачи: `task: question answering \| query:`, `task: classification \| query:`, `task: clustering \| query:`, `task: sentence similarity \| query:` и т. д.

## 4. Нормализация, размерность, батчинг

- **L2-нормализация** включена → косинус = dot product; в pgvector оператор `<=>` (меньше = ближе), сходство ≈ `1 - <=>`.
- **Размерность 768** по умолчанию. Matryoshka (MRL) позволяет обрезать до 512/256/128 (меньше индекс, чуть хуже качество) — **после обрезки заново L2-нормализовать** и держать размерность колонки `vector(N)` в соответствии. На старте — **768, не усложнять**.
- **Батчинг:** `input` принимает массив — отдавать чанки пачкой (десятки–сотни) при индексации, это сильно быстрее.

## 5. Интеграция с pgvector

```sql
CREATE EXTENSION IF NOT EXISTS vector;
-- колонка vector(768); HNSW + косинус под нормализованные векторы
CREATE INDEX ... USING hnsw (embedding vector_cosine_ops);
SELECT ... ORDER BY embedding <=> $query LIMIT N;  -- $query = вектор запроса
```
В .NET — `Pgvector` + `NpgsqlDataSourceBuilder.UseVector()` (`float[]` ↔ `Pgvector.Vector`).

## 6. Эксплуатация

`GET /health` → `{"status":"ok"}`; `systemctl status|restart gemma-embed`; `journalctl -u gemma-embed -f`. Контекст 2048; `-ub 2048` обязателен (вся последовательность в один ubatch, иначе пулинг неверный). Q8_0 для эмбеддингов — нормально (потеря систематическая, на относительную близость почти не влияет).

### Префиксы — реализовано (Э4-09)
EmbeddingGemma требует **разные префиксы** для запроса и документа. Реализовано хелпером `EmbeddingTaskPrompt` (см. [задачу Э4-09](../tasks/Э4-09-префиксы-эмбеддингов.md)):
- **Ретривер** (`PgVectorRetriever`): запрос → `task: search result | query: {query}`.
- **Ingestion** (`IngestionPort`): каждый чанк → `title: none | text: {chunk}`.

> ⚠️ **Важно:** смена префиксов меняет векторы. **Корпус, загруженный ДО Э4-09, нужно переиндексировать** (перезагрузить документы), иначе старые эмбеддинги (без document-префикса) рассогласованы с запросами (с query-префиксом).

*Документ — справочный; при расхождении с реальной конфигурацией сервера приоритет у `/health` и фактического ответа `/v1/embeddings`.*
