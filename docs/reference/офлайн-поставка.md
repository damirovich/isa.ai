# Офлайн-поставка пакетов (ТБ-050/051, Э1-01)

Регламент контролируемого переноса NuGet-пакетов за периметр и офлайн-сборки в изолированном
контуре. Артефакты — в [deploy/offline/](../../deploy/offline/).

## Устройство

| Файл | Назначение |
|---|---|
| `nuget.config` (корень репозитория) | Дев-контур: единственный явный источник nuget.org, машинные источники отсечены |
| `deploy/offline/nuget.config` | Изолированный контур (ТБ-050): единственный источник — локальная папка `feed` |
| `deploy/offline/export-packages.ps1` | Сбор фида на машине с интернетом + манифест SHA256 |
| `deploy/offline/verify-packages.ps1` | Проверка целостности после переноса + запись в журнал (ТБ-051) |
| `deploy/offline/feed/` | Сам фид (.nupkg + `packages.sha256`) — в git НЕ хранится |
| `deploy/offline/transfer-log.txt` | Журнал переноса — живёт в контуре, в git НЕ хранится |
| `deploy/offline/export-tessdata.ps1` | Скачивание языковых файлов OCR (rus+kir) с проверкой пинов SHA256 + манифест |
| `deploy/offline/tessdata/` | Языковые файлы Tesseract (`*.traineddata` + `tessdata.sha256`) — в git НЕ хранятся |

Версии пакетов пинует ТОЛЬКО Central Package Management (`Directory.Packages.props`), поэтому
фид, собранный на дев-машине, гарантированно совпадает с тем, что требует сборка в контуре.

## Процедура переноса

**На машине с интернетом:**

```powershell
.\deploy\offline\export-packages.ps1
```

Скрипт делает полное восстановление решения в чистую папку, складывает все `.nupkg` плоско
в `deploy/offline/feed` и пишет манифест `packages.sha256` (SHA256 каждого пакета).

**Перенос:** папка `deploy/offline` переносится за периметр целиком (вместе с репозиторием
или дистрибутивом) по принятой процедуре переноса носителей.

**В изолированном контуре (сразу после переноса):**

```powershell
.\deploy\offline\verify-packages.ps1
```

Проверяются все хеши по манифесту; отклоняется и несовпавший, и отсутствующий, и **лишний**
(вне манифеста) пакет. Итог — строкой в `transfer-log.txt` (дата, число пакетов, кто, вердикт) —
это журнал переноса по ТБ-051. При отказе фид использовать нельзя — перенос повторяется.

## Офлайн-сборка

```powershell
dotnet restore ISC.AI.slnx --configfile deploy\offline\nuget.config
dotnet build ISC.AI.slnx --no-restore
```

Ключ `--configfile` заставляет NuGet видеть ТОЛЬКО контурный конфиг (иерархия конфигов
не применяется) — обращений к внешним источникам нет по построению.

## Языковые файлы OCR (ПОДГ-02)

Распознавание сканов (Tesseract) требует файлов `rus.traineddata`/`kir.traineddata` — в контуре
их взять неоткуда, переносятся тем же порядком, что и фид. На машине с интернетом:

```powershell
.\deploy\offline\export-tessdata.ps1
```

Скрипт скачивает файлы из официального репозитория tesseract-ocr/tessdata (Apache-2.0), сверяет
их SHA256 с пинами, зашитыми в скрипт (контроль подмены источника), и пишет манифест
`tessdata.sha256`. После переноса целостность проверяется по манифесту (`Get-FileHash`); путь к
каталогу указывается администратором в `Ocr:TessdataPath` конфигурации хоста.

## Границы регламента

- .NET SDK, веса моделей и `llama-server` переносятся тем же порядком (контроль целостности
  по контрольным суммам), но их комплектование — предмет дистрибутива (ТИ-001..003), не этого фида.
- `dotnet ef` (dotnet-tools.json) восстанавливается тем же `--configfile` при необходимости
  миграций в контуре: `dotnet tool restore --configfile deploy\offline\nuget.config`.
