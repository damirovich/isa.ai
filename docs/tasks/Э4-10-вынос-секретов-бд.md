## Проблема
В `src/core/ISC.AI.Web/appsettings.json` строки `ConnectionStrings:Core` и `ConnectionStrings:Inspector` содержат **plaintext-пароль БД** `Qwe123!@#`. Файл закоммичен → пароль в **истории git**. Design-time фабрики миграций тоже хардкодят пароль в fallback-строке. `UserSecretsId` в хосте не настроен.

## Цель
Убрать секреты подключения из репозитория; приложение и миграции берут пароль из защищённого источника.

## Что сделано (код)
- ✅ `UserSecretsId` в `ISC.AI.Web.csproj` уже был — user-secrets работает.
- ✅ Пароль вынесен в ОТДЕЛЬНЫЙ секрет `Database:Password` (user-secrets в dev / env `Database__Password` в проде). В `appsettings.json` осталась только несекретная топология (host/db/user), пароля нет.
- ✅ `ConnectionStringResolver` (в `ISC.AI.Persistence`) собирает строку: несекретная база + пароль-секрет (через `NpgsqlConnectionStringBuilder`). Использован в `AddCorePersistence` и `AddInspectorPersistence` (Inspector.Data ссылается на Persistence — допустимо).
- ✅ Design-time фабрики (`Core/InspectorDbContextDesignFactory`): fallback без пароля; для `database update` — полная строка в env `ISCAI_CORE_CONNECTION`/`ISCAI_INSPECTOR_CONNECTION`.
- ✅ `git grep Qwe123` в рабочем дереве — пусто; сборка 0/0; юнит 90/90.

## Как задать секрет
- **Dev (user-secrets):** `dotnet user-secrets set "Database:Password" "<пароль>" --project src/core/ISC.AI.Web`
- **Прод (env):** `Database__Password=<пароль>` (или полная строка в `ConnectionStrings__Core`/`__Inspector`).
- **Миграции (`database update`):** `ISCAI_CORE_CONNECTION` / `ISCAI_INSPECTOR_CONNECTION` = полная строка с паролем.

## Осталось (операционно — за оператором/владельцем режима)
- 🔴 **Ротация пароля учётки `postgres`**: пароль `Qwe123!@#` уже в истории git (и мог утечь) → СМЕНИТЬ на сервере БД. Это главное действие: чистка истории не «отзывает» уже раскрытый пароль.
- ⏳ **Чистка git-истории** (`git filter-repo`/BFG + force-push) — переписывает коммиты, согласовать с командой. Вторично после ротации.

## Критерии приёмки
- ✅ В рабочем дереве нет plaintext-пароля БД.
- ⏳ В истории — после чистки; пароль ротирован.
- ✅ Хост и миграции поднимаются, читая секрет из user-secrets/env.
