## Цель
Собрать **структурный объект «Нарушение»** и опоры под него (иерархия подразделений, 2-уровневый классификатор), плюс **детерминированную формулу риска**. На этом стоят модули Архив, Риски, Мониторинг, Дашборд. Всё — в схеме `inspector` (профиль); ИИ здесь НЕ считает, только тексты рекомендаций (позже).

## Модель (Приложение §4)
**`inspector.violation`** (заносится человеком):
| Поле | Тип/значения |
|---|---|
| division_id | ссылка на `inspector.division` (иерархия ТУ→РО) |
| category_id | ссылка на классификатор (2 уровня) |
| severity | 4 уровня: низкая/средняя/высокая/критическая |
| detected_at | дата выявления |
| source_doc_ref | RegNumber документа СКИД (по значению) |
| source_assignment_ref | id поручения СКИД (по значению, опц.) |
| remediation_status | устранено / на контроле / частично / просрочено |
| cause | текст (может быть ИИ-черновиком) |
| recommendation | текст (может быть ИИ-черновиком) |
| reference_doc_id | id справки-проверки (по значению) |
| is_recurring | производное (по category+division во времени) |

**`inspector.division`** — иерархия ТУ→РО (`parent_id`), сопоставление с плоским справочником СКИД по коду (§4.2).
**Классификатор видов** — 2 уровня (сфера → вид), расширяемый (ведёт администратор). Стартовый набор из прототипа (агентурная работа, АОД, документооборот, планирование, исполнение поручений, взаимодействие подразделений, работа по направлениям) — уточняемо, не блокирует.

## Формула риска (Приложение §2, детерминированная — код, не ИИ)
```
RiskScore(подразделение, период) =
    w1·Σ severity_weight(нарушение) + w2·RepeatCount + w3·OverdueRemediationCount + w4·TrendDelta
severity_weight: низкая=1, средняя=2, высокая=4, критическая=8
веса по умолчанию: w1=1.0, w2=1.5, w3=2.0, w4=1.0
уровни (пороги T1<T2<T3 калибруются на Э1): <T1 низкий, [T1,T2) средний, [T2,T3) высокий, ≥T3 критический
дашборд: 3 цвета (зелёный=низкий, жёлтый=средний, красный=высокий+критический)
```

## Шаги
- 🔄 **Шаг 1 — модель данных:** сущности `Violation`/`Division`/`ViolationCategory` + enum `Severity`/`RemediationStatus`, EF-конфиги, DbSet в `InspectorDbContext`, миграция.
- ⏳ **Шаг 2 — формула риска:** детерминированный `RiskScoreCalculator` (веса конфигом) + уровни/цвета + модульные тесты на эталонном наборе (воспроизводимо).
- ⏳ **Шаг 3 — связи по значению** с СКИД (source_doc_ref/assignment) — заглушки до интеграции; классификатор-справочник (стартовый набор).

## Критерии приёмки
- Нарушение создаётся с обязательными подразделением, видом и тяжестью; связь с СКИД — по значению (без FK через границу схем).
- На фиксированном наборе уровень риска **воспроизводим** и совпадает с формулой (модульный тест, §5.2.5.1).
