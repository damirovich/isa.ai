# ЭС3в-05 — Связь двух объектов через дело-посредник

**Профиль:** «Следствие» · **Ветка:** `feature/link-via-event` · **Дата:** 2026-10-17 · **Статус:** ✔ сделано
(ADR-0056)

## Что это

[АИС ФТ-5.2.1, 5.2.4–5.2.7, табл. 2.3, ПМИ 3–5]: модель «Объект — Дело — Объект». Сотрудник связывает два
существующих объекта (из разных заданий) через дело-посредник — событие (встреча, контакт, поездка) — с ролью,
транспортом, адресом контакта, **уровнем связи** «верно / предположительно / неверно» и отметкой «учитывать в общем
поиске». Сейчас связи живут внутри одного дела (фигурант-связь), а между делами — только автоматические пересечения.

## Требования

ТФ-ПЕР-11 (новое), ТФ-ПЕР-10 (граф), ТФ-ОТЧ-06, ТБ-073, ТБ-084, ТБ-030; Приложение В вопрос 26.

## Что сделать

- ADR: форма хранения события (умолчание вопроса 26 — событие на связи двух объектов, гриф не ниже грифов обоих,
  подразделение — того, кто заводит), видимость по ТБ-084, удаление и уничтожение дела (ADR-0025).
- Схема `investigation`: событие и участники (объект, роль, транспорт, адрес, уровень связи, «в общем поиске»);
  запрет связи объекта с самим собой [АИС табл. 7.1 № 3].
- Карточка объекта: блок «Связи через события», диалог связывания (выбор объекта в пределах допуска).
- Граф (ADR-0045): ребро «объект — событие — объект», выборка по событию — все участники [ФТ-5.2.5], «Как связан
  с…» через события, без зацикливания [ФТ-5.2.6/5.2.7].
- Аудит заведения, правки и удаления связи.

## Как проверяется

- Модульные: самосвязь — отказ; уровни связи; отметка «в общем поиске».
- Интеграционные: связь видна в обеих карточках; объект выше допуска не выбирается и не раскрывается (ТБ-084);
  цепочка 2-го порядка «Объект 2 → Дело 2 → Объект 3 → Дело 3 → Объект 4» [ПМИ 4]; кольцо без зависания [ПМИ 5].

## Что сделано (ADR-0056)

- Схема `investigation` (миграция `LinkEvents`): `link_event` — вид, название, дата, описание, гриф (не ниже грифов
  участников, поднимается при добавлении), подразделение (дела объекта, откуда заведено); `link_event_participant` —
  роль, уровень связи, отметка «в общем поиске», госномер и адрес контакта с нормализованными ключами, гриф фигуранта;
  ограничения таблиц (уровень, вид, непустое название, участник один раз); каскад с событием и с фигурантом.
- Видимость: событие — в пределах допуска и при доступном по роли участнике; чужой участник — номер, вид, статус дела и
  ведущий (ТБ-084); подразделение вне допуска и гриф выше допуска — никак.
- Карточка фигуранта: вкладка «События» — участие объекта, другие участники, «Связать через событие» (второй объект —
  поиск среди доступных; событие — новое или уже связанное с одним из двух), «Изменить», «Исключить…», «Граф».
  Самосвязь — «Ошибка топологии: объект не может иметь ребро связи на самого себя».
- Граф: узел «событие», ребро «участие» (роль, «предположительно»); граф с событием в центре `/events/{id}/graph`;
  «как связан с…» через события (ПМИ 4), кольца без зацикливания (ПМИ 5); «неверно» не рисуется.
- Единый поиск: вид «События»; пересечения «адрес» и «госномер» по местам контакта — только с отметкой и не внутри
  одного события; справка по фигуранту — раздел «События»; уничтожение дела удаляет опустевшие события.
- Тесты: валидаторы, команды, журнал, граф (событие, цепочка, кольцо), поиск, справка, bUnit вкладки и поиска; на
  Postgres — видимость и GATE-7, отказы, правка и исключение, места посещения, поиск, граф, уничтожение, ограничения.
