# Э4-34. Чат-ассистент с историей диалогов (грунтованный, многоходовый)

| | |
|---|---|
| Этап | Э4/Э5 — функциональные модули |
| Статус | 🔄 Фазы 1–2 готовы (ядро + интерфейс). Фаза 3 (документы через чат) и потоковый вывод — впереди |
| Требования ТЗ | ТО-мат-01 (RAG), ТБ-040/041 (грунтовка), ТБ-030 (аудит), ТБ-020 (доступ); закрывает пробел «многоходовый диалог» из архитектурной оценки |
| Решения заказчика | Режим чата — **грунтованный ассистент**; документы в чате — **загрузка + просмотр** (обе — под грифом/подразделением, с аудитом) |

## Замысел
Интерфейс общения как у ChatGPT: сохраняемая история всех чатов, контекст диалога, управление/загрузка
документов через чат. **ДВА режима** (переключатель в UI, по умолчанию свободный):
- **Свободный** — обычный ассистент (общение, помощь с формулировками/черновиками) БЕЗ извлечения НПА и БЕЗ
  грунтовки; системное правило запрещает конкретные юр-утверждения и ссылки «по памяти» (для них — предлагает
  грунтованный режим). Ответы помечены «не сверено с НПА», гриф 0. Генерация аудируется (ТБ-030).
- **Грунтованный (по НПА / документ)** — каждый ответ проходит извлечение с фильтром доступа → грунтовку
  (ссылки только из фрагментов, проверка валидатором) → аудит. Инвариант ТБ-040/041 не обходится.

## Фаза 1 — ГОТОВО (ядро, с тестами)
- **Модель данных** (схема `core`, доменно-нейтрально — переиспользуемо любым профилем): `ConversationEntity`
  (диалог, владелец-субъект, гриф, мягкое удаление) + `ConversationMessageEntity` (реплика: роль, текст, гриф,
  итог грунтовки в jsonb) + EF-конфигурации + миграция `AddConversations`.
- **Многоходовый контекст:** `GroundedRequest.History` (список `ChatTurn`); `GroundedGenerator` вставляет
  историю ПОСЛЕ системных правил и ДО текущего запроса. Инвариант не нарушён: грунтовка нового ответа — на
  СВЕЖИХ фрагментах текущего запроса (проверено тестом).
- **Хранилище** `IConversationStore`/`ConversationStore`: создание, добавление сообщения, история, список,
  переименование, мягкое удаление. **ВСЁ разграничено по владельцу** (fail-closed: чужой/несуществующий
  диалог = «не найден») — история содержит ДСП.
- **Оркестратор** `IChatService`/`ChatService`: грузит историю → грунтованная генерация с контекстом →
  сохраняет обе реплики. Без числового субъекта — отказ. Чужой диалог — отказ ДО обращения к модели.
- **DI** подключён (`AddCorePersistence` — хранилище, `AddCoreRag` — сервис чата).

### Проверка фазы 1
- Build 0 ошибок; юнит **181/181** (+5: оркестрация, многоходовость, fail-closed, разграничение).
- Интеграционный тест хранилища `ConversationStoreTests` (реальный Postgres: история по порядку, гриф=max,

## Фаза 2 — интерфейс как у ChatGPT — ГОТОВО (профиль)
- Страница `ChatAssistant.razor` (`Inspector.UI`, маршрут `/chat`, модуль в меню): боковая панель списка
  диалогов + «Новый чат» + переименование/удаление, лента сообщений (пузыри пользователь/ассистент),
  поле ввода + «Отправить», индикатор формирования ответа, плашка грифа и предупреждение GATE-2.
- Mediator-сценарии профиля `Inspector.Application/Chat` (`SendChatMessageCommand`, `ListConversationsQuery`,
  `GetConversationHistoryQuery`, `Rename`/`DeleteConversationCommand`) — каждый резолвит контекст доступа.
- **Проверено вживую** (dev-режим + реальный сервер модели): сквозной чат работает — грунтованный ответ со
  ссылками на фрагменты НПА, сохранение истории, автоопределение модели из `/v1/models`.
- ✅ **Потоковый вывод** (Э4-24 закрыт): `IChatService.SendStreamingAsync` + Mediator `IStreamRequest`
  (`SendChatMessageStreamCommand`) + Blazor `CreateStream` — черновик печатается по кускам, итог грунтовки в
  терминальном обновлении; поток отменяется при уходе со страницы (`IDisposable`, освобождает слот к серверу).
  Тест — `ChatServiceTests` (черновик по кускам → Final; сохранение реплик).
- ⏳ Полировка: автопрокрутка ленты вниз и Enter-to-send.

## Фаза 3 — документы через чат (загрузка + просмотр)
- Загрузка документа из чата с ОБЯЗАТЕЛЬНЫМ указанием грифа и подразделения (fail-closed, поверх существующего
  ingestion), аудит; просмотр списка/статуса загруженных документов.

## Границы / примечания
- Свободный (негрунтованный) чат сознательно НЕ делается — нарушил бы инвариант грунтовки; согласовано.
- Удаление/замена документов через чат — привилегированные операции (потребуют step-up ТБ-014, Э4-28) —
  вне первой версии.
- Сквозная работа с реальной моделью и корпусом — после поступления оборудования (калибровка Э1).
