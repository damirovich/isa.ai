## Цель
Ввести **сквозной архитектурный механизм**: интеллектуальные операции (индексация, генерация, анализ) выполняются как **фоновые задачи с очередью**. Пользователь отправляет запрос → получает статус → результат по готовности. Числовые нормативы времени ИИ **не задаются** (§5.1.3).

## Что сделать
- ✅ Контракты в `Abstractions.BackgroundTasks`: `IBackgroundTaskQueue`, `IBackgroundTaskStore`, `BackgroundTaskStatus` (Queued/Running/Completed/Failed), `BackgroundTaskInfo`.
- ✅ Очередь `ChannelBackgroundTaskQueue` (`System.Threading.Channels`) + `BackgroundTaskRunner` + `BackgroundTaskWorker : BackgroundService` — **в ядре** (`ISC.AI.AI`).
- ✅ **Управляемая деградация** (§5.1.3.3/§5.1.4.1): падение задачи → `Failed`, воркер и хост живы (try/catch на задачу).
- ✅ **БД-персист** (`core.background_task`) + `EfBackgroundTaskStore` + миграция `AddBackgroundTask` (снейк-кейс, uuid PK, индекс по статусу).
- ✅ **Восстановление** (§5.1.4.5): при старте воркера незавершённые (Queued/Running) → `Failed` «Прервано перезапуском».
- ✅ Тесты: юнит (жизненный цикл + деградация, без Docker) + интеграционный на Testcontainers (персист + восстановление осиротевших).
