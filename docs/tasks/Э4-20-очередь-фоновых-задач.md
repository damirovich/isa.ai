## Цель
Ввести **сквозной архитектурный механизм**: интеллектуальные операции (индексация, генерация, анализ) выполняются как **фоновые задачи с очередью**. Пользователь отправляет запрос → получает статус → результат по готовности. Числовые нормативы времени ИИ **не задаются** (§5.1.3).

## Что сделать
- ⏳ Контракт задачи + статусы (Queued/Running/Completed/Failed) в `Abstractions`.
- ⏳ Очередь на `System.Threading.Channels` + `BackgroundService`-воркер (хост).
- ⏳ **Управляемая деградация** (§5.1.3.3): при недоступности модели/эмбеддера интерактивная часть жива, задача в очереди/статус «ошибка», данные не теряются.
- ⏳ **Возобновление** (§5.1.4.5): незавершённые задачи после перезапуска возобновляются или помечаются ошибочными (персистентность статуса).
- ⏳ Тесты: жизненный цикл задачи; инъекция отказа модели → задача Failed, хост жив; возобновление после рестарта.

## Критерии приёмки
- Сбой фоновой задачи не роняет интерактивную часть; ошибка фиксируется и доступна для повтора (§5.1.4.1).
- Под нагрузкой очередь не теряет задачи (устойчивостный тест, §5.1.3.2).
