# Э4-14. Версионирование документов при загрузке — авто-замена v1 → v2 (P2)

| | |
|---|---|
| Этап | Э4 — MVP-доработка (P2), поверх готового механизма GATE-3 |
| Статус | ✅ Реализовано (явная замена по ID + миграция + UI + тесты; сборка 0/0, unit 58/58, integration 2/2). НПА-авто-замена по идентификатору — отдельным профиль-слоем |
| Требования ТЗ | ТО-инф (актуальность корпуса), GATE-3 (только действующие редакции); ADR-0013 |
| Источник | Проектное обсуждение (версионность документов) |
| Зависит от | Э4-02 (`IChunkCurrencyPort` + `IsCurrent` + материализатор редакций), Э4-01 (загрузка) |

## Проблема
Инвариант «ИИ получает только актуальную версию» **уже держится**: ретривер отдаёт только `IsCurrent = true` (GATE-3), устаревшее в модель не уходит. НО поток загрузки новой версии **не доведён**:
- В `DocumentEntity` нет понятия «версия/заменяет»; дедуп только по хешу содержимого.
- При загрузке **изменённого** файла (v2) создаётся **новый** документ, а старый (v1) остаётся `IsCurrent = true` → в ИИ пойдут **обе версии**.
- Механизм гашения годности (`IChunkCurrencyPort`) готов, но **триггер и связка «что кого заменяет» не подключены**.

## Цель
При загрузке новой версии документа автоматически **гасить прежнюю** так, чтобы в поиск/ИИ уходила только последняя версия, а прежняя сохранялась в истории.

## Что сделать
- ⏳ **Способ связки v2 ↔ v1** (решение оператора):
  - для НПА — по **стабильному идентификатору** нормы (`LegalNorm.Identifier`): новая редакция `Active`, прежняя `Repealed` (через `NormRevision` + материализатор);
  - для прочих документов — **явный выбор** заменяемого документа при загрузке.
- ⏳ На приёме v2: новые чанки `IsCurrent = true` → чанки заменяемого документа/редакции `IsCurrent = false` (через `IChunkCurrencyPort`), порядок hide-first.
- ⏳ Запись факта замены (supersession) в **аудит/историю** (кто, когда, что заменил).
- ⏳ UI загрузки: поле «новая версия документа …» (выбор/идентификатор).
- ⏳ Старая версия **остаётся в БД** (история + пометка «утратила силу»), не удаляется (кроме гарантированного удаления ДСП, ТБ-064).
- ⏳ Тесты: после v2 retrieval отдаёт только v2; v1 не `IsCurrent`; факт замены в аудите; v1 и v2 не бывают current одновременно.

## Критерии приёмки
- После загрузки v2 поиск и ИИ возвращают только v2; v1 помечена утратившей силу и в retrieval не попадает.
- Замена зафиксирована в неизменяемом журнале.

## Осталось / риски
- Ключ связки — за оператором (явный выбор) vs идентификатор (авто) — зафиксировать в UI.
- Неатомарность гашения старого и включения нового (как в Э4-02, осознанный hide-first).
- Откат (вернуть v1 как действующую) — обратная операция currency-порта; предусмотреть.
- Связано с Э4-02, Э4-01, инвариантом GATE-3, ADR-0013.

## Результат (реализовано)
- Реализована **явная замена по ID** (нейтрально для любого документа): при загрузке оператор указывает заменяемый документ.
- Контракт: `IngestionRequest.SupersedesDocumentId` → `FileIngestionRequest` → `IngestFileCommand` (проброс); `IngestionResult.SupersededDocumentId`/`SupersededChunkCount`.
- Ядро: [`IngestionPort`](../../src/core/ISC.AI.Ingestion/IngestionPort.cs) — проверка существования заменяемого (иначе отказ) + **hide-first гашение** чанков и эмбеддингов прежней версии **в той же транзакции** ingestion (атомарно); [`DocumentEntity.SupersededByDocumentId`](../../src/core/ISC.AI.Persistence/Entities/DocumentEntity.cs) + миграция `AddDocumentSupersededBy` (`core.document`).
- UI: [`CorpusLoad.razor`](../../src/profiles/inspector/ISC.AI.Profile.Inspector.UI/CorpusLoad.razor) — поле «Заменяет документ #» + отметка «заменил #N».
- Тесты: [`DocumentVersioningTests`](../../tests/ISC.AI.IntegrationTests/Persistence/DocumentVersioningTests.cs) (2 интеграционных, GATE) + проброс в [`LoadingHandlersTests`](../../tests/ISC.AI.UnitTests/Profiles/LoadingHandlersTests.cs). **Сборка 0/0; unit 58/58; integration 2/2.**
- ⚠️ Накатить миграцию на свою БД: `dotnet ef database update --context CoreDbContext`.
- Не вошло (отдельными задачами): НПА-авто-замена по идентификатору нормы — профиль-слой поверх этого механизма (Э4-02, наполнение домена редакций); аудит-событие замены — с Э4-11.
