# Э5-02 · Картотека НПА (реестр норм с редакциями)

| | |
|---|---|
| Требования | ТФ-НПА-02 (актуальность НПА), ТО-инф-04/06, ТБ-020/021, GATE-3; опирается на Э4-02 |
| Ветка | `feature/npa-registry` |
| Статус | ✅ ГОТОВО (2026-08-10), прошло состязательное ревью (16 подтверждённых находок исправлено) |

## Зачем

Механика актуальности НПА (Э4-02: статус редакции → гашение `core.chunk.IsCurrent` → поиск и
грунтовка перестают выдавать устаревшее) была построена и покрыта Gate-тестами, но **мертва**:
таблицы `legal_norm`/`norm_revision`/`norm_document_link`/`chunk_revision_link` не наполнял ни один
продакшн-код, команда смены статуса не вызывалась ни с одного экрана — и всегда затрагивала 0 чанков.
Картотека — ручное ведение, которое делает GATE-3 рабочим на живых данных.

## Что сделано

- **Домен:** порт `INormRegistryStore` + контракты `NormRegistryContracts` (реестр, карточка,
  редакции, кандидаты корпуса, итоги операций); подписи статуса `RevisionStatusLabels`.
- **Данные:** `NormRegistryStore` над двумя контекстами (inspector + core, слабые ссылки по
  значению, ТО-инф-06). Миграции: `NormIdentifierUnique` (номер НПА уникален — на него ссылается
  грунтовка), `NormLinkUniqueness` (уникальные связки — гонка привязки не задваивает данные).
- **Сценарии** (`Features/Norms`, все команды — гард `NormGuard` по `AdministrationRule` + аудит):
  ListNorms/GetNorm/SearchCorpusDocuments (запросы), CreateNorm/UpdateNorm/AddNormRevision/
  LinkNormDocument (команды). `SetRevisionStatusCommand` переехал из `Features/Revisions` и получил
  гард+аудит — закрыта «дыра-прецедент» (любой вошедший мог менять выдачу для всех без следа
  в журнале).
- **Экраны:** `/norms` — реестр (создание, отбор по тексту/действию, серверная пагинация),
  `/norms/{id}` — карточка (правка реквизитов, редакции со статусами и датами, привязка документов
  корпуса, смена статуса с показом числа затронутых чанков). Пункт меню «Картотека НПА».

## Режимные решения (закреплены ревью)

1. **Привязка никогда не поднимает видимость чанков — только гасит.** Привязка документа
   к утратившей силу редакции скрывает его чанки немедленно (hide-first, до записи связок);
   поднятие — только явной сменой статуса с ограждениями материализатора.
2. **Ограждения материализатора:** поднятие (Active) не воскрешает документы, погашенные заменой
   на уровне корпуса (supersede, Э4-14); гашение (Repealed) не прячет чанки, действующие по другой
   редакции (общий документ двух норм). Оба — в сторону «скрыть надёжнее, чем показать».
3. **Решётка допуска на реквизиты корпуса (ТБ-020/021):** кандидаты на привязку — только документы
   в пределах допуска субъекта (фильтр в запросе); в карточке заголовок/тип/гриф документа вне
   допуска не отдаются — только «документ №N» (факт связки живёт в профиле и не грифован).
4. **Диалог кандидатов — под гардом ведения:** первое ревью нашло утечку (заголовки и грифы всех
   документов корпуса любому вошедшему) — закрыто гардом + решёткой.
5. **Дубли невозможны на уровне БД:** уникальные индексы на номер нормы и обе связки; гонки
   (двойной клик, два оператора) ловятся по `23505` и отвечают «уже есть», прочие сбои БД
   не маскируются под дубль.
6. **Документ без чанков и погашенный заменой не привязываются** (мёртвая связка ничего не даёт,
   отвязки в картотеке нет); `RepealedDate` проставляется материализатором при гашении.
7. **Документы документооборота не привязываются и не предлагаются** (вопрос заказчика): в корпусе
   они лежат рядом с НПА, но поручение или письмо — делопроизводство, а не редакция закона, и утрата
   силы нормы не должна прятать их из поиска. Отсечка по `core.document.source = CorpusSources.DocFlow`
   (константа в Abstractions — её пишет модуль, читает профиль; друг на друга ссылаться не могут)
   и в диалоге кандидатов, и в самой команде привязки (мимо диалога не обойти).

## Подразделение при наполнении корпуса — из справочника (2026-08-19)

Выявлено при первой проверке картотеки заказчиком: «Найти в корпусе» не находил ни одного из 111 НПА.
Причина — пакет ЦБД был собран сборщиком (вне контура) с подразделением 10, которого в справочнике
нет; решётка допуска отсекала эти документы у КАЖДОГО пользователя — ни поиск, ни чат, ни картотека
их не видели. Сборщик справочника видеть не может (вне контура — иначе дыра в контур), поэтому
решение перенесено внутрь:

- **Экран «Загрузка корпуса»:** подразделение — выпадающий список действующих подразделений
  справочника вместо числа; и для файлов, и для пакета. Для пакета выбранное подразделение
  ПЕРЕКРЫВАЕТ записанное в манифесте (`IBundleImporter.ImportAsync(path, divisionId)`).
- **Команды `IngestFileCommand` / `ImportBundleCommand`:** проверка `DivisionRule` —
  подразделение должно быть ДЕЙСТВУЮЩИМ в справочнике (`IDivisionAdminStore.ExistsActiveAsync`),
  иначе отказ с понятным текстом ДО обращения к порту. Проверка в профиле, не в ядре: ядро
  справочника не знает (ADR-0013), ему подразделение — число в решётке.
- **Сборщик Harvester:** поле «Подразделение (DivisionId)» УБРАНО из формы и `SourceConfig`; коннекторы
  пишут в пакет пустое подразделение. Без явного выбора при импорте такой пакет не загрузится даже
  старым путём (fail-closed, ТБ-024). Формат пакета (`HarvestedDocument.DivisionId`) сохранён — старые
  пакеты читаются, их подразделение перекрывается выбором оператора.
- **Данные заказчика:** 100 НПА перенесены с «10» на «Главную инспекцию» (1) SQL-командами
  (document + chunk — поле денормализовано на чанках).
- Проверено: юнит +2 (отказ на призрак для файла и пакета, перекрытие подразделения доезжает
  до импортёра).

## Каталог корпуса НПА — вид «как в ЦБД» (2026-08-19)

По просьбе заказчика (скриншот реестра ЦБД Минюста): «База НПА» (`/npa`) теперь — два инструмента
на одном экране. Сверху — прежний поиск по смыслу (ретривер, GATE-1/3). Ниже — **каталог документов
корпуса**: `MudTable` в стиле остальных реестров с галочкой/крестиком действия, отбором по тексту/виду
акта/статусу, сортировкой (дата, название, загрузка), серверной пагинацией; клик — карточка
`/npa/documents/{id}` с реквизитами, статусом, текстом по фрагментам (утратившие силу помечены),
преемником и нормами картотеки.

- **Домен:** `ICorpusCatalog` + `CorpusCatalogContracts` (статусы `Current/Superseded/Mixed/NoText`).
- **Данные:** `CorpusCatalog` над `core` (+ связки картотеки из `inspector` вторым контекстом).
  Решётка допуска в запросе (ТБ-020/021): гриф ≤ допуска И подразделение ∈ разрешённых —
  тот же floor, что у ретривера; документооборот исключён (у него свой реестр). Статус действия —
  ТОЛЬКО то, что знает система: флаг годности чанков (картотека / гашение при замене версии).
- **Сценарии:** `Features/Catalog` — `ListCorpusDocumentsQuery` (Search), `GetCorpusDocumentQuery`
  (View); `AuditClassification` не переопределён намеренно — выдача возможна только при
  допуск ≥ гриф, запись журнала по допуску не ниже грифа данных (как у `GetDocumentQuery` docflow).
- **Дата документа:** пакеты ЦБД даты не несут — `TitleDateParser` (ядро, нейтрально) берёт её из
  заголовка («от 28 октября 2021 года») при импорте; не распознана — пусто, не отказ.

**Ревью (17 подтверждённых находок) — исправлено:** (1) хит поиска по смыслу из документа
документооборота вёл в каталог НПА, где его нет намеренно, — тупик; теперь `NpaHit.DocFlowDocumentId`
из метаданных (как у источников чата) и такие хиты ведут в карточку документооборота; (2) статус
«без чанков» расходился между отображением и фильтром, заменённый документ без чанков показывался
«действующим» — одна семантика в проекции и SQL-фильтре, новое честное состояние `NoText`,
`SupersededByDocumentId` = утратил силу; (3) ссылка на преемника выдавала существование документа
вне допуска — преемник отдаётся только если сам виден субъекту; (4) сброс ошибки/списка при
перезагрузке, сброс карточки при переходе на преемника, «не найден» не показывается поверх ошибки;
(5) дата из заголовка (без неё сортировка «по дате» была бессмысленна на реальном корпусе ЦБД).
Принято как общий паттерн проекта (не чинилось здесь): двойная загрузка при предрендере (две
записи аудита на открытие — у всех страниц, решать централизованно); карточка рендерит все
фрагменты разом (для кодексов на 1000+ фрагментов — виртуализация, по потребности).

## Качество текста НПА: структура при сборе, нарезка по статьям, карточка как документ (2026-08-19)

Заказчик показал карточку кодекса: фрагменты рвались посреди слова («…бюджет Кыргызско» / «й Республики…»),
слова на стыках абзацев склеены («бюджетеКыргызской», «ЖогоркуКенеш»), таблицы — каша из `|||`.
Причина — цепочка из трёх дефектов, все исправлены:

1. **Сборщик терял структуру.** `HtmlContentExtractor` брал `Body.TextContent` и схлопывал всё
   в одну строку. Теперь обход дерева: блочные элементы (абзацы, заголовки, строки таблиц, пункты
   списков) → переносы, абзацы разделены ровно одной пустой строкой (граница для чанкеров,
   ТО-мат-03), ячейки таблиц — ` | `, `&nbsp;` → пробел. `ConfigurableSiteConnector` — тем же
   структурным обходом (`HtmlContentExtractor.StructuredText`). Тесты: абзацы/статьи отдельными
   строками, стыки не склеиваются, таблица построчно, `<br>`/`<li>`.
2. **Чанкер НПА не видел заголовков и резал слепо.** `NpaStructuralChunker`: заголовок «Статья N.» /
   «Глава II» / «Раздел 3» распознаётся и В НАЧАЛЕ строки, и ВНУТРИ (старые пакеты одной строкой);
   ссылка «в статье 3 настоящего Закона» (строчная, без точки) заголовком не считается; римские
   номера; длинный абзац режется по концу предложения → по пробелу → только для слова длиннее окна
   по длине (раньше — `Substring` по 1800 символов посреди слова). Тесты: inline-заголовки, ссылка
   не рвёт, римские главы, длинный абзац — каждый кусок от заглавной до точки, текст без потерь.
3. **Карточка показывала рамки вместо документа.** `/npa/documents/{id}`: текст сплошь, заголовки
   глав/статей выделены, абзацы с отступом, номер фрагмента — мелкая пометка; утративший силу
   фрагмент приглушён и помечен.

**Данные заказчика:** уже загруженные 100 НПА собраны СТАРЫМ сборщиком — их текст в пакете
испорчен, ядро его не починит. Нужен повторный сбор пакета новым Harvester и импорт (дедуп по
хешу НЕ сработает — текст другой; старые документы следует заменить: при импорте указать прежнюю
версию или удалить старые). Дата теперь берётся из заголовка при импорте.

## Проверено

- Юнит 269/269 (гард смены статуса: Администратор — делегирует, не-Администратор — отказ без
  вызова материализатора; валидаторы полей).
- Интеграционные (живой Postgres): полный цикл — создание (дубль номера — отказ), реестр

  привязанные чанки + дата утраты; отдельный сценарий hide-first — привязка к уже погашенной
  редакции гасит чанки сразу.
