# Э5-10 — Остатки функционального ТЗ: ТФ-АРХ-03, ТФ-МЕТ-02, ТФ-РСК-02

**Ветка:** `feature/tz-leftovers` · **Дата:** 2026-08-25 · **Статус:** готово

## Что это

Три последних незакрытых функциональных требования ТЗ — одной волной, все по устоявшемуся
паттерну «числа считает код (факт-блок), ИИ пишет только текст»:

- **ТФ-АРХ-03 — ИИ-аналитика архива** (кнопка на странице «Архив»): тренды (текущий период
  против предыдущего той же длины — сводка спрашивается ДВАЖДЫ), повторяемость (повтор = то же
  подразделение и тот же вид), сравнение территориальных и линейных подразделений. Роль —
  вдумчивая Analysis: интерпретация закономерностей, не пересказ цифр. Промпту запрещено
  «натягивать» выводы — закономерность только из приведённых чисел.
- **ТФ-МЕТ-02 — план работы / дорожная карта** (вкладка «План работы» в «Методиках»): проект
  плана из проблемных зон живого учёта (факт-блок общий с отчётом руководству). Календарные
  сроки и ответственных ИИ не назначает — «в срок до ______». Сохраняется в реестр методик
  видом «План работы».
- **ТФ-РСК-02 — правила и критерии оценки** (вкладка «Правила контроля» в «Рисках»): проект
  положения из показателей, которые система РЕАЛЬНО считает (`ControlRulesFacts` — перечень
  зашит кодом рядом с расчётом), пороги ИИ не назначает — «порог: ______». Сохраняется в реестр
  методик видом «Правила контроля».

## Предпосылка: тип подразделения

Для сравнения «территориальные/линейные» в модели не было типа — добавлен `DivisionKind`
(Territorial/Linear): поле в `Division` (миграция `AddDivisionKind`, существующие записи —
территориальные), `DivisionNode.Kind`, тип в формах справочника «Подразделения» (создание
и правка, колонка-чип). Непомеченные линейные — факт-блок честно объявляет сравнение
невозможным, а не выдумывает вторую группу.

## Судьба результатов

Как у всех ИИ-документов: лист с гербом, экспорт .docx (ТБ-033), «Доработать в Редакторе»;
аналитика архива — регистрация в документообороте (Origin «Архив», GATE-2-гейт), план и правила —
реестр методик (утверждение Руководителем, Ц-03). Всё — проекты (ТБ-042).

## Устройство

- Шаблоны `archive-analytics.scriban`, `work-plan.scriban`, `control-rules.scriban`.
- `GenerateArchiveAnalyticsCommand(PeriodDays)` (роль Analysis, +IDivisionAdminStore для типов),
  `GenerateWorkPlanCommand(PeriodDays)` и `GenerateControlRulesCommand(PeriodDays)` (роль Draft) —
  все `IGroundedScenario`, guard пустого ответа, аудит пишет оркестратор ядра.
- Факт-строители: `ArchiveAnalyticsFacts` (два периода + разрез типов), `ControlRulesFacts`
  (показатели+процедуры+картина), план — переиспользует `ManagementReportFacts`.
- Тесты: `ArchiveAnalyticsTests` (тренд из двух точек, честность при непомеченных линейных,
  роль Analysis, два вызова сводки), `WorkPlanTests`, `ControlRulesTests` — настоящие шаблоны,
  роли, факт-блоки в промпте, HITL.
