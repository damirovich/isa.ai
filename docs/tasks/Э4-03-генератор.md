## Цель
Реализовать первый сквозной генерирующий сценарий: один тип документа (справка ИЛИ проект приказа) на основе ввода инспектора и извлечённых норм.

## Что сделать
- ✅ Use-case в `*.Application` профиля (команда Mediator `GenerateReferenceCommand` + handler) + промпт-файл Scriban (`reference.scriban`, не хардкод).
- ✅ Генерация через RAG-оркестратор ядра (`IGroundedGenerator` → модель + грунтовка ТБ-040 + аудит).
- ✅ Результат помечен как проект, требующий проверки человеком (HITL, ТБ-042/ТЭ-002).
- ✅ Страница модуля «Генератор» в `*.UI` (MudBlazor) + регистрация в реестре модулей.
- ⏳ Живой прогон через модель (llama-server) + загруженный корпус — приёмочная проверка.

## Критерии приёмки
- Документ формируется со ссылками, прошедшими грунтовку; непроверенные — маркированы; действие — в аудите.

## Результат
Первый сквозной генерирующий сценарий профиля (тип документа — **справка**):
- [`GenerateReferenceCommand` (+вложенный `Handler`)](../../src/profiles/inspector/ISC.AI.Profile.Inspector.Application/Features/Generation/Commands/GenerateReference/GenerateReferenceCommand.cs): контекст доступа → задачный промпт (Scriban) → `IGroundedGenerator` (извлечение с фильтром доступа → модель → грунтовка → аудит) → результат с HITL и наследованием грифа.
- Промпт — файл [`reference.scriban`](../../src/profiles/inspector/ISC.AI.Profile.Inspector.Application/Generation/Prompts/reference.scriban) (встроенный ресурс), системное правило грунтовки добавляет ядро (ТБ-041) — профиль его не ослабляет.
- UI [`Generator.razor`](../../src/profiles/inspector/ISC.AI.Profile.Inspector.UI/Pages/Generator.razor): ввод темы → черновик + баннер «ЧЕРНОВИК (HITL)» + ссылки с пометками грунтовки (подтверждена / не подтверждена / УТРАТИЛА СИЛУ) + предупреждение GATE-2, если не все подтверждены. Модуль зарегистрирован в реестре.
- Тест [`GenerateReferenceHandlerTests`](../../tests/ISC.AI.UnitTests/Profiles/GenerateReferenceHandlerTests.cs). Сборка 0/0; unit 32/32.
