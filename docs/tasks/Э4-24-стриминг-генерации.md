## Проблема

RAG-оркестратор (`GroundedGenerator`) вызывал блокирующий `IChatClient.GetResponseAsync` — ответ модели
появлялся у пользователя ЦЕЛИКОМ, после полного ожидания. На локальных моделях (llama-server) генерация
длинной справки — это десятки секунд «пустого экрана». Doc-комментарий в `CoreAiModelsServiceCollectionExtensions`
при этом сам утверждал про стриминг, а конвейер его не делал — расхождение кода с заявленным.

## Инвариант, который нельзя нарушить

Грунтовка (ТБ-040, GATE-2): ссылки берутся ТОЛЬКО из извлечённых фрагментов, вывод проверяется против них.
Наивный стриминг «показать токены как готовый ответ» нарушил бы это — пользователь видел бы НЕпроверенный
текст как результат. Поэтому стриминг сделан так, чтобы грунтовка оставалась гейтом.

## Что сделано (ядро)

- ✅ `IGroundedGenerator.GenerateStreamingAsync` → `IAsyncEnumerable<GroundedStreamUpdate>`.
- ✅ `GroundedStreamUpdate` (`Abstractions/Rag`): либо `TextDelta` (кусок черновика), либо `Final` (итог с
  грунтовкой). Ровно одно терминальное обновление с `Final` завершает поток.
- ✅ `GroundedGenerator.GenerateStreamingAsync`: тот же порядок инвариантов — фильтр доступа ДО модели
  (ТБ-020) → тот же промпт (грунтовка ПЕРВОЙ, ТБ-041) → стриминг СЫРОГО черновика по токенам, параллельно
  сборка полного текста → **грунтовка на СОБРАННОМ полном тексте** (ТБ-040) → аудит (ТБ-030) → `Final`.
- ✅ Промежуточные токены = непроверенный черновик; вердикт грунтовки и подтверждённые ссылки — ТОЛЬКО в
  `Final`. Согласуется с HITL (результат всегда черновик под проверку, ТБ-042).
- ✅ Блокирующий `GenerateAsync` сохранён без изменений поведения (`GenerateReferenceCommand` работает как
  раньше); общий «хвост» (грунтовка + наследование грифа + единственный аудит) вынесен в `FinalizeAsync` —
  блокирующий и потоковый пути не расходятся.
- ✅ Тест `GroundedGeneratorTests`: черновик отдаётся по токенам; грунтовка вызвана на полном собранном
  тексте (а не на отдельном токене) — ключевая проверка инварианта; итоговый гриф и единственная запись
  аудита с субъектом.

## Что осталось (почему статус ⚙️, а не ✅)

- ⏳ Подключить стриминг в сценарий генерации: `GenerateReferenceCommand` (или отдельный стриминговый
  сценарий) → отдавать `IAsyncEnumerable` в UI; Blazor-страница рендерит черновик по мере поступления и
  показывает подтверждённые ссылки/гриф ТОЛЬКО по приходу `Final`, с явной пометкой «черновик, идёт
  проверка» на промежуточном тексте.
- ⏳ Учесть сквозные pipeline-поведения (аудит/грунтовка-страховка) для стримингового пути — сейчас
  аудит пишет сам `GroundedGenerator`, но `IAuditableRequest`/`GroundingBehavior` рассчитаны на
  request→response; для `IAsyncEnumerable`-сценария нужна отдельная проверка, что страховки применимы.

## Критерии приёмки

- ✅ Ядро отдаёт ответ потоково через `IAsyncEnumerable` (конвенция CLAUDE.md).
- ✅ Грунтовка выполняется на полном тексте, а не на токенах; вердикт — только в терминальном обновлении.
- ✅ Блокирующий путь не сломан; дублирования «хвоста» нет.
- ✅ Build 0 ошибок; юнит 124/124.
- ⏳ Виден потоковый вывод в UI — отдельный шаг (команда/страница), см. выше.
