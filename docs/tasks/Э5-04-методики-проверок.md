# Э5-04 — Методики проверок (§5.2.9, ТФ-МЕТ-01)

**Ветка:** `feature/inspection-methods` · **Дата:** 2026-08-24 · **Статус:** готово (P1-объём)

## Что это

Генерация методических документов по типу и объекту проверки (ТФ-МЕТ-01): **программа проверки,
чек-лист, инструкция, памятка, учебный материал**. Планы работы и дорожные карты (ТФ-МЕТ-02) — P2,
не входят.

Второй генерирующий сценарий на конвейере Генератора (Э4-03) — ядро и грунтовка не трогались:
извлечение норм по допуску (ТБ-020) → модель → грунтовка ссылок (ТБ-040, GATE-2) → черновик для
проверки человеком (HITL, ТБ-042) → экспорт .docx с грифом (ТБ-033, общий `ExportReferenceCommand`).

## Устройство

- **Шаблон** `Generation/Prompts/method.scriban` (встроенный ресурс, подхватывается wildcard-ом
  csproj): заголовочный комментарий по ТД-006 §7.2; параметры `artifact_kind` / `inspection_type` /
  `scope` / `extra`; требования структуры (цель и основания → нумерованный чек-лист → порядок
  проведения), опора ИСКЛЮЧИТЕЛЬНО на фрагменты.
- **Рендерер** `IMethodPromptRenderer`/`ScribanMethodPromptRenderer` (ключ «method» через
  нейтральный `IPromptProvider`); DI — `AddInspectorApplication`.
- **Команда** `GenerateMethodDocumentCommand` (`IGroundedScenario`, НЕ `IAuditableRequest` — аудит
  генерации пишет оркестратор ядра): Query для извлечения — тип+объект+указания; конверт результата
  общий с Генератором (`GenerateReferenceResult`). Валидатор: вид/тип/объект обязательны,
  пределы 100/200/300/2000.
- **UI** `/methods`: чипы вида документа (5) и типа проверки (4), объект — подразделение из живого
  справочника (§4.2) и/или направление текстом, доп. указания; результат — блок как в Генераторе
  (HITL-плашка, гриф, метки грунтовки по каждой ссылке, экспорт .docx). Демо-витрина снята,
  демо-наборы Programs/Materials/Checklists удалены из `InspectorDemoData` (остались Анализ и
  правила контроля Рисков).

## Починено попутно

Пример заголовка шаблона в `docs/10_Стандарт_кодирования.md` §7.2 использовал Jinja-синтаксис
`{# … #}`, который Scriban комментарием НЕ считает — такой заголовок уходил в текст промпта модели.
Пример исправлен на Scriban `{{ ## … ## }}` с пояснением; шаблон «method» использует рабочий синтаксис
(закреплено тестом: заголовок в рендер не попадает).

## Тесты

`MethodGenerationTests` (юнит): настоящий шаблон «method» встроен и рендерит все параметры,
заголовок-комментарий и пустые доп. указания в промпт не попадают; handler отдаёт оркестратору
тему извлечения и задачный промпт, результат всегда HITL; валидатор требует объект проверки.

## Реестр методик (добавлен тем же днём, решение заказчика)

Сформированные методики СОХРАНЯЮТСЯ (Ц-03 «институциональная память»): таблица
`inspector.method_document` (миграция `AddMethodRegistry`), вкладка «Реестр методик» на `/methods`
(фильтры вид/статус/поиск, карточка с правкой текста, утверждением и экспортом).

- **Жизненный цикл:** сохранённое — всегда черновик (ТБ-042); утверждают Руководитель/Администратор
  (`MethodRegistryGuard.CanManage`); правка текста возвращает утверждённую в черновики (утверждение
  относится к редакции); удаляется только черновик. Сохраняют Инспектор/Руководитель/Администратор.
- **РЕЖИМ:** методика наследует гриф генерации (max грифов фрагментов); все выборки и правки реестра
  фильтруются по допуску субъекта В ЗАПРОСЕ — методика выше допуска неотличима от несуществующей
  (ТБ-020-стиль). Запись аудита сохранения классифицируется грифом методики (ТБ-032).
- Метки грунтовки сохраняются JSON-ом и показываются в карточке «на момент сохранения»;
  имена «кто сохранил/утвердил» — из реестра пользователей ядра (склейка в памяти, ТО-инф-06).
- Тесты: `MethodRegistryTests` (решётка по грифу — недоступная не выдаётся и не правится; правка
  возвращает в черновики; удаляется только черновик), `MethodRegistryHandlersTests` (гарды).

## Не входит (по потребности)

- ИИ-доработка сохранённого текста («переформулируй строже») — это модуль «Редактор» (ТФ-РЕД-02).
- История редакций методики (сейчас хранится последняя).
- ТФ-МЕТ-02 (планы работы, дорожные карты) — P2.
