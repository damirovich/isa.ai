# Э4-17. Харвестер: масштабный сбор (170К+) — стриминг, фон, троттлинг, монитор

| | |
|---|---|
| Этап | Э4 — сборщик корпуса (вне контура) |
| Статус | ✅ Реализовано (троттлинг+429, стриминг-шарды, фоновый runner, возобновление, импортёр шардов, UI-монитор; сборка 0/0, unit 64/64) |
| Требования ТЗ | ПОДГ-02 (первичная загрузка корпуса), ТНД-002 (идемпотентность), ТО-инф-07 |
| Источник | Реальный объём ЦБД — ~170 000 действующих НПА |
| Зависит от | Э4-16 (API-коннектор ЦБД), Э4-08 (движок, пакет) |

## Контекст
Реальный корпус — сотни тысяч документов. Прежняя схема «собрать всё в память → один `manifest.json` → выгрузить» на 170К **не работает**: ~3-4 ГБ в памяти Blazor, гигабайтный манифест, 170К запросов к API (часы + 429). Нужен потоковый, фоновый, устойчивый сбор.

## Что сделать
- ⏳ **Троттлинг + ретрай 429**: `ResilientHttpHandler` (мин. интервал между запросами + повтор с backoff на 429/5xx, учёт `Retry-After`) на HttpClient коннектора.
- ⏳ **Стриминг в шардированный пакет**: `IStreamingBundleWriter` — `Begin` → `Append` (ролл шардов, напр. 2000/файл) → `Complete` (manifest.json = индекс шардов + total). Память ограничена размером шарда.
- ⏳ **Фоновый `HarvestRunner`**: запуск сбора в фоне, стрим в пакет, **лёгкие строки** (заголовок/url/статус/длина, без текста) для UI, прогресс+счётчик, **Стоп**, чекпоинт последней страницы для **возобновления**.
- ⏳ **Возобновление коннектора**: `SourceConfig.StartPage` + старт пагинации с неё.
- ⏳ **Импортёр шардов** (контур): `BundleImporter` читает индекс-манифест → по шардам; обратная совместимость с одиночным массивом.
- ⏳ **UI-монитор**: старт/стоп, прогресс, `MudTable` с пагинацией+поиском по лёгким строкам, чип статуса, подсветка коротких, просмотр текста по требованию (из шарда), статистика, путь пакета.

## Критерии приёмки
- Сбор десятков/сотен тысяч документов не переполняет память (стрим + шарды).
- Прогресс виден, «Стоп» останавливает, «Продолжить» дописывает с чекпоинта.
- 429 не роняет сбор (ретрай). Пакет импортируется в контур пошардно.

## Осталово / риски
- «Всего» действующих неизвестно заранее (клиентский фильтр) → прогресс как счётчик+скорость, без жёсткого ETA.
- Курирование per-doc на 170К непрактично → таблица = мониторинг + spot-check; фильтрация на источнике (только действующие).
- Полный прогон 170К — часы; фоновая задача, переживает уход со страницы.
