## Контекст и режимный инвариант
Боевой ISC.AI работает в **изолированном контуре без интернета** (инвариант 2: air-gap). Поэтому сбор корпуса из интернета (`gov.kg` и др. — НПА первым, но **не единственным** типом) **выносится за пределы контура** в отдельный инструмент. Внутрь контура попадает только **пакет файлов** (через контролируемый перенос — организационный процесс, не код), который импортируется уже существующим fail-closed `IngestionPort`. Ядро/хост в контуре **никогда** не обращаются в интернет.

> **Жёсткое правило:** `ISC.AI.Harvester` обрабатывает только **открытые** (публичные) НПА (гриф=открытый/0). Он не касается контура, БД и материалов ДСП. Хост контура **не ссылается** на Harvester; Harvester **не ссылается** на `Persistence`/`AI`/`Web`.

## Цель
Отдельное **веб-приложение оператора** (вне контура) — **универсальный сборщик**: умеет скачать документы с **произвольной ссылки** (best-effort) и точно — с подключаемых источников (gov.kg первым), для **любого типа документа** (НПА, положения, приказы, архивы), **показать собранное для проверки/курирования**, нормализовать и сложить в переносимый **пакет импорта**, пригодный для `IngestionPort`. Движок сбора **нейтрален**; источник и тип — **подключаемые** ([ADR-0015](../06_ADR/ADR-0015-universalnyy-sborshchik-dvizhok-i-konnektory.md), аналогия «ядро + профиль»).

## Роли
- **Оператор подготовки данных** (вне контура, есть интернет) — работает с web-консолью Harvester: источники, сбор, курирование, выгрузка пакета.
- **Инспектор** (внутри контура, интернета нет) — Harvester НЕ видит и не использует; он работает только с импортированным корпусом в основном хосте.

## Архитектура
- Новый проект **`src/tools/ISC.AI.Harvester`** — **веб-приложение** (Blazor Server + MudBlazor, .NET 10), запускается **вне контура** на машине с интернетом. **Отдельный деплой**, а НЕ страница внутри `ISC.AI.Web` (иначе интернет попал бы в контур, нарушив инвариант 2). Ссылается только на `Abstractions` ради общего контракта пакета; НЕ ссылается на `Persistence`/`AI`/`Web` контура и не подключается к боевой БД. Своё локальное хранилище состояния (вне контурной БД).
- **Нейтральный движок** (`Harvester.Core`): конвейер `Discover → Fetch → Extract → Map → (курирование) → Bundle`. Не знает про gov.kg/НПА — источник и тип подключаемые.
- **Универсальная модель документа** `HarvestedDocument` (типонезависима, как корпус ядра): `SourceUrl`, `Lang` (ru/ky/…), `Title`, `Text`, **`DocType` — свободная строка**, **`Metadata` — открытый словарь** (любые поля источника), `ContentHash`; режимные поля декларируются (`Classification=открытый`, `DivisionId` из конфига оператора).
- **Подключаемые адаптеры:**
  - `ISourceConnector` — источник (`Discover` + `Fetch`, вежливо: User-Agent, rate-limit, retry, `robots.txt`): `GenericUrlConnector` — **любой URL** (best-effort), доступен **всегда** (zero-config); `ConfigurableSiteConnector` — точное извлечение по **правилам из конфига** (CSS-селекторы); любой структурированный сайт (gov.kg и др.) — **конфиг, не класс**. Новый источник = новые правила, без пересборки; класс-адаптер — редкое исключение (API/JS).
  - `IContentExtractor` — по типу контента: HTML-readability (универсально), далее PDF/DOCX.
  - `IMetadataMapper` (опц., на источник) — поля источника → `Metadata`/`DocType`; generic = best-effort.
- **Реестр коннекторов:** web-консоль показывает доступные источники; оператор выбирает источник + конфиг (seed, глубина, фильтры, целевые `DocType`/`DivisionId`).
- **Веб-консоль оператора:** добавить источник/URL, запустить сбор, видеть **прогресс**, просматривать собранные документы (заголовок, тип, дата, язык, источник, фрагмент текста), **курировать** (включить/исключить, поправить метаданные), **выгрузить пакет**. Векторизация/чанкинг здесь НЕ выполняются — это происходит в контуре при импорте (локальной моделью).
- **Пакет импорта (контракт через air-gap):** папка с документами + `manifest.json` (на документ: исходный URL, тип, номер, дата, редакция/статус, язык, **гриф=открытый**, подразделение, content-hash). Манифест — единственное, что «пересекает» зазор, как данные.
- **Импортёр в контуре** (часть Э4-01): читает `manifest.json` → на каждый документ вызывает `IngestionPort` (валидирует гриф/подразделение fail-closed, дедуп по хешу, идемпотентно).

## Критерии приёмки
- Harvester — **отдельное веб-приложение вне контура**; оператор в браузере добавляет источник, запускает сбор, видит прогресс, просматривает и курирует собранное, выгружает пакет.
- С `gov.kg` (через `ConfigurableSiteConnector` + конфиг правил) собран ограниченный **открытый** корпус НПА в пакет; пакет импортируется в контур через `IngestionPort` (гриф проставлен, дублей нет, повторный импорт идемпотентен).
- Произвольная ссылка даёт хотя бы текст (best-effort), без падения сборщика.
- **Контур остаётся air-gap:** ни ядро, ни хост контура не обращаются в интернет; Harvester не ссылается на проекты контура и не подключается к боевой БД; единственный путь данных — импорт пакета. Подтверждено архитектурным тестом и ревью.
- Все зависимости — только MIT/Apache.
