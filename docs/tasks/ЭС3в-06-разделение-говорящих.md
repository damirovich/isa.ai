# ЭС3в-06 — Разделение говорящих в расшифровке («Диктор 1», «Диктор 2»)

**Профиль:** «Следствие» · **Ветка:** `feature/speaker-diarization` · **Дата:** 2026-10-17 · **Статус:** ✔ сделано (ADR-0062)

## Что это

[АИС ФТ-5.8.3, экран 10, ПМИ 14]: расшифровка с разделением реплик по говорящим и правкой стенограммы по дикторам.
Сейчас расшифровка — фрагменты с таймкодами без говорящих (ADR-0026/0047); вопрос 11 Приложения В решён 17.10.2026 —
говорящих различать.

## Требования

ТФ-МЕД-19 (новое), ТФ-МЕД-08, ТФ-МЕД-18, ТСТ-004, ТЭ-007, КИ-10.

## Что сделать

- Подобрать локальную модель разделения говорящих с кодом и весами под MIT/Apache (ТСТ-004), работающую вне
  интернета и со смешанной русско-киргизской речью; проверить на записях пилота (телефон, диктофон, голосовые).
- Конвейер: разметка «кто говорит» по участкам речи → привязка фрагментов расшифровки к дикторам; повтор по кнопке.
- Слой правок: переименовать диктора, перенести реплику, объединить дикторов — с автором и временем, дословный
  текст не меняется.
- Проигрыватель и режим «Текстом» (ADR-0047): реплики с именами дикторов; выгрузка в Word — по репликам.
- ADR: модель, лицензия, манифест SHA-256 в поставке (ТИ-004), ограничения точности.

## Как проверяется

- Модульные: привязка фрагментов к участкам дикторов, слой правок.
- Интеграционный на синтетической записи двух голосов (без реальных голосов в тестах).
- Пилот: доля правильно разделённых реплик — КИ-10.

## Зависимости и вопросы

Выбор модели под лицензию — главный риск; без подходящей модели — сообщить Заказчику до реализации.

## Что сделано (ADR-0062, 22.10.2026)

- **Модели (решение Заказчика 22.10.2026):** сегментация pyannote/segmentation-3.0 (MIT) и «голосовой отпечаток» CAM++
  из 3D-Speaker (Apache-2.0) через `OfflineSpeakerDiarization` той же sherpa-onnx 1.13.8 — новых зависимостей нет.
  Отвергнуты Reverb (некоммерческая), WeSpeaker VoxCeleb и TitaNet (CC-BY-4.0).
- **Два режима:** стерео-запись с раздельными каналами — по громкости каналов в адаптере (окна 100 мс, перевес в 4 раза,
  каналы-копии и один говорящий распознаются и уходят модели); иначе — моделью в процессе-распознавателе, если заданы
  модели `Speech:Speakers:*`; запись длиннее `MaxMinutes` (120) и сбой разметки — расшифровка без дикторов с причиной.
- **Протокол:** ключи `--speaker-segmentation/--speaker-embedding` (парой), `--speakers`, `--speaker-threshold`,
  `--speaker-max-minutes`; строки `turn`; в `done` — исход разметки. Фрагменту — диктор наибольшего перекрытия,
  номера по первому появлению; пустые фрагменты номеров не занимают.
- **Хранение:** миграция `media` `TranscriptSpeakers` — автоматический диктор и перенос у фрагмента, источник и причина у
  носителя, таблица `media.transcript_speaker` (имя, «слит в», автор, гриф носителя); повторная расшифровка заменяет
  разметку и правки; чтение — под решёткой, в том числе строк дикторов.
- **Правки:** команды «переименовать», «объединить» (без кругов), «перенести реплику» (не к слитому; «как разметила
  система») — право загрузки, носитель в делах субъекта, журнал `Modify` с номерами без имён.
- **Экран и выгрузка:** подпись диктора его цветом у реплики, «✎» у перенесённой; полоса «Дикторы» с числом реплик;
  «Текстом» — новый абзац при смене диктора; «Копировать» и Word — по репликам «Диктор [мм:сс]: текст».
- **Поставка:** `export-speech-models.ps1 -Speakers` (два файла ~34 МБ; в источнике хеша нет — пины закреплены по
  первой проверенной выгрузке 22.10.2026, размеры совпали с API релизов); ключи — в «Развёртывании», 7.4 и 6.1п; в
  дев-настройках профиля модели прописаны.
- **Тесты:** процесс-распознаватель — ключи и протокол; адаптер — разбор `turn`, приписывание, стерео на синтетическом
  звуке (раздельные каналы, копии, один говорящий, тишина), настройки и аргументы; медиа — уплотнение номеров, выгрузка
  по репликам, команды и правила, экран (bUnit); интеграционные на Postgres — запись, правки, круги, повторная
  расшифровка, решётка; интеграционные с настоящими моделями (`Category=Speech`) — загрузка и разметка, пропуск длинной
  записи, стерео по каналам, каналы-копии — моделью.
- **Ручная проверка 22.10.2026** на синтетическом диалоге двух голосов синтеза речи Windows (Irina — русский, Zira —
  английский; 6 реплик, 37 с; записей людей нет): модель сама нашла 2 диктора, все 13 участков речи отнесены к своему
  голосу, разметка — 1,8 с; через адаптер целиком: моно — моделью, стерео с раздельными каналами — по каналам с тем же
  итогом, стерео-копия — моделью.

- **v0.2 (22.10.2026, по проверке на записи заказчика):** на видео с телефона модель по порогу 0,5 разделила одного
  рассказчика на 5 дикторов, а порог 0,9 уже сливает разные голоса синтетического диалога — единого порога нет. Добавлены
  «Говорящих: авто / 1–6» с «Расшифровать заново» в полосе «Дикторы» (число — с задачей в очереди, в журналах; стерео по
  каналам — при «авто» и 2) и подпись «Диктор ?» у реплики без диктора. Без миграций.

- **v0.3 (22.10.2026, ветка `feature/speaker-diarization-2`):** разметка по «отпечаткам» целых реплик и своя группировка
  вместо pyannote (тот же диалог — 14 из 14, видео с телефона — рассказ одним диктором вместо четырёх; 0,5 с вместо
  1,8 с); переключатель Администратора «Размечать дикторов при расшифровке загруженных материалов» и выбор «Дикторы: без
  дикторов / авто / 1–6» у «Расшифровать заново». Без миграций.

**Не сделано / на пилот:** проверка точности на реальных записях — телефон, диктофон, похожие голоса, перебивания (КИ-10)
— и подбор `Threshold`/`Count`. Синтетический диалог в постоянные тесты не перенесён: голоса синтеза Windows есть не на
каждой машине.
