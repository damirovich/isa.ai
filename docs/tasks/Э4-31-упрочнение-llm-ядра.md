## Зачем
Архитектурный разбор (не по ТЗ, а «правильной ли формы ядро для LLM») подтвердил: несущие узлы зрелые, но
есть предметные пробелы **продакшн-готовности**, важные именно для аудируемого юридического ассистента. Ни
один — не архитектурный тупик (швы `ChatOptions`/`IChatClient` их держат), поэтому закрыты сразу.

## Что сделано

### 1. Параметры генерации из конфигурации (детерминизм)
Раньше генерация шла с `options: null` — ни температуры, ни `max_tokens`, ни `seed`. Одинаковый запрос давал
**разные** ответы (дефолт сервера ~0.7), что подрывает воспроизводимость и доверие к неизменяемому журналу.
- `GenerationOptions` (`ISC.AI.AI/Rag`) — `Temperature` (по умолчанию **0** = детерминированно), `TopP`,
  `MaxOutputTokens` (по умолчанию 4096 — граница длины), `Seed`. Читается из секции `Llm:Generation`.
- `GroundedGenerator` строит `ChatOptions` и передаёт в **оба** пути (блокирующий и стриминг).
- Тест: `GroundedGeneratorTests` — параметры доходят до модели.

### 2. Гвард бюджета токенов / контекстного окна
Раньше все `TopK` фрагментов склеивались без подсчёта — на длинных НПА промпт мог молча превысить окно, и
грунтовка проверяла ответ против фрагментов, часть которых модель **не видела**.
- `GenerationOptions.PromptTokenBudget` — бюджет на весь промпт; при превышении младшие по релевантности
  фрагменты отбрасываются, **грунтовка идёт по ФАКТИЧЕСКИ отправленным** фрагментам (исправлен и логический
  изъян грунтовки). Усечение **не тихое** — пишется предупреждение (`GroundedGeneratorLog.ContextTruncated`).
- Оценка токенов приблизительная (без реального токенизатора), `CharsPerToken` конфигурируем (кириллица ~2.5).
  `null`-бюджет — без гварда (безопасный дефолт до калибровки под окно модели, как `Retrieval:MaxDistance`).
- Тест: `GroundedGeneratorTests` — лишние фрагменты отброшены, грунтовка/результат по отправленным.

### 3. Ограничитель параллелизма к серверу инференса (bulkhead)
Раньше интерактивные пользователи и фоновые задачи били в один GPU-сервер без лимита; circuit breaker
реагирует ПОСЛЕ сбоев, а не предотвращает перегрузку.
- `ModelCallResilience` получил `SemaphoreSlim` (на роль, singleton → лимит на роль). Слот удерживается на
  весь блокирующий вызов и на **всю длительность стрима**. Лимит из `Llm:MaxConcurrencyPerRole` (по умолч. 4).
- Тест: `ModelCallResilienceTests` — не больше N одновременных вызовов.

### 4. Тест-инвариант неподменяемости грунт-валидатора (ТБ-041)
Системный промпт грунтовки был защищён, но сам `IGroundingValidator` профиль технически мог бы подменить —
теста не было. Теперь заявленный инвариант закреплён **сборкой**, а не конвенцией.
- `GroundingCompositionTests` — после полной композиции (ядро + профиль) `IGroundingValidator` = ядровый
  `GroundingValidator`.

## Проверка
- Build 0 ошибок; юнит **176/176** (+4); интеграционные **23/23**.

## Границы / примечание
- Оценка токенов — эвристика (символы/токен), не реальный токенизатор модели. Для точного бюджета под
  конкретную модель порог калибруется на стенде (Э1). `null` по умолчанию — поведение не меняется, пока
  оператор не задаст бюджет.
- Дефолт bulkhead (4) — стартовое значение; под ёмкость конкретного сервера инференса подбирается конфигом.
