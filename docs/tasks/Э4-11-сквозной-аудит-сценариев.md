# Э4-11. Сквозной аудит сценариев (AuditBehavior) + аудит загрузки корпуса (P0, режим)

| | |
|---|---|
| Этап | Э4 — hardening (P0) |
| Статус | ⏳ Запланировано |
| Требования ТЗ | ТБ-030 (все обращения/генерации — в журнал), ТБ-031 (неизменяемость) |
| Источник | Аудит 2026-06-26 (top-risk P0 #3; инвариант «Аудит — частично») |
| Зависит от | Э3-03 (инфраструктура аудита), связано с Э3-08 (SubjectId) |

## Проблема
Инфраструктура аудита полная (хеш-цепочка, append-only триггер). Но:
- Сценарии **загрузки корпуса** (`IngestFileCommand`, `ImportBundleCommand`) **не пишут аудит**; `AuditAction.Ingest` нигде не используется → загрузка материалов (в т.ч. с грифом) проходит **мимо журнала** (нарушение ТБ-030).
- Нет **сквозного `AuditBehavior`**: каждый новый сценарий должен помнить ручной вызов `IAuditWriter` (Search/Generate/Export пишут, загрузка — нет). Системный риск.
- `SubjectId` не проставляется (анонимные записи до Э3-08).

## Цель
Сделать аудит **поведением по умолчанию** для всех обращающихся/генерирующих сценариев и закрыть дыру с загрузкой.

## Что сделать
- ⏳ `AuditBehavior` в Mediator-pipeline хоста (после Validation): фиксирует факт обращения/генерации для помеченных сценариев (атрибут/маркер-интерфейс команды → действие аудита).
- ⏳ Аудит `AuditAction.Ingest` для `IngestFileCommand`/`ImportBundleCommand` (через поведение или явно).
- ⏳ Протягивать `SubjectId` из контекста доступа (анонимно до Э3-08, затем реальный субъект).
- ⏳ Тесты: загрузка пишет запись аудита; новый сценарий с маркером — пишет без ручного вызова.

## Критерии приёмки
- Загрузка корпуса фиксируется в неизменяемом журнале (ТБ-030).
- Добавление нового сценария не требует ручного вызова аудита (поведение по умолчанию, как в CLAUDE.md).

## Осталось / риски
- Атомарность: аудит пишется отдельным DbContext/транзакцией от бизнес-факта — отметить, единую транзакцию решить отдельно (P2).
- До Э3-08 субъект анонимен — это ожидаемо, не блокер.
