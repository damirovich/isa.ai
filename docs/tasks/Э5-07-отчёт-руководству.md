# Э5-07 — Аналитический отчёт для руководства (§5.2.6, ТФ-МОН-02)

**Ветка:** `feature/management-report` · **Дата:** 2026-08-24 · **Статус:** готово

## Что это

Кнопка «Аналитический отчёт для руководства» на странице «Мониторинг» (заглушка снята): по выбранному
периоду страницы формируется докладная «Отчёт о состоянии внутреннего контроля» — общая картина,
оценка по подразделениям (светофор и чем объясняется балл), проблемные зоны, выводы и предложения.

**Разделение труда (суть ТФ-МОН-02):** ВСЕ числа считает КОД — `ManagementReportFacts.Build`
собирает детерминированный факт-блок из тех же источников, что экраны (`IRiskDataSource`: сводка,
разбор риска с сигналами, ход устранения); ИИ быстрой ролью Draft пишет только связующий деловой
текст, и промпт прямо запрещает ему выдумывать числа. Результат — проект для человека (ТБ-042).

## Судьба отчёта

Диалог результата: экспорт в .docx (гриф, общий экспортёр — ТБ-033), «Доработать в Редакторе»
(передача текста как из Генератора), «Зарегистрировать в документообороте» (пометка
«сформировано ИИ (Мониторинг)», GATE-2-гейт на неподтверждённые ссылки).

## Устройство

- Шаблон `Generation/Prompts/management-report.scriban` (параметры `period_days`, `facts`).
- `GenerateManagementReportCommand(PeriodDays)` — `IGroundedScenario`, роль Draft, guard пустого
  ответа; аудит пишет оркестратор ядра. Retrieval-тема — «внутренний контроль…» (нормы могут
  украсить основания, но промпт не требует ссылок).
- Тесты `ManagementReportTests`: факт-блок несёт счётчики/уровни словами/сигналы/болевые сферы,
  пустой период честно назван; настоящий шаблон встроен; handler шлёт роль Draft с факт-блоком
  в задачном промпте; HITL всегда.

## Не входит

- Расписание автоформирования (еженедельный отчёт по расписанию) — по потребности.
- ТФ-МОН-02 «аналитика эффективности» в части сложных показателей §5.2.5.2 — P2, отдельно.
