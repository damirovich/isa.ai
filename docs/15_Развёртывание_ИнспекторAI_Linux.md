# Развёртывание «ИнспекторAI» на Linux

Инструкция по установке «ИнспекторAI» на серверы изолированного контура (без доступа в интернет).
Редакция от 28.10.2026. Версия самого пакета записана в файле `VERSION` внутри архива.

Что из чего состоит:

- веб-приложение на .NET 10, работает как служба systemd `isc-ai`;
- PostgreSQL с расширением pgvector: одна база, в ней схемы `core`, `docflow`, `inspector`;
- узел ИИ: `llama-server` с языковой моделью и отдельной моделью эмбеддингов.

Приложение собрано вместе со средой .NET, поэтому .NET на сервер ставить не нужно. Из пакетов дистрибутива нужны
только клиент PostgreSQL, Tesseract (распознавание сканов) и шрифты. Всё остальное есть в архиве и ставится его
скриптами.

## 1. Что понадобится

### 1.1. Серверы

| Сервер | Назначение | Требования |
|---|---|---|
| Сервер приложений | служба `isc-ai`, файлы документов, ключи сессий | Linux x86-64 с systemd. Проверено на Debian 12; подойдут Ubuntu 24.04, RHEL 9 и совместимые. Astra Linux и РЕД ОС в списке поддерживаемых у .NET нет, на них нужен пробный прогон |
| Сервер БД (можно совместить с сервером приложений) | PostgreSQL | PostgreSQL 16–18 (разрабатываем на 18), pgvector 0.5 и выше, `pg_trgm` из contrib, включённый SSL |
| Узел ИИ | `llama-server`: модель Gemma на порту 9000 и EmbeddingGemma 300M на порту 9001 | GPU |
| Носитель для резервных копий | зашифрованные копии баз и файлов | монтируется на сервер приложений в `/mnt/isc-backup` |
| Рабочие места пользователей | браузер | свежий Chromium или Firefox, корневой сертификат УЦ контура в доверенных |

### 1.2. Что переносится в контур

| Что | Размер |
|---|---|
| Архив `isc-ai-inspector-<версия>-linux-x64.tar.gz` и файл `.tar.gz.sha256` к нему | около 120 МБ, в распакованном виде около 275 МБ |
| Пакеты ОС из раздела 1.4, если в контуре нет зеркала репозитория | десятки МБ, сам PostgreSQL около 50 МБ |
| `llama-server` и файлы моделей GGUF | Gemma 26B-A4B Q4 около 15–17 ГБ, EmbeddingGemma Q8_0 около 320 МБ |
| Нормативная база | см. раздел 8, п. 2 |

Сертификат HTTPS и ключи резервных копий извне не везём, они создаются внутри контура.

### 1.3. Что подготовить до установки

1. Имя сервера в DNS контура. Система будет открываться только по нему: запросы с другим именем в заголовке Host
   отклоняются.
2. Сертификат HTTPS на это имя от УЦ контура: `server.crt` и `server.key` в формате PEM. Корневой сертификат УЦ
   должен быть в доверенных на рабочих местах.
3. Сетевой доступ:
   - рабочие места → сервер приложений: 443 (порт 80 только перенаправляет на HTTPS);
   - сервер приложений → БД: 5432;
   - сервер приложений → узел ИИ: 9000 и 9001.

   К узлу ИИ, кроме сервера приложений, доступа ни у кого быть не должно.
4. Роль и база в PostgreSQL (раздел 3).
5. Ключи резервных копий. Их создаёт тот, кто будет хранить ключ, на отдельной машине с Linux x86-64, программой
   из архива:

   ```bash
   tools/backup-restore/ISC.AI.Backup.Restore keygen --out <каталог>
   ```

   Программа спросит пароль (не короче 12 символов), создаст `backup-public.pem` и `backup-private.pem` и напечатает
   отпечаток открытого ключа. Закрытый ключ остаётся у хранителя, на сервер его не кладут. На сервер идут только
   `backup-public.pem` и отпечаток.
6. Точка монтирования носителя для копий: `/mnt/isc-backup`.
7. Синхронизация времени (NTP) на всех серверах. От неё зависит время записей в журнале аудита.

### 1.4. Пакеты ОС

| Зачем | Debian 12 / Ubuntu 24.04 | RHEL 9 и совместимые |
|---|---|---|
| Среда .NET: ICU, OpenSSL, сертификаты (обычно уже стоят) | `libicu72` / `libicu74`, `libssl3`, `ca-certificates` | `libicu`, `openssl-libs`, `ca-certificates` |
| Распознавание сканов: Tesseract 5 и Leptonica | `libtesseract5`, `liblept5` (Debian) / `libleptonica6` (Ubuntu 24.04) | `tesseract-libs`, `leptonica` (EPEL) |
| Шрифты с кириллицей для PDF-отчётов | `fonts-dejavu-core` | `dejavu-sans-fonts` |
| Клиент PostgreSQL той же основной версии, что и сервер (для `migrate.sh` и резервных копий) | `postgresql-client-18` (репозиторий PGDG) | `postgresql18` (PGDG) |
| Сервер БД | `postgresql-18`, `postgresql-18-pgvector` | `postgresql18-server`, `postgresql18-contrib`, `pgvector_18` |

Языковые файлы Tesseract (`rus`, `kir`) из ОС ставить не нужно, они лежат в архиве. В Ubuntu 22.04 Tesseract
четвёртой версии: приложение там работает, но сканы не распознаются.

Если зеркала нет, пакеты скачиваются на машине с той же версией ОС и интернетом: `apt-get install --download-only
<пакеты>` (файлы окажутся в `/var/cache/apt/archives`) или `dnf download --resolve <пакеты>`.

## 2. Проверка архива после переноса

```bash
sha256sum -c isc-ai-inspector-<версия>-linux-x64.tar.gz.sha256
tar -xzf isc-ai-inspector-<версия>-linux-x64.tar.gz
cd isc-ai-inspector-<версия>-linux-x64
bash verify.sh --log /var/log/isc-ai-transfer.log
```

`verify.sh` сверяет каждый файл со списком `SHA256SUMS`. Изменённый, отсутствующий или лишний файл означает отказ, и
такой пакет не ставим. С ключом `--log` результат (кто, когда, какая версия, итог) дописывается в журнал переноса.

Что лежит в архиве:

| Путь | Что это |
|---|---|
| `app/` | приложение (`ISC.AI.Web` вместе со средой .NET) |
| `tools/backup-restore/` | программа для ключей, проверки и восстановления резервных копий |
| `sql/10-core.sql`, `20-docflow.sql`, `30-inspector.sql` | миграции схем; повторное применение ничего не ломает |
| `tessdata/` | `rus.traineddata`, `kir.traineddata` |
| `config/appsettings.Production.json`, `config/isc-ai.env` | шаблоны настроек и секретов |
| `systemd/isc-ai.service` | описание службы |
| `verify.sh`, `install.sh`, `migrate.sh`, `account.sh` | проверка, установка, миграции, создание учётной записи |
| `VERSION`, `SHA256SUMS` | версия и контрольные суммы |
| `docs/INSTALL.ru.md` | эта инструкция |

## 3. База данных

1. Поставить PostgreSQL и pgvector (раздел 1.4).
2. В `postgresql.conf`: `ssl = on` с сертификатом сервера БД от УЦ контура; в `listen_addresses` — адрес, на котором
   его видит сервер приложений. Перед загрузкой большой нормативной базы поднять `maintenance_work_mem`. Если памяти
   не хватит, векторный индекс будет строиться очень долго, а в журнале PostgreSQL появится
   `hnsw graph no longer fits in maintenance_work_mem`.
3. В `pg_hba.conf`: только `hostssl` с адреса сервера приложений, метод `scram-sha-256`.
4. Под пользователем `postgres` создать роль и базу:

   ```sql
   CREATE ROLE isc_ai LOGIN PASSWORD '<пароль>';
   CREATE DATABASE isc_ai OWNER isc_ai ENCODING 'UTF8' TEMPLATE template0;
   \c isc_ai
   CREATE EXTENSION IF NOT EXISTS vector;
   CREATE EXTENSION IF NOT EXISTS pg_trgm;
   ```

Приложение работает под владельцем базы, а не под суперпользователем. Программа восстановления из копии создаёт и
переименовывает базы, поэтому её запускают под `postgres`.

## 4. Сервер приложений

### 4.1. Установка

```bash
sudo bash install.sh
```

Скрипт можно запускать повторно. Что он делает:

- проверяет архив (тот же `verify.sh`);
- создаёт системного пользователя `iscai`;
- раскладывает приложение в `/opt/isc-ai/releases/<версия>` и делает ссылку `/opt/isc-ai/current`;
- создаёт каталоги данных `/var/lib/isc-ai/{storage,docflow-files,keys}` с правами 0700;
- кладёт языковые файлы в `/opt/isc-ai/tessdata` и связывает приложение с системными библиотеками Tesseract;
- при первой установке кладёт шаблоны настроек в `/etc/isc-ai`; при повторной существующие файлы не трогает;
- ставит службу `isc-ai` в автозапуск;
- проверяет, что есть ICU, OpenSSL, шрифты и `pg_dump`.

Всё, что требует внимания, выводится строками `ВНИМАНИЕ`. Службу скрипт не запускает.

### 4.2. Настройки

| Файл | Что заполнить |
|---|---|
| `/etc/isc-ai/appsettings.Production.json` | `AllowedHosts` (имя сервера), строки подключения `Core`, `Inspector`, `DocFlow` (все три в одну базу), адреса узла ИИ, отпечаток ключа копий в `Backup:PublicKey:Sha256`. Пути к каталогам уже заполнены под раскладку `install.sh` |
| `/etc/isc-ai/isc-ai.env` (root:root, 0600) | `Database__Password`; ключи API модели, если `llama-server` запущен с ключом. `Auth__DefaultAccount__Password` оставить пустым |
| `/etc/isc-ai/tls/server.crt`, `server.key` (root:iscai, 0640) | сертификат HTTPS (п. 1.3) |
| `/etc/isc-ai/backup-public.pem` | открытый ключ резервных копий (п. 1.3) |

Пароли в JSON не пишем: пароль БД приложение берёт из переменной `Database__Password`.

### 4.3. Миграции

```bash
bash migrate.sh --host <сервер БД> --db isc_ai --user isc_ai --yes
```

Скрипт проверяет, что pgvector и нужные расширения есть, применяет схемы по порядку (`core`, `docflow`, `inspector`)
и сверяет число применённых миграций с пакетом. Пароль берётся из `PGPASSWORD`, иначе скрипт его спросит. Ключ `--yes`
нужен только при первой установке на пустую базу. При обновлении скрипт сначала спросит, сделана ли резервная копия.

### 4.4. Запуск

```bash
sudo systemctl start isc-ai
journalctl -u isc-ai -n 50 --no-pager      # ищем строку «Хост ISC.AI запущен с профилем inspector (ИнспекторAI)»
curl -sk https://localhost/health          # должно вернуть ok
```

Если приложение не стартует, в журнале будет строка с `FTL`, а systemd будет перезапускать службу каждые 10 секунд.
Обычные причины: не заполнен шаблон настроек, нет сертификата, неверный пароль БД, на сервере БД выключен SSL.

При первом запуске в журнале будет предупреждение `No XML encryptor configured … unencrypted form`. Это нормально.
Ключи сессий лежат в `/var/lib/isc-ai/keys`, и защищают их права на каталог: 0700, доступ только у `iscai`.

### 4.5. Первая учётная запись

```bash
sudo bash account.sh admin "Фамилия И. О."
```

Команда один раз печатает временный пароль, в базе хранится только его хеш. Дальше войти под этой учётной записью,
сменить пароль, в разделе «Пользователи» назначить себе роль Администратора и в блоке «Допуск» выдать гриф и
подразделения.

### 4.6. Проверка после установки

1. С рабочего места открыть систему по имени сервера: страница открывается по HTTPS, браузер не ругается на
   сертификат.
2. Загрузить тестовый документ без грифа: текстовый PDF или DOCX и отдельно скан, чтобы проверить распознавание.
3. Поиск и подготовка документа: модель отвечает, в ответе есть ссылки на нормативные документы.
4. PDF-отчёт из документооборота: кириллица отображается.
5. «Резервные копии»: «Сделать копию», затем «Проверить последнюю копию».

## 5. Узел ИИ

Узел ИИ поднимается отдельно. Со стороны приложения нужно следующее:

- адреса `http://<узел ИИ>:9000/v1` (Gemma) и `http://<узел ИИ>:9001/v1` (EmbeddingGemma) прописаны в
  `Llm:Models:*:Endpoint`;
- `llama-server` слушает только внутренний адрес, межсетевой экран пускает к нему только сервер приложений.
  Желательно запускать его с `--api-key`, тогда ключ указывается в `isc-ai.env` (`Llm__Models__<роль>__ApiKey`);
- тексты запросов и ответов не пишутся в журналы `llama-server` и ОС, своп на узле выключен или зашифрован;
- модель эмбеддингов должна быть той же, на которой индексировалась нормативная база. Если её сменить, базу придётся
  индексировать заново.

## 6. Обновление и откат

Обновление:

1. Сделать резервную копию: «Резервные копии» → «Сделать копию» → «Проверить».
2. Перенести новый архив и прогнать `verify.sh` (раздел 2).
3. Поставить новую версию и применить миграции:

   ```bash
   sudo bash install.sh             # раскладывает новую версию и переключает ссылку, работающую службу не трогает
   sudo systemctl stop isc-ai
   bash migrate.sh --host … --db … --user …
   sudo systemctl start isc-ai
   ```

   До применения миграций новую версию не запускать: на старой схеме БД она упадёт.
4. Сравнить `/etc/isc-ai/appsettings.Production.json` с шаблоном из `config/` нового архива. Настройки при обновлении
   не перезаписываются, а в новой версии могут появиться новые параметры.

Откат. Прежние версии остаются в `/opt/isc-ai/releases/`. Если миграции не применялись, достаточно вернуть ссылку:

```bash
sudo ln -sfn /opt/isc-ai/releases/<прежняя версия> /opt/isc-ai/current
sudo systemctl restart isc-ai
```

Если миграции уже применены, откатить их скриптами нельзя: базу восстанавливают из резервной копии. Это делается
программой `tools/backup-restore` при остановленной службе, вдвоём: администратор и хранитель закрытого ключа.

Если нужно поменять что-то в службе (другой каталог для копий, зависимость от локального PostgreSQL), делайте это
через `systemctl edit isc-ai`. Сам файл службы `install.sh` при каждом запуске перезаписывает.

## 7. Что уже проверено

Пакет прогнан в контейнере с Debian 12, PostgreSQL 16 и pgvector. systemd в контейнере нет, поэтому приложение
запускалось вручную с тем же окружением, что у службы. Проверено:

- `verify.sh` принимает целый архив и отказывает при лишнем или изменённом файле;
- `install.sh` правильно раскладывает файлы и выставляет права, повторный запуск не трогает настройки;
- `migrate.sh` на пустой базе создаёт расширения и применяет все миграции, повторный запуск ничего не меняет;
- приложение стартует, `/health` отвечает, ключ сессий появляется в `/var/lib/isc-ai/keys`, ошибок в журнале нет;
- по шаблону настроек: HTTPS на 443, с 80 перенаправление на HTTPS, запрос с чужим именем хоста отклоняется (400);
- `account.sh` создаёт учётную запись и выдаёт временный пароль.

Пока не проверялось, нужно проверить на стенде:

- сама служба systemd: ограничения службы, автозапуск, перезапуск после сбоя;
- распознавание сканов с системным Tesseract 5;
- PDF-отчёты со шрифтами дистрибутива;
- SSL-соединение с БД;
- работа с узлом ИИ;
- восстановление из резервной копии на Linux.

## 8. Что нужно решить до запуска в работу

1. Дистрибутив и версия ОС в контуре. От этого зависит список пакетов из раздела 1.4. Нужен Tesseract 5, иначе
   сканы не распознаются. Если это Astra Linux или РЕД ОС, сначала прогнать на стенде.
2. Как заливать нормативную базу (около 208 тыс. документов). Вариант первый: загрузить в контуре на странице
   «Загрузка корпуса», тогда все документы заново проходят через модель эмбеддингов, а это долго. Вариант второй:
   перенести уже готовую базу.
3. Отдельная роль БД с урезанными правами и разграничение доступа к строкам. Сейчас приложение работает под
   владельцем базы. До загрузки документов с грифом ДСП это нужно поменять.
4. Журнал аудита сейчас хранится только в самой БД. Нужна его копия или подпись вне БД, чтобы администратор
   базы не мог незаметно его поправить.
5. HTTPS и шифрование резервных копий сделаны штатными средствами ОС и .NET, это не сертифицированные СКЗИ.
   Допустимо ли это для нашей системы, должны решить безопасники.

## Приложение. Как собирается архив

Архив собирается вне контура, на машине разработки (Windows, интернет, .NET SDK 10, `dotnet-ef`), из закоммиченного
состояния репозитория:

```powershell
.\deploy\linux\build-inspector-package.ps1
```

Скрипт публикует приложение под `linux-x64` вместе со средой .NET и проверяет, что в сборку попал только профиль
«ИнспекторAI». Затем публикует программу восстановления копий, выгружает SQL-миграции трёх схем и кладёт языковые
файлы Tesseract из `deploy/offline/tessdata` (если их нет, сначала запустить `deploy/offline/export-tessdata.ps1`).
После этого добавляет скрипты, службу, шаблоны и эту инструкцию, пишет `VERSION` и `SHA256SUMS` и упаковывает всё в
`.tar.gz` с файлом контрольной суммы.

Результат появляется в `artifacts/deploy/`. Версия по умолчанию: `<дата>-<коммит>`. Если в репозитории были
незакоммиченные правки, к версии добавляется `-dirty`; такой архив в контур не отправляем.
