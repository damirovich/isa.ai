## 1. Термины, определения и сокращения

Термины платформы (ядро, профиль, модуль, гриф, допуск, решётка доступа, аудит, грунтовка, HITL, изолированный контур, multi-instance) — по ДОК-01 §1. Дополнительно:

| Термин / сокращение | Определение |
|---|---|
| Дело | Единица учёта следственной работы (уголовное дело, материал проверки, ОРМ-производство), к которой привязываются материалы, фигуранты и поисковые запросы. Основание ведения — процессуальный или ведомственный документ. |
| Фигурант (персона) | Физическое лицо, учтённое в деле; имеет карточку с эталонными изображениями лица. |
| Носитель (медиа-актив) | Загруженный файл фото или видео с реквизитами: дело, источник, дата/время, место, гриф, подразделение. |
| Кадр | Извлечённое из видео изображение с меткой времени (таймкодом). |
| Лицо (детекция) | Область изображения, распознанная детектором как лицо; имеет координаты, ключевые точки, оценку качества. |
| Биометрический шаблон (вектор лица) | Числовое представление лица, вычисленное моделью; используется только для сравнения. **Специальная категория персональных данных** (ЦК ст. 80). |
| Пробное изображение | Фотография, по которой выполняется поиск («найти этого человека»). |
| Кандидат-лист | Упорядоченный по схожести список лиц из базы, возвращаемый поиском. **Не является установлением личности.** |
| Балл схожести (score) / порог | Мера близости шаблонов; порог — настраиваемое значение, ниже которого кандидат считается слабым. Баллы не переносимы между моделями. |
| Режим investigation | Режим поиска 1:N с фиксированной длиной кандидат-листа и обязательным разбором человеком (NIST FRTE). Базовый режим профиля. |
| Верификация (двойная) | Подтверждение или отклонение кандидата двумя независимыми обученными сотрудниками (эксперт + верификатор). |
| Следственная версия (investigative lead) | Единственный допустимый статус результата поиска до процессуальной проверки: основание для дальнейших действий, а не доказательство. |
| Эталонная база | Совокупность шаблонов лиц, по которой ведётся поиск (лица из носителей дел и эталонные изображения фигурантов). |
| Оценка воздействия | Документ по ст. 82 Цифрового кодекса КР (аналог DPIA), обязательный до обработки специальных категорий ПД более чем 1000 субъектов. |
| ЦК | Цифровой кодекс Кыргызской Республики от 31.07.2025 № 178 (глава 11 — персональные данные, глава 23 — системы ИИ). |
| Закон об ОРД | Закон КР от 26.06.2025 № 127 «Об оперативно-розыскной деятельности». |
| УПК | Уголовно-процессуальный кодекс КР от 28.10.2021 № 129. |
| TPIR / FPIR / FNIR | Метрики идентификации 1:N (ISO/IEC 19795-1): доля верно найденных, доля ложных срабатываний по «чужим» запросам, доля пропусков. |
| Rank-k | Доля поисков, где верный человек оказался в первых k кандидатах. |
| FTE | Доля изображений, из которых шаблон извлечь не удалось (failure to enrol/extract). |

> **Соглашение об этапах.** Рабочие этапы профиля обозначаются **ЭС0–ЭС5** (чтобы не смешивать с этапами платформы Э0–Э7 из ДОК-01). Фаза внедрения профиля — **ФС1** (пилот на обезличенных/тестовых данных) и **ФС2** (промышленная эксплуатация после режим-гейта и оценки воздействия).

## 2. Общие сведения

**2.1.** Полное наименование: профиль «Следствие» («СледствиеAI») платформы ISC.AI. Разрабатывается как **второй профиль** платформы по правилу «нейтральное ядро + сменный профиль» (ТС-003, ADR-0002): ядро переиспользуется, доменная логика следствия — только в профиле и подключаемом пакете модулей медиа.

**2.2.** Основание для разработки: заявка Заказчика; действующая платформа ISC.AI (ДОК-01, готовность §5.2 — полная); правовые основания применения — Закон об ОРД ст. 2 п. 12 (оперативно-розыскное мероприятие «цифровое распознавание объектов»: программное обеспечение, способное на основе баз данных автоматически идентифицировать или верифицировать человека), ст. 7 ч. 2, ст. 8, ст. 11 (создание и использование цифровых систем органами ОРД); ЦК ст. 80 ч. 2 п. 9 (обработка биометрии допустима для предотвращения, расследования и судебного рассмотрения уголовных преступлений при закреплённых законом мерах защиты); УПК ст. 89, 94 (фото-/видеоматериалы и научно-технические средства).

**2.3.** Плановые сроки: ЭС0–ЭС5 — по §6.2; ориентир для малой команды (2–3 человека) — 3–4 месяца до пилота ФС1.

**2.4.** Порядок оформления и предъявления результатов: по этапам §6.2, документы §9, приёмка §7. Реальные биометрические данные обрабатываются только после режим-гейта (ТБ-063) **и** утверждённой оценки воздействия (ТБ-078, ПОДГ-08).

**2.5.** Принципиальное положение. Система **не устанавливает личность**: результат любого поиска по лицу — кандидат-лист со схожестью, статус «следственная версия». Установление личности выполняется человеком процессуальными средствами (опознание по УПК ст. 209–211, экспертиза, протокол по ст. 94 ч. 4). Автоматическое решение с правовыми последствиями запрещено (ЦК ст. 1 п. 1, ст. 82 ч. 2 п. 1; ТБ-073). Применение системы носит **вспомогательный характер** (ЦК ст. 194 ч. 3).

## 3. Назначение и цели создания

### 3.1. Назначение

Профиль обеспечивает следственному подразделению единую защищённую среду для ведения дел и материалов, накопления фото- и видеоматериалов с автоматической разметкой лиц, ретроспективного поиска человека по фотографии по всем доступным сотруднику материалам, ведения карточек фигурантов, двойной верификации совпадений, подготовки справок по делам и фигурантам с помощью ИИ (с грунтовкой по документам дела) — в изолированном контуре, под решёткой доступа и неизменяемым аудитом.

### 3.2. Цели создания (с измеримыми показателями и трассировкой)

| Код | Цель | Показатель достижения | Реализующие требования и проверка |
|---|---|---|---|
| ЦС-01 | Сократить время поиска человека по имеющимся материалам | Поиск по фотографии по базе объёма ТН-007 — не более 5 с (p95); вместо ручного просмотра часов видео | ТФ-ПЛ-01..07, ТН-006; нагрузочный тест |
| ЦС-02 | Не пропустить присутствие лица в материалах | Rank-10 (TPIR при R=10, T=0) на пилотном наборе не ниже согласованного порога (КИ-06) | ТО-мат-05..09, КИ-05..06; Evals |
| ЦС-03 | Исключить ложную идентификацию как результат системы | Ноль случаев выдачи статуса «подтверждено» без двух подтверждений (GATE-5) | ТБ-073, ТФ-ВЕР-01..05; gate-тест |
| ЦС-04 | Обеспечить законность обработки биометрии | Утверждённая оценка воздействия (ст. 82 ЦК), аудит каждого поиска, удаление шаблонов по закрытию дела | ТБ-070..078, ПОДГ-08; аудит конфигурации |
| ЦС-05 | Переиспользовать платформу без переписывания ядра | Изменения ядра — только нейтральные контракты (ТС-011); архитектурный тест проходит | ТС-010..013, ТС-009 |

### 3.3. Критерий «не-цель»

Система **не** ведёт наблюдение в реальном времени (real-time идентификация в общественных местах — вне назначения; ЦК ст. 82 ч. 2 п. 3 и международные ограничения), **не** выводит по лицу этническую принадлежность, эмоции, состояние здоровья или иные признаки (ТБ-075), **не** является средством доказывания сама по себе (УПК ст. 94), **не** заменяет опознание и экспертизу, **не** передаёт изображения и шаблоны за пределы контура (ТБ-052, ЦК ст. 89).

## 4. Характеристика объектов автоматизации

**4.1.** Объект автоматизации — следственное подразделение: следователи, оперативные сотрудники (в части ОРМ по поручениям), эксперты по сравнению лиц, руководство, администратор системы, офицер ИБ.

**4.2.** Объекты учёта — дела и материалы дел: фото и видео (записи камер, изъятые носители, материалы ССД по УПК гл. 30, материалы, представленные участниками), документы дел (постановления, протоколы, справки), фигуранты.

**4.3.** Ситуация «как есть»: материалы хранятся на носителях и в папках; поиск человека по видео — ручной просмотр; эталонные фотографии — в бумажных и разрозненных электронных делах; ни автоматической разметки, ни сквозного поиска, ни журналирования обращений к материалам нет. Уточняется обследованием на ЭС1.

**4.4.** Окружение: изолированный контур Заказчика; смежные системы (ведомственные учёты, СЭД) — на ФС1 не подключаются; интеграции — по итогам обследования ЭС1 отдельным ТЗ.

**4.5.** Условия эксплуатации: изолированный контур без Интернета; сведения до ДСП включительно; биометрические данные — специальная категория (ЦК ст. 80); материалы ССД — конфиденциальны до окончания досудебного производства (УПК ст. 224).

## 6. Состав и содержание работ

### 6.1. Исходное состояние

Платформа ISC.AI: ядро, профиль «ИнспекторAI» и пакет модулей документооборота реализованы (ДОК-01 §5.2 закрыт); доступны решётка доступа, аудит с хеш-цепочкой, фоновые задания, векторный поиск (pgvector, HNSW с проверенными параметрами), файловая раздача с проверкой допуска, экспорт .docx с маркировкой, офлайн-поставка. ### 6.3. Очерёдность

P0 (сквозной срез пилота): дела → медиатека с индексацией → поиск по лицу → двойная верификация → появления фигуранта. P1: документы дела, справки, история поисков, реестр моделей. P2: связи фигурантов, пакетный импорт, отчёт руководителю.

| Код | Тест | Условие приёмки |
|---|---|---|
| GATE-4 | **Фильтр доступа для шаблонов лиц** (интеграционный тест на настоящем PostgreSQL+pgvector): шаблон с грифом выше допуска или из чужого подразделения/дела не возвращается поиском ни при каких параметрах; ответ неотличим от «лица в базе нет» по содержимому, счётчикам, ранжированию и времени; прямое обращение к векторной таблице — под решёткой; fail-closed без контекста доступа | Тест проходит безусловно. |

## Приложение Б. Схема идентификаторов

Идентификаторы — единая сквозная схема платформы (ДОК-01 Приложение Б): `<ПРЕФИКС>-[<СЕГМЕНТ>-]<NN>`, неизменные, номера не переиспользуются. Настоящий документ **продолжает нумерацию** платформенных групп (ТС, ТП, ТН, ТНД, ТЭ, ТБ, ТСТ, ТИ, ТО-*, ПР, КИ, GATE, ПОДГ, ДОК) с первого свободного номера, чтобы ссылки из кода, тестов и документов оставались однозначными в обоих профилях; блок ТБ-07x выделен теме «биометрические данные» по правилу блочной нумерации ТБ. Функциональные требования профиля — сегменты ДЕЛ, ПЕР, МЕД, ПЛ, ВЕР, ДДЛ, ОТЧ, АДМ. Цели профиля — ЦС-NN, этапы — ЭС0..ЭС5, фазы — ФС1/ФС2. Задачи бэклога профиля — «ЭС<этап>-<NN>» в `docs/tasks`.
