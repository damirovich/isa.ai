# Развёртывание «Следствие AI» на Linux

Инструкция по установке «Следствие AI» на серверы изолированного контура (без доступа в интернет).
Редакция от 06.11.2026. Версия самого пакета записана в файле `VERSION` внутри архива.

Что из чего состоит:

- веб-приложение на .NET 10, работает как служба systemd `isc-ai`;
- распознавание лиц (модели YuNet и SFace) и видео (ffmpeg) — внутри приложения, на процессоре сервера;
- распознавание речи — отдельный процесс-распознаватель из того же архива, тоже на процессоре;
- PostgreSQL с расширением pgvector: одна база, в ней схемы `core`, `docflow`, `media`, `investigation`;
- узел ИИ: `llama-server` с языковой моделью и отдельной моделью эмбеддингов — для чата по материалам дел и справок.

Приложение и распознаватель речи собраны вместе со средой .NET, поэтому .NET на сервер ставить не нужно. ffmpeg и
модели лежат в архиве. Из пакетов дистрибутива нужны клиент PostgreSQL, fontconfig, шрифты и Tesseract (распознавание
сканов). Всё остальное есть в архиве и ставится его скриптами.

Пакет ставится теми же скриптами, что и «ИнспекторAI». Если вы уже ставили Инспектора, порядок тот же, отличаются
состав архива, схемы БД и раздел настроек про модели.

## 1. Что понадобится

### 1.1. Серверы

| Сервер | Назначение | Требования |
|---|---|---|
| Сервер приложений | служба `isc-ai`, распознавание лиц и речи, файлы дел | Linux x86-64 с systemd. Проверено на Debian 12; подойдут Ubuntu 24.04, RHEL 9 и совместимые. Astra Linux и РЕД ОС в списке поддерживаемых у .NET нет, на них нужен пробный прогон. Лица и речь распознаются на процессоре, видеокарта не нужна; мощность — по замеру на пилоте. Под файлы дел — отдельный том под объём архива |
| Сервер БД (можно совместить с сервером приложений) | PostgreSQL | PostgreSQL 16–18, **pgvector 0.8.4 или новее**, `pg_trgm` из contrib, включённый SSL. База отдельная, не та, что у «ИнспектораAI» |
| Узел ИИ | `llama-server`: языковая модель на порту 9000 и модель эмбеддингов на порту 9001 | GPU |
| Носитель для резервных копий | зашифрованные копии базы и файлов | монтируется на сервер приложений в `/mnt/isc-backup`; объём — база плюс все файлы дел |
| Носитель обмена между офисами | зашифрованный пакет за месяц из одного офиса в другой | монтируется на сервер приложений в `/mnt/isc-exchange`: в офисе-источнике — на время формирования пакета (запись), в офисе-получателе — после проверки на шлюзе на время приёма (достаточно чтения); объём — материалы дел за месяц (видео — десятки гигабайт) |
| Том архива (если переносится архив материалов) | пакетный импорт фото, видео и документов | монтируется на сервер приложений только для чтения, например в `/mnt/isc-archive`; не под `/home` |
| Рабочие места пользователей | браузер | свежий Chromium или Firefox, корневой сертификат УЦ контура в доверенных |

### 1.2. Что переносится в контур

| Что | Размер |
|---|---|
| Архив `isc-ai-investigation-<версия>-linux-x64.tar.gz` и файл `.tar.gz.sha256` к нему | около 0,75 ГБ, в распакованном виде около 1,2 ГБ (больше всего места занимает модель речи) |
| Пакеты ОС из раздела 1.4, если в контуре нет зеркала репозитория | десятки МБ, сам PostgreSQL около 50 МБ |
| `llama-server` и файлы моделей GGUF | языковая модель Q4 около 15–17 ГБ, модель эмбеддингов около 320 МБ |

Сертификат HTTPS и ключи резервных копий извне не везём, они создаются внутри контура.

### 1.3. Что подготовить до установки

1. Имя сервера в DNS контура. Система будет открываться только по нему: запросы с другим именем в заголовке Host
   отклоняются.
2. Сертификат HTTPS на это имя от УЦ контура: `server.crt` и `server.key` в формате PEM. Корневой сертификат УЦ
   должен быть в доверенных на рабочих местах.
3. Сетевой доступ:
   - рабочие места → сервер приложений: 443 (порт 80 только перенаправляет на HTTPS);
   - сервер приложений → БД: 5432;
   - сервер приложений → узел ИИ: 9000 и 9001.

   К узлу ИИ, кроме сервера приложений, доступа ни у кого быть не должно.
4. Роль и база в PostgreSQL (раздел 3).
5. Ключи резервных копий. Их создаёт тот, кто будет хранить ключ, на отдельной машине с Linux x86-64, программой
   из архива:

   ```bash
   tools/backup-restore/ISC.AI.Backup.Restore keygen --out <каталог>
   ```

   Программа спросит пароль (не короче 12 символов), создаст `backup-public.pem` и `backup-private.pem` (закрытый —
   с правами 0600, только владельцу) и напечатает отпечаток открытого ключа. Закрытый ключ остаётся у хранителя, на
   сервер его не кладут. На сервер идут только `backup-public.pem` и отпечаток.
6. Точка монтирования носителя для копий: `/mnt/isc-backup`. Если переносится архив материалов — точка монтирования
   тома архива (например, `/mnt/isc-archive`).
7. Если офис участвует в обмене пакетами (Офис №2 отправляет, Офис №1 принимает, ADR-0068), — ключи обмена. Их создают
   хранители ключей той же программой с назначением:

   ```bash
   # в офисе-получателе (Офис №1): ключ, которым шифруются пакеты для него
   tools/backup-restore/ISC.AI.Backup.Restore keygen --out <каталог> --purpose exchange-recipient
   # в офисе-источнике (Офис №2): ключ, которым подписываются его пакеты
   tools/backup-restore/ISC.AI.Backup.Restore keygen --out <каталог> --purpose exchange-signing
   ```

   На сервер офиса-источника идут: `exchange-recipient-public.pem` из офиса-получателя и его отпечаток, свой
   `exchange-signing-private.pem` (он под паролем хранителя; пароль хранитель вводит при каждом пакете) и его отпечаток.
   На сервер офиса-получателя идут: свой `exchange-recipient-private.pem` (под паролем хранителя ключа приёма; пароль
   вводится при приёме каждого пакета) и его отпечаток, `exchange-signing-public.pem` офиса-источника и его отпечаток —
   им проверяется подпись пакетов. Отпечатки офисы сверяют отдельно от ключей (звонком, письмом), не по носителю обмена.
   Точка монтирования носителя обмена: `/mnt/isc-exchange`.
8. Синхронизация времени (NTP) на всех серверах. От неё зависит время записей в журнале аудита.

## 2. Проверка архива после переноса

```bash
sha256sum -c isc-ai-investigation-<версия>-linux-x64.tar.gz.sha256
tar -xzf isc-ai-investigation-<версия>-linux-x64.tar.gz
cd isc-ai-investigation-<версия>-linux-x64
bash verify.sh --log /var/log/isc-ai-transfer.log
```

`verify.sh` сверяет каждый файл со списком `SHA256SUMS`. Изменённый, отсутствующий или лишний файл означает отказ, и
такой пакет не ставим. С ключом `--log` результат (кто, когда, какая версия, итог) дописывается в журнал переноса.

Что лежит в архиве:

| Путь | Что это |
|---|---|
| `app/` | приложение (`ISC.AI.Web` вместе со средой .NET и нативными библиотеками для Linux) |
| `speech-worker/` | распознаватель речи (`ISC.AI.Speech.Worker` со своей средой .NET); тексты лицензий рядом |
| `models/vision/` | модели распознавания лиц YuNet и SFace |
| `models/speech/` | модели распознавания речи (GigaAM, Silero VAD, разделение говорящих) и их лицензии |
| `ffmpeg/` | ffmpeg и ffprobe (LGPL-сборка), библиотеки к ним, `LICENSE.txt` |
| `tools/backup-restore/` | программа для ключей, проверки и восстановления резервных копий |
| `sql/10-core.sql`, `20-docflow.sql`, `30-media.sql`, `40-investigation.sql`, `sql/ORDER` | миграции схем и порядок их применения; повторное применение ничего не ломает |
| `tessdata/` | `rus.traineddata`, `kir.traineddata` |
| `config/appsettings.Production.json`, `config/isc-ai.env` | шаблоны настроек и секретов |
| `systemd/isc-ai.service` | описание службы |
| `verify.sh`, `install.sh`, `migrate.sh`, `account.sh` | проверка, установка, миграции, создание учётной записи |
| `VERSION`, `SHA256SUMS` | версия и контрольные суммы |
| `docs/INSTALL.ru.md` | эта инструкция |

## 3. База данных

1. Поставить PostgreSQL и pgvector (раздел 1.4). Нужен pgvector **0.8.4 или новее**: `migrate.sh` покажет версию и
   предупредит, если она старее. Если расширение в базе уже было создано старой версией, после обновления пакета
   выполнить под `postgres`: `ALTER EXTENSION vector UPDATE;`.
2. В `postgresql.conf`: `ssl = on` с сертификатом сервера БД от УЦ контура; в `listen_addresses` — адрес, на котором
   его видит сервер приложений. Перед пакетным импортом большого архива поднять `maintenance_work_mem`: иначе
   векторный индекс лиц будет строиться очень долго, а в журнале PostgreSQL появится
   `hnsw graph no longer fits in maintenance_work_mem`.
3. В `pg_hba.conf`: только `hostssl` с адреса сервера приложений, метод `scram-sha-256`.
4. Под пользователем `postgres` создать роль и базу:

   ```sql
   CREATE ROLE isc_ai_inv LOGIN PASSWORD '<пароль>';
   CREATE DATABASE isc_ai_inv OWNER isc_ai_inv ENCODING 'UTF8' TEMPLATE template0;
   \c isc_ai_inv
   CREATE EXTENSION IF NOT EXISTS vector;
   CREATE EXTENSION IF NOT EXISTS pg_trgm;
   ```

Приложение работает под владельцем базы, а не под суперпользователем. Программа восстановления из копии создаёт и
переименовывает базы, поэтому её запускают под `postgres`.

## 4. Сервер приложений

### 4.1. Установка

```bash
sudo bash install.sh
```

Скрипт можно запускать повторно. Что он делает:

- проверяет архив (тот же `verify.sh`);
- создаёт системного пользователя `iscai`;
- раскладывает приложение и распознаватель речи в `/opt/isc-ai/releases/<версия>` и делает ссылку `/opt/isc-ai/current`;
- кладёт модели в `/opt/isc-ai/models`, ffmpeg — в `/opt/isc-ai/ffmpeg` и проверяет запуском, что ffmpeg работает и
  собран как LGPL;
- создаёт каталоги данных `/var/lib/isc-ai/{storage,docflow-files,keys,tmp}` с правами 0700 (в `tmp` — временные копии
  видео и звука при обработке);
- кладёт языковые файлы в `/opt/isc-ai/tessdata` и связывает приложение с системными библиотеками Tesseract;
- при первой установке кладёт шаблоны настроек в `/etc/isc-ai`; при повторной существующие файлы не трогает;
- ставит службу `isc-ai` в автозапуск;
- проверяет, что есть ICU, OpenSSL, fontconfig, шрифты и `pg_dump`.

Всё, что требует внимания, выводится строками `ВНИМАНИЕ`. Службу скрипт не запускает.

### 4.2. Настройки

| Файл | Что заполнить |
|---|---|
| `/etc/isc-ai/appsettings.Production.json` | `AllowedHosts` (имя сервера), строки подключения `Core`, `DocFlow`, `Media`, `Investigation` (все четыре в одну базу), адреса узла ИИ, отпечаток ключа копий в `Backup:PublicKey:Sha256`. Если переносится архив материалов — каталог тома архива в `Media:Import:Roots`. Пути к моделям, ffmpeg, распознавателю и каталогам уже заполнены под раскладку `install.sh` |
| `/etc/isc-ai/isc-ai.env` (root:root, 0600) | `Database__Password`; ключи API модели, если `llama-server` запущен с ключом. `Auth__DefaultAccount__Password` оставить пустым |
| `/etc/isc-ai/tls/server.crt`, `server.key` (root:iscai, 0640) | сертификат HTTPS (п. 1.3) |
| `/etc/isc-ai/backup-public.pem` | открытый ключ резервных копий (п. 1.3) |
| секция `Exchange` в `appsettings.Production.json` | только в офисах, участвующих в обмене: `InstanceId` (номер этого экземпляра: `office-1`, `office-2`). Офис-источник заполняет отпечатки ключа получателя и своего ключа подписи; офис-получатель — часть `Import`: отпечаток своего ключа приёма и, под номером источника, отпечаток его ключа подписи. Ненужную часть удалить; офис, не участвующий в обмене, удаляет секцию целиком |
| `/etc/isc-ai/exchange-recipient-public.pem`, `/etc/isc-ai/exchange-signing-private.pem` (root:iscai, 0640) | в офисе-источнике — ключи обмена (п. 1.3): открытый ключ офиса-получателя и свой ключ подписи под паролем |
| `/etc/isc-ai/exchange-recipient-private.pem`, `/etc/isc-ai/exchange-source-signing-public.pem` (root:iscai, 0640) | в офисе-получателе — свой ключ приёма под паролем и открытый ключ подписи офиса-источника |

Пароли в JSON не пишем: пароль БД приложение берёт из переменной `Database__Password`. Хеши моделей в настройках
менять не нужно: приложение проверяет ими файлы моделей и с другим файлом не запустит распознавание.

### 4.3. Миграции

```bash
bash migrate.sh --host <сервер БД> --db isc_ai_inv --user isc_ai_inv --yes
```

Скрипт проверяет, что pgvector и нужные расширения есть, показывает версию pgvector, применяет схемы по порядку
(`core`, `docflow`, `media`, `investigation`) и сверяет число применённых миграций с пакетом. Пароль берётся из
`PGPASSWORD`, иначе скрипт его спросит. Ключ `--yes` нужен только при первой установке на пустую базу. При обновлении
скрипт сначала спросит, сделана ли резервная копия.

### 4.4. Запуск

```bash
sudo systemctl start isc-ai
journalctl -u isc-ai -n 50 --no-pager      # ищем строку «Хост ISC.AI запущен с профилем investigation (СледствиеAI)»
curl -sk https://localhost/health          # должно вернуть ok
```

Если приложение не стартует, в журнале будет строка с `FTL`, а systemd будет перезапускать службу каждые 10 секунд.
Обычные причины: не заполнен шаблон настроек, нет сертификата, неверный пароль БД, на сервере БД выключен SSL.

При первом запуске в журнале будет предупреждение `No XML encryptor configured … unencrypted form`. Это нормально.
Ключи сессий лежат в `/var/lib/isc-ai/keys`, и защищают их права на каталог: 0700, доступ только у `iscai`.
Второе предупреждение при каждом запуске — `The 'SessionOrigin' property 'Origin' on entity type 'SearchSession' …
sentinel value`: это замечание библиотеки работы с БД к описанию одной таблицы, на работу оно не влияет.

### 4.5. Первая учётная запись

```bash
sudo bash account.sh admin "Фамилия И. О."
```

Команда один раз печатает временный пароль, в базе хранится только его хеш. Дальше войти под этой учётной записью,
сменить пароль, в разделе «Пользователи» назначить себе роль Администратора и в блоке «Допуск» выдать гриф и
подразделения. После 5 неудачных входов подряд учётная запись блокируется; снять блокировку может другой
администратор (кнопка «Снять блокировку» в карточке сотрудника) — поэтому лучше сразу завести двух администраторов.

### 4.6. Проверка после установки

1. С рабочего места открыть систему по имени сервера: страница открывается по HTTPS, браузер не ругается на
   сертификат.
2. Завести тестовое дело, загрузить фото с лицом: через несколько секунд у фото статус «проиндексирован», на нём
   отмечены лица.
3. Загрузить короткое видео с людьми: появляется лента кадров под проигрывателем, найдены лица, идёт расшифровка речи.
4. Поиск по лицу: найти человека с загруженного фото по другому его фото.
5. Печать фото в PDF: кириллица в подписях читается.
6. Чат по материалам дела: модель отвечает.
7. «Резервные копии»: «Сделать копию», затем «Проверить последнюю копию».

Если фото остаются в статусе «ошибка» с сообщением про библиотеку или модель, смотрите `journalctl -u isc-ai`: обычно
не поставлен `fontconfig` (раздел 1.4) или изменён путь к модели в настройках. Сообщение про телеметрию ONNX Runtime
значит, что у службы убрали переменную `ORT_DISABLE_TELEMETRY=1` (раздел 6, последний абзац).

## 5. Узел ИИ

Узел ИИ поднимается отдельно. Со стороны приложения нужно следующее:

- адреса `http://<узел ИИ>:9000/v1` (языковая модель) и `http://<узел ИИ>:9001/v1` (эмбеддинги) прописаны в
  `Llm:Models:*:Endpoint`;
- `llama-server` слушает только внутренний адрес, межсетевой экран пускает к нему только сервер приложений.
  Желательно запускать его с `--api-key`, тогда ключ указывается в `isc-ai.env` (`Llm__Models__<роль>__ApiKey`);
- тексты запросов и ответов не пишутся в журналы `llama-server` и ОС, своп на узле выключен или зашифрован.

Распознавание лиц и речи от узла ИИ не зависит: без него не работают только чат и справки.

## 6. Обновление и откат

Обновление:

1. Сделать резервную копию: «Резервные копии» → «Сделать копию» → «Проверить».
2. Перенести новый архив и прогнать `verify.sh` (раздел 2).
3. Поставить новую версию и применить миграции:

   ```bash
   sudo bash install.sh             # раскладывает новую версию и переключает ссылку, работающую службу не трогает
   sudo systemctl stop isc-ai
   bash migrate.sh --host … --db … --user …
   sudo systemctl start isc-ai
   ```

   До применения миграций новую версию не запускать: на старой схеме БД она упадёт.
4. Сравнить `/etc/isc-ai/appsettings.Production.json` с шаблоном из `config/` нового архива. Настройки при обновлении
   не перезаписываются, а в новой версии могут появиться новые параметры.

Модели и ffmpeg общие для всех версий и при обновлении заменяются целиком. Распознаватель речи лежит внутри каталога
версии и откатывается вместе с приложением.

Откат. Прежние версии остаются в `/opt/isc-ai/releases/`. Если миграции не применялись, достаточно вернуть ссылку:

```bash
sudo ln -sfn /opt/isc-ai/releases/<прежняя версия> /opt/isc-ai/current
sudo systemctl restart isc-ai
```

Если миграции уже применены, откатить их скриптами нельзя: базу восстанавливают из резервной копии. Это делается
программой `tools/backup-restore` при остановленной службе, вдвоём: администратор и хранитель закрытого ключа.

Если нужно поменять что-то в службе (другой каталог для копий, зависимость от локального PostgreSQL), делайте это
через `systemctl edit isc-ai`. Сам файл службы `install.sh` при каждом запуске перезаписывает. Переменную
`ORT_DISABLE_TELEMETRY=1` в службе не трогайте: она выключает телеметрию библиотеки распознавания лиц (ONNX Runtime),
которая иначе пытается связаться с сервером Microsoft. Без неё программа распознавание лиц не запускает.

## 8. Что нужно решить до запуска в работу

1. Дистрибутив и версия ОС в контуре. От этого зависит список пакетов из раздела 1.4. Нужен Tesseract 5, иначе
   сканы не распознаются. Если это Astra Linux или РЕД ОС, сначала прогнать на стенде.
2. Мощность сервера приложений. Лица и речь распознаются на процессоре: при пакетном импорте большого архива скорость
   обработки зависит от числа ядер. Замерить на пилоте на реальных видео.
3. Отдельная роль БД с урезанными правами и разграничение доступа к строкам. Сейчас приложение работает под
   владельцем базы.
4. Журнал аудита сейчас хранится только в самой БД. Нужна его копия или подпись вне БД, чтобы администратор
   базы не мог незаметно его поправить.
5. HTTPS и шифрование резервных копий сделаны штатными средствами ОС и .NET, это не сертифицированные СКЗИ.
   Допустимо ли это для нашей системы, должны решить безопасники.
6. ffmpeg распространяется по лицензии LGPL: вместе с системой передаётся текст лицензии (`ffmpeg/LICENSE.txt`) и
   предложение исходных текстов этой сборки (тег и коммит — в `deploy/offline/export-ffmpeg.ps1`).
7. Перенос старой базы Access на сервере Linux не работает: драйвер Microsoft Access есть только под Windows, и
   программа об этом прямо говорит. Если перенос нужен, решить, где его выполнять (например, временный сервер
   Windows с той же базой данных).

## Приложение. Как собирается архив

Архив собирается вне контура, на машине разработки (Windows, интернет, .NET SDK 10, `dotnet-ef`, Git for Windows), из
закоммиченного состояния репозитория. Сначала выгружаются составные части — каждая со своей проверкой лицензии и
контрольными суммами (повторять, только если их нет или они обновляются):

```powershell
.\deploy\offline\export-tessdata.ps1
.\deploy\offline\export-vision-models.ps1
.\deploy\offline\export-speech-models.ps1 -Speakers
.\deploy\offline\export-ffmpeg.ps1 -Platform linux-x64
.\deploy\offline\export-sherpa-no-tts.ps1
.\deploy\offline\publish-speech-worker.ps1 -Runtime linux-x64 -SelfContained
```

Затем сам архив:

```powershell
.\deploy\linux\build-investigation-package.ps1
```

Скрипт публикует приложение под `linux-x64` вместе со средой .NET и проверяет, что в сборку попал только профиль
«Следствие» и нативные библиотеки для Linux (обработка изображений и распознавание лиц). Затем публикует программу
восстановления копий, выгружает SQL-миграции четырёх схем, кладёт распознаватель речи, модели, ffmpeg и языковые
файлы Tesseract, сверяя каждую часть с её контрольными суммами. После этого добавляет скрипты, службу, шаблоны и эту
инструкцию, пишет `VERSION` и `SHA256SUMS` и упаковывает всё в `.tar.gz` с файлом контрольной суммы. Ключ
`-SpeechModel 220m` кладёт облегчённую модель речи (вдвое быстрее, чуть хуже качество) — для слабого сервера.

Результат появляется в `artifacts/deploy/`. Версия по умолчанию: `<дата>-<коммит>`. Если в репозитории были
незакоммиченные правки, к версии добавляется `-dirty`; такой архив в контур не отправляем.
