# Спайк: чат-тест локального ИИ (vLLM)

Маленький консольный тест связи с локальным ИИ (vLLM, OpenAI-совместимый API) через наш стек `Microsoft.Extensions.AI` (`IChatClient`). Цель — убедиться, что мы достукиваемся до модели нашим стеком (де-риск задачи [Э3-04](../../docs/tasks/Э3-04-модели-vllm.md)). Это спайк в ветке `spike/llm-chat`, **не часть основного решения** `ISC.AI.slnx`.

## Запуск

```text
dotnet run --project spikes/LlmChat
```

По умолчанию: эндпоинт `http://127.0.0.1:9000/v1`, модель — **определяется автоматически** из `/v1/models` (как curl без поля `"model"`), вопрос «Кыргыз тилинде өзүң жөнүндө кыскача жаз.».

Со своими параметрами (порядок: эндпоинт, модель, вопрос). Пустая строка вместо модели = автоопределение:

```text
dotnet run --project spikes/LlmChat -- http://127.0.0.1:9000/v1 "" "Ваш вопрос"
```

Или через переменные окружения: `LLM_ENDPOINT`, `LLM_MODEL`, `LLM_API_KEY`.

## Что делает
1. Если модель не задана — запрашивает `/v1/models` и берёт первую (как curl без поля `"model"`).
2. Создаёт `IChatClient` поверх OpenAI-совместимого клиента, нацеленного на vLLM.
3. Отправляет вопрос и **стримит** ответ модели в консоль.

## Если не подключается
- Убедитесь, что vLLM запущен и слушает указанный адрес.
- Эндпоинт — базовый, с `/v1` (клиент сам добавит `/chat/completions`).
- Если vLLM в WSL/Docker — нужен проброс порта в localhost Windows (или укажите реальный адрес/IP машины с моделью).

> Примечание: эндпоинт, модель и ключ вынесены в параметры намеренно — в боевой системе связка «роль модели → клиент» задаётся конфигурацией через keyed-регистрацию (ТО-прог-03), а не хардкодом.
