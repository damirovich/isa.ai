# Оценка качества расшифровки речи (пилот, КИ-10)

Инструмент для пилота из [ADR-0026](../../../docs/06_ADR/ADR-0026-raspoznavanie-rechi.md). Порядок пилота, состав
набора и правила эталона описаны в методике
[Пилот_расшифровки_речи.md](../../../docs/следствие/Пилот_расшифровки_речи.md). Этот файл описывает сам инструмент.
Коды, формат набора и правила подсчёта здесь и в методике одни и те же. Если меняете одно, меняйте и другое.

Инструмент получает гипотезу (текст модели) для каждой записи эталонного набора и считает WER и CER отдельно
для русской, киргизской и смешанной речи и по условиям записи. Кроме того, он измеряет время распознавания и
коэффициент реального времени (RTF), а по контрольным файлам без речи считает ложные слова и фрагменты.
Гипотезу можно получить двумя способами:

- **через распознаватель системы** — порт `IAudioTranscriber`, рабочая реализация `ISC.AI.Speech` с GigaAM
  220M или 600M (`SpeechEvalPilot.RunAndExportAsync`);
- **из готового выхода сторонней модели** — Vosk и Whisper прогоняются на стенде своими утилитами, их тексты
  кладутся в `hyp/<модель>/` (`SpeechEvalPilot.RunPrecomputedAndExportAsync`). Нормализация, учёт
  `[неразборчиво]` и сводки у обоих способов общие, поэтому числа сравнимы.

## Режим — прочитать до начала

- Набор пилота состоит из **реальных записей заказчика и их расшифровок**, то есть из материалов дел. Набор,
  папка `hyp` и папка отчёта хранятся **только в контуре**. В репозиторий и в тесты они не попадают (как и фото
  людей, ТО-прог-13). После пилота их уничтожают.
- В отчёт попадают дословные расшифровки, имена файлов, примечания и примеры слов из эталонов. Отчёт так же
  чувствителен, как сам набор. В протокол пилота переносятся только числа (методика, раздел 2).
- Сам инструмент временных файлов не создаёт. Распознаватель `ISC.AI.Speech` пишет временный WAV в
  `%TEMP%\iscai-speech\<guid>\` и удаляет его при любом исходе; каталоги прогонов, погибших при аварийном
  останове, он убирает перед следующей расшифровкой (хост — ещё и при старте). `TEMP` учётной записи прогона
  должен указывать на защищённый том.
- Тесты в `Speech/Tests` работают только на синтетических данных: на искусственной тишине в WAV и выдуманных
  фразах.

## Эталонный набор

```
pilot-set/
  manifest.csv
  rec-001.ogg          ← запись (любой формат, который берёт ffmpeg: ogg/opus, mp3, m4a, amr, wav, видео…)
  rec-001.txt          ← эталон: то же имя, расширение .txt, рядом с записью
  interviews/
    rec-002.m4a
    rec-002.txt
  ctrl-01.wav          ← контрольный файл без речи: эталон пустой или его нет
  hyp/                 ← только для готового выхода сторонних моделей (см. ниже)
    vosk-ky/
      rec-001.txt
      interviews/rec-002.txt
```

`manifest.csv` — UTF-8, разделитель `;`. Excel сохраняет такой файл через «CSV UTF-8». Строка заголовка и
строки, начинающиеся с `#`, пропускаются. Поле в двойных кавычках может содержать `;`, всё после третьего
поля считается примечанием.

```
файл;язык;условия;примечание
rec-001.ogg;ky;voice;голосовое, шум улицы
interviews/rec-002.m4a;mixed;interview;два собеседника, 1 ч 40 мин
ctrl-01.wav;-;dictaphone;тишина кабинета
```

| Поле | Значения |
|---|---|
| язык | `ru` — русский, `ky` — киргизский (код языка, **не** `kg`), `mixed` — вперемешку; `-` — контрольный файл без речи |
| условия | `phone` — запись телефонного разговора, `voice` — голосовое сообщение мессенджера, `interview` — допрос, беседа в кабинете, `dictaphone` — диктофон или телефон на столе, `street` — улица, транспорт, шум, `far` — дальний микрофон, `overlap` — наложение голосов, `other` — прочее (пояснить в примечании) |

Указывается одно основное условие, остальное пишется в примечание. Регистр кодов не важен. Других значений
нет: на частые ошибки (`kg`, `mix`, `recorder`) инструмент подсказывает правильный код, но молча их не принимает.

При загрузке набор проверяется целиком. Если что-то не так, инструмент выдаёт **все** проблемы разом с
номерами строк: нет записи или эталона, неизвестный код, повтор файла, путь выходит за папку или ведёт в
`hyp`, файл не в UTF-8, пустой эталон у речевой записи, непустой эталон у записи с языком `-`. Последние два
случая считаются ошибками, чтобы незаполненный эталон не превратился молча в «контрольный файл». Замечания к
эталонам прогон не останавливают, но выводятся в отчёт.

## Как писать эталон

Правила — в методике, раздел 4 (дословно, числа словами, ң/ө/ү кириллицей, каждое слово смешанной речи на
своём языке). Для инструмента важно следующее:

- **Неразборчивое** отмечается пометкой `[неразборчиво]`: одна пометка на один непрерывный участок, сколько бы
  слов в нём ни было. Инструмент распознаёт её без учёта регистра и пробелов в скобках.
- Других пометок (`[шум]`, `[смех]`) нет. Инструмент предупреждает о любых квадратных скобках, кроме
  `[неразборчиво]`, в том числе об опечатках вроде `[неразборчево]`.
- Инструмент также предупреждает о цифрах в эталоне, о латинских ö/ü/ñ вместо ө/ү/ң, о смеси латиницы и
  кириллицы в одном слове и об эталоне, в котором нет ничего, кроме пометок.
- Эталон в Windows-1251 отклоняется, а не читается кракозябрами. Файл нужно сохранять в **UTF-8**.

## Что считается

- **Нормализация.** Её применяют одинаково к эталону и к выходу модели. Текст приводится к NFC и к нижнему
  регистру, ё заменяется на е. Знаки препинания, символы и дефис становятся границами слов, пробелы
  схлопываются. Знаки ударения и невидимые символы удаляются. Буквы ң/ө/ү, цифры и латиница не заменяются.
  См. `SpeechTextNormalizer`.
- **WER** = (S + D + I) / N по словам, **CER** — то же по символам вместе с пробелами между словами.
  S — замены, D — слова, пропущенные моделью, I — лишние слова модели, N — длина эталона. Обе метрики
  могут быть больше 100 %. Число ошибок — расстояние Левенштейна; разбиение на S, D и I берётся из одного
  из оптимальных выравниваний.
- **`[неразборчиво]`** — «джокер» в выравнивании (`ErrorRateCalculator.Wildcard`). Участок совмещается с
  любым, в том числе нулевым, числом слов модели без штрафа. Эти слова не считаются ни ошибками, ни
  совпадениями, в отчёте они показаны в столбце «Не оцен.» (`word_unscored`). Сама пометка не входит в N. Для
  CER то же по символам, и пробелы по краям участка тоже не оцениваются. Но участок поглощает только целые
  слова модели — от пробела или края текста до пробела или края. Буквы, приклеенные без пробела к соседнему
  слову, остаются ошибками: эталон «үй [неразборчиво]» против «үйгө бар» — две вставки («гө»), а не CER 0.
- **Записи «только скорость».** Если эталон речевой записи состоит из одних пометок (по методике, 7.2, так
  вносят длинные записи целиком), WER не определён и запись в сводки качества не входит: ни в «Записей», ни в
  «Нрзб.» и «Не оцен.», ни в список записей с большой долей неразборчивого. Её звук, время и RTF показаны
  отдельно — раздел «Только скорость» в `report.md` и строка `speed_only` в `summary.csv`.
- **Много неразборчивого.** Записи, где пометок больше одной на 20 слов эталона (методика, 4.6), перечислены
  в разделе `report.md` «Записи с большой долей неразборчивого»: их WER посчитан только по разобранной речи.
- **Сводки** считаются по корпусу группы: Σ ошибок / Σ длины эталона. Для WER это среднее по записям,
  взвешенное по числу слов эталона, для CER — по числу символов. Короткое голосовое сообщение весит меньше
  часового допроса. Сводки строятся по языку (всегда все три языка, пустой тоже виден), по условиям и по
  сочетанию «язык × условия». **Общего WER по всем языкам нет намеренно** (КИ-03): хороший русский не должен
  скрывать провал киргизского.
- **Контрольные файлы без речи** (язык `-`) в WER и в сводки по языку и условиям не входят. По ним
  считаются **ложные слова** (все слова модели) и **ложные фрагменты** (фрагменты, в которых после
  нормализации есть хоть одно слово). Оба числа даются в сумме и на 10 минут звука. «На 10 минут»
  считается только по файлам, длительность которых измерена по самому файлу.
- **RTF** = время распознавания / длительность звука. Время считается от вызова распознавателя до
  последнего фрагмента, включая запуск процесса, ffmpeg и загрузку модели. Поэтому на коротких записях RTF
  завышен, и честнее смотреть RTF длинных записей (раздел «Только скорость»). Длительность WAV берётся из
  заголовка, других форматов — из `ffprobe` офлайн-поставки (`duration_source` = `measured`). Если ffprobe
  недоступен, берётся длительность записи, которую сообщил распознаватель (`transcriber`, тоже точная), а если
  нет и её — конец последнего фрагмента (`last_segment_end`): такая длительность занижена, и RTF помечается
  «≈». Записи обрабатываются строго по одной. У готового выхода сторонних моделей время и RTF не измеряются.

## Готовый выход сторонних моделей (`hyp/<модель>/`)

- Для записи `interviews/rec-002.m4a` инструмент ищет `hyp/<модель>/interviews/rec-002.txt`, а если его нет —
  `hyp/<модель>/interviews/rec-002.m4a.txt`. Второе имя — то, которое по умолчанию даёт whisper.cpp. Если есть
  оба файла, это ошибка.
- Файл содержит только текст в UTF-8, без таймкодов. Каждая непустая строка считается одним фрагментом:
  whisper.cpp с `-otxt` и Vosk пишут по фрагменту в строке. По этим строкам считаются ложные фрагменты
  на контрольных файлах.
- Записи без файла не оцениваются и перечисляются в замечаниях отчёта. Например, Whisper прогоняется только
  на `ru` и на контрольных файлах. Файлы без записи в манифесте тоже попадают в замечания, по ним видны
  ошибки в именах.
- Имя модели — это имя подпапки (например, `vosk-ky-0.42`, `whisper-large-v3-turbo`). Оно попадает в
  колонку `model` вместо версии модели.
- Числа Whisper пишет цифрами. Инструмент числа не нормализует, поэтому их переводят в слова вручную до
  подсчёта (методика, 4.4).

## Запуск

Программы запуска в репозитории нет. Проект оценок ссылается только на порт (`ISC.AI.Modules.Media.Domain`), а
не на `ISC.AI.Speech`, поэтому вызов делает небольшая программа на стенде пилота, которая ссылается на оба
проекта. Сигнатуры:

```csharp
// GigaAM через распознаватель системы: гипотезы, время и RTF.
Task<SpeechEvalReport> SpeechEvalPilot.RunAndExportAsync(
    IAudioTranscriber transcriber,
    string datasetFolder,
    string outputFolder,                          // вне папки набора; для каждой модели и настройки — своя
    string? ffprobeFolder = null,                 // каталог ffprobe; null — PATH
    IProgress<SpeechEvalProgress>? progress = null,
    CancellationToken cancellationToken = default);

// Vosk, Whisper: готовый выход из <набор>\hyp\<model>\.
Task<SpeechEvalReport> SpeechEvalPilot.RunPrecomputedAndExportAsync(
    string datasetFolder,
    string model,                                 // имя подпапки в hyp
    string outputFolder,
    string? ffprobeFolder = null,
    IProgress<SpeechEvalProgress>? progress = null,
    CancellationToken cancellationToken = default);
```

Пример для GigaAM. Настройки те же, что у хоста, — секция `Speech`, пути и пины SHA-256 из офлайн-поставки:

```csharp
SpeechOptions options = SpeechServiceCollectionExtensions.ReadOptions(configuration);
using var transcriber = new SpeechWorkerTranscriber(options with { Threads = 4, MaxSegmentSeconds = 20 });
var report = await SpeechEvalPilot.RunAndExportAsync(
    transcriber,
    datasetFolder: @"D:\pilot\set",
    outputFolder: @"D:\pilot\out\gigaam-220m-t4",
    ffprobeFolder: options.FfmpegFolder,          // тот же каталог, что Speech:Ffmpeg:Folder
    progress: new Progress<SpeechEvalProgress>(p => Console.WriteLine($"{p.Completed}/{p.Total} {p.Last.Recording.File}")));
```

Части можно вызывать и по отдельности: `SpeechEvalDataset.LoadAsync`, `SpeechEvalExternalHypotheses.LoadAsync`,
`SpeechEvalRunner.RunAsync`, `SpeechEvalReportExporter.ExportAsync`. Для одной пары текстов есть
`ErrorRateCalculator.WordErrors` и `ErrorRateCalculator.CharacterErrors`.

## Результат (папка отчёта)

| Файл | Что внутри |
|---|---|
| `report.md` | модель и источник гипотез, машина, методика подсчёта; сводки по языку, условиям и их сочетанию (со столбцами «Нрзб.» — число пометок и «Не оцен.»); худшие записи; все оцениваемые речевые записи; записи с большой долей неразборчивого; записи «только скорость» (звук, время, RTF); контрольные файлы без речи; сбои; замечания к набору |
| `records.csv` | строка на запись: язык, условия, WER/CER долями, S/D/I, длительность, время, RTF, ошибка; в конце `unintelligible` (пометок), `word_unscored`, `char_unscored`, `text_segments` (фрагментов с текстом; у контрольного файла это ложные фрагменты, а `hyp_words` — ложные слова), `hypothesis_source` (`transcriber` или `precomputed`) |
| `summary.csv` | сводки: `group_by` = `language` / `condition` / `language_condition` (в конце — `unintelligible`, пометок в группе), строка `speed_only` (записи «только скорость»: звук, время, RTF) и строка `no_speech` с `false_words` и `false_fragments` |
| `transcripts/<имя>.hyp.txt` | дословная расшифровка модели: с таймкодами, а у готового выхода — по строкам без таймкодов |
| `transcripts/<имя>.ref.words.txt`, `<имя>.hyp.words.txt` | нормализованные эталон (пометки `[неразборчиво]` отдельной строкой) и гипотеза, по слову в строке |

Файлы «по слову в строке» можно сравнить любой программой сравнения, например WinMerge или
`git diff --no-index a.ref.words.txt a.hyp.words.txt`. Она покажет, какие именно слова модель заменила,
пропустила или добавила: имена, числа, киргизские слова.

CSV пишутся с BOM и разделителем `;`, числа — с точкой. Для русского Excel при вызове
`SpeechEvalReportExporter.ExportAsync` можно передать `csvNumberFormat: CultureInfo.GetCultureInfo("ru-RU")`. В
каждой строке CSV есть колонка `model`, поэтому CSV прогонов разных моделей склеиваются в одну таблицу.

## Чего инструмент не измеряет

- Память процесса-распознавателя: это отдельный процесс, её смотрят системными средствами во время
  прогона (методика, 6.4).
- Точность таймкодов на стыках фрагментов: она проверяется выборочным прослушиванием по `*.hyp.txt` или в
  самой системе (методика, 6.5).
- Сводки по группам порогов КИ-10 (А — `interview` + `dictaphone`, Б — `phone` + `voice`). Их складывают из
  строк `language_condition` файла `summary.csv`: Σ ошибок / Σ `ref_words` (методика, 10.2).
- Полноту ключевых слов (имена, топонимы, числа), замены ң/ө/ү и места переключения языка (методика, 6.2 и
  6.3). Это ручные проверки по файлам «по слову в строке».
- Качество по говорящим: разделения по голосам пока нет.
- Эквивалентность «25» и «двадцать пять»: числа не нормализуются (методика, 4.4).
